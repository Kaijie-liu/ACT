# Modular candidate supervision V1 — integration contract

Separate namespace `modular_supervised/`; frozen `modular_basis/` arithmetic and
the original standalone LP checker are unchanged. No real diagnostic execution
is authorized by integration controls. No production MoE acceptance changes.

## One budget, one basis

Copy original-coordinate assembly and instrument the frozen modular algorithm;
test exact differential of bundle, original system hash, statistics, operations
and arithmetic metadata. Keep native fidelity V2 options, single native call
<=10s, one basis, all 4096-bit/sparsity/operation caps and 128-prime schedule.
No alternative basis, retry, cap increase or fallback arithmetic.

The original monotonic request start determines every deadline: load, capture,
mapping and construction <=218s; package/check/in-request audit <=298s; terminal
publication <=300s. Owned subprocess groups are killed at their phase cutoff.
Late publication invalidates success. No stage resets the clock.

The scope is a **supplied LP**, not full network inference/propagation. Charge
startup/imports, input decoding, native fidelity checks, basis mapping, modular
construction, journal/result serialization, portable packaging, checking and
in-request review. Historical propagation/F0 costs are excluded explicitly.
Outer publication = disjoint phase windows + residual; constructor and native
subcosts are nested, not added again. Missing/censored values remain null.

## Partial evidence is not proof

The arithmetic journal follows setup/assembly then bounded cycles of prime
schedule, finite-field work, CRT, reconstruction and exact residual, followed
by candidate construction only on completion. Every saved segment is contiguous
in time, and each transition must be registered. Fixed snapshots at phase
changes and every100000 operations, max2048 events, bind original request,
LP, statement, hint, plan, original start and deadline. Increasing this log cap
from the old monotonic journal is not an arithmetic/budget increase: modular
cycles require more phase records. Serialization stays charged.

All snapshots are `PARTIAL_DIAGNOSTIC_NOT_PROOF`, immutable and non-resumable.
They preserve modular counters/round progress and first arithmetic limit; no
snapshot independently proves elimination, a feasible point or a network claim.
Interrupted final writes remain censored; missing middle entries or wrong
bindings reject. A complete journal with an interrupted candidate write does
not yield an accepted result.

`UNRESOLVED_MODULAR_RECONSTRUCTION`, LIMIT and TIMEOUT are unresolved, not
infeasibility. An exact assembled-system candidate may still violate original
LP residual/slack restrictions. Only the separate unchanged original-LP checker
can establish its exact feasibility and objective upper bound; that does not
establish network UNSAFE or a positive safety lower bound.

## Controls and next gate

Test full analytic native pipelines, original deadline exhaustion, every modular
phase stall, malformed/partial writes, checker cutoff, exceptions, journal
cycles/identity/prefix mutations and complete cost reconstruction. Compare
instrumented and uninstrumented arithmetic exactly, including multi-prime work.
Relocate complete bundles and rerun python -I -S checking in a fresh review.
Controls advancing the original start are fault injections, not real timings.

Only after passing control/fresh-review gates: separately freeze the same four
original obligations in a new real-diagnostic namespace and output directory,
with unchanged 218/298/300 clocks and complete terminal roster. Freezing does
not execute; explicit launch remains a later action.
