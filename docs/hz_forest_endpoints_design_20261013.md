## Mechanism and acceptance contract

1. Only a successful independent source check may issue an immutable
   `CheckedForest`. Preserve the complete source inventory, including inactive
   and intermediate roots, and privately bind source/request/forest identities.
   The whole-request consumer refuses prefixes. No eager Store conversion.
2. Pair slices contain row identities, not coefficient copies: common ancestry
   once, the selected pair guard, expert A suffix, expert B suffix. Never
   conjoin guards for different pairs or merge private factor identities.
3. Source-generated output nodes have no coefficient references; only unstable
   ReLU equality nodes reference one earlier output with coefficient −1. Check
   this structure. With local matrix L and references R, C=(I+R)L and R²=0.
   Native forward/transpose use sparse L and reference scatter, not expanded C.
   This restricted operator is not a general DAG shortcut.
4. Candidate generation retains the registered CPU float64 projected
   subgradient rule (128 updates, initial evaluation, .125/sqrt(step+1),
   inequality multipliers ≤0), tiles at most 8 columns for one pair. CPU exact
   acceptance combines all global-factor residuals before absolute values,
   counts every original rhs independently, and checks proposed and zero duals.
   Different floating accumulation order need not produce identical iterates.
5. All unordered tie-legal pairs, all non-label classes, and both distinct gate
   endpoints are obligations. Gate bounds use the shared router difference;
   sign gives [0,1/2], [1/2,1], equality [1/2,1/2], otherwise [0,1]. Complete
   source dimensions/property/margin/ties are binding. Threshold remains 1e-7.
   Missing evidence is UNKNOWN; nonpositive bounds are not UNSAFE.
6. Source construction, source check, planning, candidate generation, exact
   selection, serialization and complete final checking share one at-most-300s
   worker deadline and the existing cumulative 8M work limit. No silent use of
   the older endpoint composition's 96M limit. Parent includes startup and
   receipt publication. Partial/error/deadline artifacts remain; no late success.
