# 小型 HybridZ 支持的实机兼容性协议

本阶段检验原设备可选候选核能否在本机 GPU 上执行、归还资源并完成相同的 CPU
精确检查。沿用四个既有小型 HZ、原稀疏 COO 算法、float64、128 次优化和全部义务。
不扩大批量，不启动真实模型，不把小例冷启动成本当成 GPU 性能胜负。

[设计冻结](../configs/hz_physical_device_design_20261001.json)先定义六次 CPU/模拟
接线控制。通过后须另行提交执行冻结，绑定准确代码、控制结果、四来源、八次顺序
交错调用及每请求 30 秒（统一上限仍为 300 秒）。此设计文件本身不允许启动 CUDA。
八次调用各自创建来源、付费分析，不读取另一臂的候选答案。

## 设备和预算合同

只允许 producer 使用 CUDA；它是新进程组的唯一 CUDA 进程，不启动 CUDA 子进程或
逃逸 session。只有该 producer 可见固定 GPU UUID，其余阶段隐藏 CUDA。
候选核初始化 CUDA 后核对实际 UUID，并使用原 1 GiB PyTorch allocator 限制。
该限制不涵盖所有驱动开销；保存峰值 allocated/reserved，不将它们当作设备全部显存。

准入观察、producer 内初始化前复查及清理后的归还观察都在受有界监督的进程中执行。
`nvidia-smi` 的内部 timeout 不能代替外层进程组硬截止。准入要求两次间隔 0.2 秒的
新鲜观察：无计算 PID、利用率不超过 5%、至少 4 GiB 可用。producer 创建批量对象后、
调用候选核前再次观察；他人出现就返回 RESOURCE_UNAVAILABLE，不初始化 CUDA。
这不是独占预约，无法原子阻止之后有新租户加入；保留这一共享服务器限制。

请求时钟覆盖启动、创建、GPU 初始化、传输、同步优化、读回、独立检查、序列化、
接收、清理和终态。为 post-producer 工作保留最多 7 秒；资源观察与清理各有阶段
截止。失败 producer 同样必须清理并观察归还。归还只要求两次清单无本 PID，不要求
终止其他用户或等待全卡空闲，也不能授予下次准入。

## 接受与停止

候选不是证书。CPU checker 针对绑定的原始 HZ/性质重算有理数残差与合法下界；
每臂独立检查全部目标，保存差值，不要求 CPU/GPU 的优化轨迹逐 bit 相同。
给定 HZ 的下界检查不包含网络来源，也不自动意味着正界或完整 MoE SAFE。

物理批次开始前做一次有界资源 preflight；忙则保存 NOT_ADMITTED，无自动轮询、
无 kernel 请求、无假称正在运行。实际请求的资源拒绝、错误、超时或清理/归还未确认
均停止后续调用，完整保留已运行前缀和未运行列表。故障不通过重跑、换 dtype、
延长预算或改问题掩盖。若只是 preflight 未准入，未来资源改变后需记录新的准入事件，
不能把旧观察当作预约。

六项接线调用之外只做不启动求解的变异/解析控制：GPU 身份、源码、截止、准入
原始数据、checker 输出、缺义务、成本和环境隔离。旧生命周期和数值控制做回归。
新的协调层采用显式 policy 参数，不改旧冻结模块，不猴补其全局绑定。

本阶段通过只关闭“设备算子与完整小流程是否可执行”的问题。G2 的实用加速标准、
容量/真实请求效果，以及其他五项目标仍需各自证据，不能据此宣布已完成。
