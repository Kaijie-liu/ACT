# Guard 域专用视图的静态设计判断

**可消除 pair 视图的冗余值输出接口，但不能仅靠这一改动准入注册八专家请求。**
本设计绑定 `5c40bf80e2089ce6e5c679b0523f75c1b7e6f625`，只分析已有代码、数学关系与
冻结形状。它不是执行协议或已实现的算法，未运行新来源、候选、worker、模型或 GPU。
[静态证据记录](hz_domain_guard_decision_20261015.json)保存代码身份和数量推导。

分页阶段已经结束；本次不再研究分页、复制或结果缓存。目标是判断一个真正改变
MoE 中间表示的方向，是否值得单独授权开发，而不是改变既有统计口径。

## 实际消费者需要什么

当前构造器将每个 pair 的 `output` 设为 common 的输入输出目录，检查器强制其相等。
但 weighted endpoint 路径并不读取这些 pair 值输出：

| 使用位置 | 实际依赖 |
| --- | --- |
| `source_dag.Builder.finish` | 为每个 pair 复制输入输出目录，另生成全部 guard |
| `check_source_dag.Checker.run` | 检查这份别名目录及完整有序 guard |
| `forest_endpoints.CheckedForest.rows` | common、pair 及两专家的 `eq/ine`，不取 pair 输出 |
| `scaled_endpoints._plan` | router 输出，用于 gate 端点；全部 pair／类别仍枚举 |
| `bounded_runtime.shared_objective`、`forest_endpoints.objective_roots` | 两个专家的最终输出 |
| `pair_workspace.Scope` | view ancestry、node／factor owner，不以 pair 输出定义作用域 |

因此，pair 更适合作为**仅定义条件域、不产生值输出的视图**。common 和 Flatten
仍有真正的数据消费者，不在这项设计中删除。只把 pair 输出改成父序列引用不是新
方案：现有 `shared_format` 已 intern 序列，`RootTable` 已共享相同成员存储。

## 保持同一可行域和性质的数学合同

令全局因素向量为 \(\xi\)，其连续／二元范围保持原样。对 unordered pair
\(S=\{a,b\}\)，令 \(D_S\) 是同一已检查 HZ 表示的因素可行域，由 common／router
约束、pair guard、两个专家的路径约束及原节点和因素的关系定义。消费者使用二元
连续松弛时，两侧也采用同一松弛域；这不是原网络精确可达域的等价断言。

旧 pair 视图额外列出 \(p_{\rm input}(\xi)\) 作为值输出；该列表没有添加新的等式
或不等式，也没有被上述目标消费者使用。新视图保留所有节点、因素、parent、owner、
`eq/ine` 及其顺序，只将 pair 的值输出接口设为空。于是，对每一个 \(\xi\)：

\[
\xi\in D_S^{\rm old}\iff\xi\in D_S^{\rm domain},
\qquad
s_{S,k,t}^{\rm old}(\xi)=s_{S,k,t}^{\rm domain}(\xi).
\]

这里 \(s_{S,k,t}\) 是原 gate 端点 \(t\) 下的完整加权分类性质，不是单专家性质。
此变换**不消去共享输入因素、不独立化专家、不删除路由条件**，仅移除未使用的命名
值输出。全部 guard、节点／因素编号、scales、因素范围、目标系数、rhs 和 dual 行序
不变，所以同一组合法 dual
数值及原残差公式给出的精确下界相同。它不会收紧松弛或自动新增证书。

这项等价只针对当前已核对的 endpoint 消费者闭包，不宣称所有外部通用 view API 都
允许空输出。未来版本必须显式区分域视图与值视图，不能偷偷放宽旧检查器。

## 注册形状上的准确影响

八个专家、3,072 维输入，共 28 个 pair；删除的是真实接口成员
\(28\times3072=86,016\)，不是 86,016 条独立约束或源系数。

| 项目 | 当前表示 | 仅域视图设计 |
| --- | ---: | ---: |
| expanded memberships 必需下界 | 126,632 | 40,616 |
| expanded memberships 保守上界 | 136,232 | 50,216 |
| 原 membership 上限 | 65,536 | 65,536，不变 |
| pair guard 行 | 336 | 336 |
| 完整分类义务 | 252 | 252 |
| 端点最大数／两角色候选最大数 | 504／1,008 | 504／1,008 |

新成员数按同一规则统计新 IR **实际存在**的列表项；不是给旧成员免计费。唯一根、
节点、因素、专家系数、dual 维度均不变；输入序列仍被 input／common／Flatten 引用，
所以不能据上述差额声称 forest 字节或峰值内存同比下降。具体存储与时间增量待新版本
实现后测量，当前保持 null。

该变化确实解决成员数这一项结构矛盾，但原 source、candidate、dense arena 和整体
heap／RSS 条件没有因此解决。

## 为什么还不能作为完整准入修复

当前 Snapshot 对每个参数有两次计数访问，另访问每条仿射行；其完整路径本身就是
\(2\times6,961,368+3,288=13,926,024>8,000,000\)。即使融合这些重复装包／重放，
两次完整独立仿射方程检查仍至少需要：

\[
2(W_1+W_2)=2(6,684,672+273,408)=13,916,160>8,000,000.
\]

此外，现有两次完整消费者在最小 252 端点目录、全部候选存在且保持原完整 merge／
两次 norm 下，仅保守输入因素部分就有 9,289,728 的既有 Work 下界。
删除 pair 的未使用值输出不改变这些循环。

这些是**当前表示、检查调度及 logical Work 合同**的下界，不是所有 MoE 验证算法的
信息论下界。`TensorRows._values` 有截止检查而没有 Work 自增；把原循环移入不计数层，
或将每系数操作改名为一次 block 访问，不能作为保留旧计量合同的算法收益。

另一个可能改变方程扫描的方向，是把仿射节点定义成绑定源张量上的精确原语，而非
另生成系数／中心后逐元素核对。但它需要新的来源语义、中心与误差补偿、因素映射、
独立检查命题和完整成本合同。现有 SourceLocal 仅是物理系数别名，不等于这种新证明
系统。该方向尚未闭合；不能把它当作已经可行的 8M 替代路径。

## 若后续批准实施所需的版本边界

新域视图至少必须同时满足：同一 common parent；无值输出和额外等式；本 reference
guard 构造不增加因素；全部 \(2(E-2)\) 条非严格 guard 按原顺序逐条检查；全部 unordered
pair 保留，ties 不排除。域视图不得作为 Linear／ReLU 的值输入。

来源 schema、method、forest、property query、candidate 和 portable 身份必须绑定
新语义。差分只能在身份重新绑定后比较相同 dual **数值**，不能复用旧 receipt 或旧
正界文件。变异边界包括混用旧格式、把值视图伪装成域视图／缺失必需输出、删除 guard、
错 parent、错专家／因素、
ties、部分义务和搬迁后全量重算。这里列的是未来必要条件，未冻结或运行这些控制。

单独实施本视图尚不能满足当前完整容量合同，因此**不把它作为下一轮立即执行的小
优化**。进一步运行时开发前，应在以下两条路线中做明确选择：

1. 新来源算子与支持检查调度的联合研究合同：同时处理来源与消费者下界，而不只
   改一个成员目录。必须先给出来源 soundness、独立重算和完整成本依据。
2. 独立版本化资源合同：保持数学算法不变，明确资源向量、来源捕获、候选策略和拒绝
   语义；不能从宽松上界直接选额度，也不能将资源提升算作算法优势。

两条路线均不自动授权实施、提额、真实模型或 GPU；300 秒及时接受门、全部义务与
数学检查继续保留。内存拒绝机制也不是成功容量：已有分阶段／接收 helper 草案不能
用采样 RSS 冒充硬上限，实际采用仍需另行合同。下一项需要的是这项具体范围决定，
不是重做分页控制、扩大样本或重新试跑已拒绝形状。

本次有限诊断到此完成；G1–G6 保持开放。域视图的静态等价与成员数改善不是已经
贯通 HybridZ 的算法效果，也不改变历史主表的保证等级。

## 后续核查 两遍来源合法性本身仍超原额度

在 `e589debf8e1a548eb9bece602aef2297b32f6c70` 上继续核对算子表示与支持消费者后，
**不启动仅源算子或残差模板的另一轮实现**。注册参数数量为
\(P=6,684,672+273,408+3,288=6,961,368\)，包括所有仿射权重和偏置，
不包含输入中心。只要生产与 fresh portable 各保留每参数至少一次已计费合法性访问，
即使把系数等式比较、中心、范数和全部输出计算都免费处理，也有：

\[
W_{\mathrm{two\ source\ checks}}\ge 2P=13,922,736>8,000,000.
\]

代码依据是 `shared_source.PackedRow.__init__` 对包括零在内的全部权重／偏置执行
有限性检查并逐值计费，以及 `check_shared_source.Checker`、
`direct_lifecycle_package.check_manifest` 在两条路径上分别创建新的来源核验。
这比“必须比较两份展开系数”的限制更前置：将后层仿射改成源定义算子，可以免去另一
份 refs 的生成与比对，却不自动取消来源合法性检查。

此下界**以保留上述逐参数计费和两遍完整核验为前提**，不是任意验证算法的复杂度
下界。`TensorRows._values` 的原始读取／有限性检查仅做 deadline tick；把原已计费
访问移入那里，不能称为旧计量不变的算法加速。只凭哈希接受旧核验收据，也不满足
fresh 独立重算。这里既没有提出新额度，也没有主张必须减少检查。

联合研究的另半边也没有发现可直接宣称的新机制：共享／私有块与多列精确 pullback
已经实现；[72 个残差模板的首轮计算反例](hz_residual_template_capacity_20261013.md)
仍适用。低秩候选需要额外证明和搜索族合同，不能假设任意已提交对偶天然低秩；用标量
三角界替代共同输入上的残差抵消，也不是保持同一候选精确接受的等价变换。

固定 pair 和同一个 dual 时，gate 参数 \(t\) 的下界可写为
\(L(t)=a+bt-\sum_j s_j|r_{0j}+tr_{1j}|\)，其中 \(s_j\ge0\)。它是凹函数，
两端点的最小值可覆盖整个区间；单端点却不能证明另一端点，插值也不等于精确下界。
当前两端点允许独立 dual，因此更不能假设其残差具有已知的低秩关系而省略核验。

因此，先前“两条后续路线”不能理解为只要批准联合算法开发，就能在原 8M 下准入。
如果仍保留两遍完整独立核验和现有计费语义，**注册完整形状需要独立的资源政策决策**；
算法研究可减少真实成本，但不能承诺跨过这个参数合法性下界。新资源合同仍须闭合
来源／候选域、完整成本与内存边界后才确定数值，不能从 `2P` 倍数直接设置额度。
不继续重试当前形状或添加别名／分页微控制；没有真实运行、候选生成或新的证书结果。
