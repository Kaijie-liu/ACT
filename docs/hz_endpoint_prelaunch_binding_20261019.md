需要区分两个对象：纯测量宿主 H 与为当前请求创建的执行进程 R。

而 H 是显式可信的测量根，不再向外递归。当前代码文件和哈希仍不代表已有一个绑定的 H。

| 待选边界 | 原预算内必须计入 | 边界变化及实施代价 |
| --- | --- | --- |
| 冷启动请求宿主 | H 记录 `t0` 后创建 R；R 冷启动、全部导入及现有请求流程均计费 | 需绑定实际 H；若没有现成 H，创建它超出本轮“不新增监督层”的授权 |

也不得提前完成请求身份／代码／来源检查。实际宿主、版本、限额及测量根身份必须绑定，
不能只把一个启动脚本重新命名为已存在服务。

宿主预置成本须单独保留，未测到的部分为未知，不填零；报告同时区分预置成本、原预算内
请求成本和可得的合计。预算内结果只能采用已声明的预置宿主口径，不能冒充从创建 H 开始的
冷启动总成本，也不能与历史不同口径的耗时直接求加速比。两臂采用相同边界，
无跨请求模型／数据缓存或摊销；本提案不自动适用于真实模型、GPU 或外部竞争实验。

无论采用哪种边界，全部数学检查、七位置／22 项目录、300 秒单位置／2100 秒整批、
一次 60 秒准入及现行 Work、制品、AS、RSS 门均保留。检查、候选、回退、序列化、清理、
在线接收和终态仍计费；迟到或缺失证据不能经离线归档补成成功。

未获该决定前不修改运行代码、批准表或冻结配置；不再为此新增监督包装或重复静态控制。

## 最小启动接线已实现

2026-10-19 后续授权仅覆盖最小接线实现与静态核查。起始 HEAD 为
`0da0f2d8d823eb77c4a891b43e2297433ad7a76b`，分支、远端和工作区状态正常。
新增默认关闭的 [launch_from_retained_start](../scripts/endpoint_midpoint_launcher.py)，
不新建 caller 进程、监督层或常驻服务，不修改全局导入器。

它在同一专用宿主中完成以下接线：外部保留的原始时钟记录及预期哈希 →
继承限额／独立批准表／冻结代码核对 → 有界 anchor → 现有 `receive_once()` →
最终接收。每宿主只允许一次尝试，早失败也消耗该次机会；默认关闭调用不启动任何工作。
它不在函数入口生成预算起点，不调用 `setrlimit()`，因此不会用事后降限伪装成创建前限额。

`origin` 为有界标量记录，包含 freeze、issuer、原时钟、boot、namespace 和本宿主 PID incarnation。
复制并校验外部 `origin_sha256` 后才使用其时间。`issuer_identity()` 绑定本接线代码及合同，
不证明宿主真实存在，也不赋予执行权；实际批准仍由独立批次批准表决定。
原始起点必须覆盖本宿主／模块冷启动；新起 Python 再用函数入口时间填入 origin 不合格。

同宿主调用的来源核查拒绝已有项目代码、模型／原生后端、异源 namespace、同目录
扩展／包／无源码模块遮蔽和未绑定的时间戳字节码缓存。宿主须为单线程的 `-I -S -B`
环境并具有已核对的 ROOT 导入路径；接线不自动改路径、不删除缓存。
读取代码后至导入完成之间的仓库不可变性、标准 Python 导入机制和外部宿主仍受信任；
这些检查不是通用 Python 沙箱或机器级启动证明。

调用者正常返回后，接线将同一接收锚的时间延后到本次接收工作完成，超过原 2100 秒只能
撤销正接受。目录创建前的异常返回 `ENDPOINT_LAUNCH_FAILURE_V1`，不能当作成功；
原始时间未通过校验时完整耗时为 `null`，另列已观察前缀，绝不填零。
宿主被外部终止而无法返回时仍是缺失终态，不能凭后来文件补造完成。

没有新增磁盘元数据成员或额度。origin／anchor 分别上限 4096 字节，最终返回仍受原
64 KiB 接收上限约束；代码校验、anchor 构造、导入、早失败和接收均使用原始累计时间。
数值门、每位置 300 秒、整批 2100 秒、七位置／22 项名称及原有候选数学均不变。

本阶段静态检查 PASS：12 入口、4 bootstrap、75 依赖；原生检查仍为 12 入口、60 依赖。
只读复核指出的预加载与导入来源缺口已修复。没有运行控制、来源工厂、候选优化、模型或 GPU；
没有创建 V3 冻结／r2 目录、激活批准表或修改旧冻结。**最小接线实现已完成，真实宿主及早起点
来源仍未绑定。** 后续需要实际执行环境提供该绑定，再另行冻结有限执行；不要再请求同一接线的
实现许可或增加外层包装。若环境无法提供原始起点，就保持不可执行，不自设一个更晚的边界。

## 已完成的接口修正

启动方必须在本批请求准备及创建调用者进程之前记录 `CLOCK_MONOTONIC` 起点，
保留原始记录与其预期哈希，并在创建进程前施加原有 AS／FSIZE 硬限额。
调用者的 `execute()` 不再自行产生预算起点，也不在导入完成后补设限额。
当前限额不匹配时拒绝，不提升、修复或重试。

启动记录绑定冻结身份、真实启动方身份、请求目录、代码根目录、nonce、boot ID、
时钟命名空间及启动方 PID incarnation。它在校验和哈希之前脱离调用方可变字典，
随后只使用这份标量快照。PID／namespace 检查仅排除部分身份错配，
**记录的哈希不证明启动方可信，也不证明起点确实早于全部准备工作**。
这些事实仍由待绑定的真实启动方负责。

同一 `start_sha256` 贯通准入记录、worker 汇总、终态、返回 proposal、外部接收锚及审计。
`observer_entry` 只是观察点；`startup_seconds = observer_entry - started` 单列调用者启动成本，
所有累计截止时间仍从原始 `started` 计算。接收起点和进程身份检查完成后才记录接收时间，
不能把这些检查的耗时藏在更早的到达时间之后。

| 接口 | 本次改变 |
| --- | --- |
| [批次合同](../scoped_source/endpoint_batch.py) | V3 要求明确的 prelaunch 合同及启动方身份 |
| [观察与接收](../scoped_source/endpoint_batch_observer.py) | 必需外部起点、继承限额核对、启动成本及全链绑定 |
| [调用入口](../scripts/endpoint_midpoint_caller.py) | 显式转交原起点与预期哈希，不提供时钟回退或 CLI |
| [worker](../scripts/run_endpoint_midpoint_controls.py)与[审计器](../scripts/audit_endpoint_midpoint_controls.py) | V3 汇总绑定原起点，缺失成本不当零 |

不能用 `/proc` 进程出生时间补齐完整启动成本。Linux 的进程时间字段在部分创建工作后才设置，
导出的 starttime 又是 boot-time ticks；它既不覆盖调用方准备，也不能直接替换本合同的
monotonic 起点。本接口仅将该字段用于进程 incarnation 检查，不将它换算成预算起点。
参见 [Linux fork 实现](https://github.com/torvalds/linux/blob/master/kernel/fork.c)、
[proc 字段说明](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html)与
[时钟语义](https://man7.org/linux/man-pages/man2/clock_gettime.2.html)。

## 剩余依赖与停止边界

接收锚仍是明确的可信边界，不是完整操作系统或浮点计算栈证明。
