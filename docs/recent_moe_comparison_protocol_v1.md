# 新 MoE 作者制品比较：执行安排 v1

日期2026-09-21。此文是**部署及后续冻结的设计文档**，不是已完成的比较成绩，
也不是在依赖、权重身份尚未核对时直接授权整批实验自动开跑。
依据：[六篇实验研究记录](recent_moe_baselines_20260921.md)。

## 1. 三类表全部要做，但不混淆其含义

| 表 | 问题 | 固定条件 | 不能推出 |
|---|---|---|---|
| A 作者实验复现表 | 能否执行他们的方法并重现其指标？ | 作者模型、数据、威胁、指标、配置；逐项标偏差 | 我们优于该方法 |
| B 同对象验证表 | 在同一函数/域/性质上谁多证明、谁更省？ | checkpoint、物化张量、归一化、tie规则、性质、完整预算 | 不同语义模型上的普遍支配 |
| C 系统级鲁棒性—成本表 | 不同训练/认证系统在同一任务上如何折中？ | 数据、威胁换算规则、训练成本披露、分母 | 不同函数间的纯求解器优劣 |

现有ACT内部monolithic等不是这六篇作者工具。旧表保持不变。
公开论文成绩在表A标`AUTHOR_REPORTED`，原始结果文件复算标`AUTHOR_RESULT_REPLAY`，
新模型评估标`FRESH_AUTHOR_MODEL_EVALUATION`；不能以完成前两项冒充第三项。

所有正结论保留等级：原生经验攻击RA、RS统计保证及置信参数、CROWN数值过滤、
HZ冻结policy接受、给定源对象的条件化有理数检查、source-complete证明。
目前ACT主表没有闭合source-complete严格认证，23个历史增益不可因此升级。

## 2. 第一执行队列：MetaMoE作者工具

### A-META：先复现原实验

已定位作者库及`paper/artifacts`，不再让“未发现代码”阻止这条线。

1. 固定作者repo `6aed3606e4b226e18e1c9d249485d99bb453f488`，记录所有权重hash。
   安全解析checkpoint类和网络拓扑；确认各expert类别顺序、router对应的数据域。
   先核对声明的`d4c79e3`与子模块`58bb93f...`，不把现有别的αβ-CROWN安装当成同版本。
2. 单独运行目录：作者脚本会清除旧VNNLIB，必须在新副本、显式输出目录执行。
   子模块代码不混入ACT；依赖放专用环境，网络／日志上报禁用。
3. 先执行一张CIFAR和一张MNIST的加载→预处理→原生预测→导出→性质生成控制，
   不依据bound选择输入；逐层形状、BN模式、范围、类别映射必须匹配。
   导出数值探针是兼容性检查，不是全域等价证明。
4. 冻结作者Fig3/4复跑：router40条，四expert配置各20条、三半径；按作者组件300秒。
   五次重复绑定相同checkpoint时标为重复验证运行，不当五个训练seed。
   保存原返回状态、终态及每样本时间；timeout/unknown不能计成unsafe。
5. 分别报告RoCRA、ExCRA以及相同输入上两者均通过的完整组合比例；
   禁止拿两个边缘百分比相乘替代完整请求交集。

以上整批只有在代码／权重／输入／后端身份清单完成后生成可执行冻结配置。
若原作者选择脚本不能恢复原输入，标新输入复跑而非精确表格复现。

### B-META：再做同对象、同预算比较

- 对作者的disjoint-class hard top-1模型，比较作者组件验证与ACT相应验证实现。
  当前生产入口weighted top-2 **不能直接接收该对象**；先做单独的top-1完整语义适配与控制。
  不允许把类别拼接改成共享10类，或把top-1改成top-2来制造自己的优势。
- 20条首次未用于本适配设计的正确分类输入（两域各10），按原测试顺序确定，
  固定2/255；每完整请求共300秒，router+expert+导出+加载+检查都计入。
  作者组件各300秒的A表与完整300秒的B表明确分开。
- 共同物化输入上下界及归一化参数，必要时在原像素空间生成域后映射。
  两方每请求独立获得答案，交错轮换执行，不免费用对手的router证书。
- 主要结果：完整正结果gained/lost/交集、完整反例复放、unknown/timeout/error与全成本。
  在这类任务上，route change可能意味着真实类别错误；不要求必出现ACT-only SAFE。

**此对照的价值**：直接面对相关作者工具，检验组合成本与可用性。
它不是测试共享类别weighted top-2“解除路由保持前提”的最佳任务；后者另列方法范围。

## 3. 第二执行队列：Dual RS

### A-DRS：部署及原实验复现

已完成部分保存结果重算，但没有fresh certification。
先在隔离环境安装作者依赖；固定diffusion/ViT及variance-estimator模型hash。
优先用公开训练标签训练CIFAR estimator；不重新花数千GPU小时制作ImageNet标签。
主目标先是CIFAR off-the-shelf路径，再按作者90epoch→15epoch→再训练流程验证fine-tuned路径。
不得用未训练router前向通过作为认证pipeline已完成。

首个有界端到端试运行：原顺序前2张CIFAR测试图，不按clean正确或认证半径选；
N0=100、N=10,000，两阶段各alpha=.0005、作者sigma网格。资源上限和batch在启动前冻结；
OOM/超时保留，不能降低N后仍宣称原置信协议。随后20条固定前缀检查吞吐和完整性；
只有成功完成pipeline才冻结全测试复跑。随机种子列表事前固定，统计置信与经验重复方差分开。
Fig4多专家为独立子协议，绑定weak/strong每个expert、estimator和sigma关系。

零半径69.34/68.34不一致、缺CIFAR Multiscale TSV、TeX失败分别挂账；
不为了匹配论文改脚本。绘图可另设“仅绘图后端替换”的可追踪兼容补丁，不改变数组与计数。

### C-DRS：与ACT如何真正比较

同一CIFAR测试任务可报告训练／推理／认证成本及认证曲线，但注明
Dual RS证明的是平滑函数g，ACT证明的是输入的确定性MoE F；不是同一函数的解集比赛。
L2 radius r若要用于d维L∞盒，只能通过 `epsilon <= r/sqrt(d)` 的包含关系转换。
CIFAR原始像素d=3072，2/255的盒要求L2至少 `sqrt(3072)*2/255`，
且这仍只保证g，不保证未平滑F。归一化不同必须重新计算变换，不能盲用d。
主表原样保留L2曲线和失败概率，转换结果放单独列；不比较45% L2 CRA和旧HZ SAFE分母。

若想在相同base MoE上比较RS与ACT，应另行实现/冻结平滑包装，标为
`Dual-RS-inspired adaptation`，而不是原作者方法复跑；它不替代A-DRS。

## 4. 第三执行队列：RoME与Robust Experts

### A-ROME

使用作者已发布ViT-CIFAR10 MAX/APGD checkpoint，先核对完整key/shape以及未序列化的
`s,b,lora_alpha`；当前代码默认b6、论文b2，先标code-default路径，不做效果导向二选一。
原始实现完整架构已通过CPU前向/梯度，下一步是权重及数据实际加载。

首个评估控制为seed0固定的4张测试输入，执行clean和作者AutoAttack三个norm；
这不是4张上的正式RA结论。控制通过后固定100张随机索引（由作者seed0选择规则生成，
不筛clean-correct），先测端到端可用性再决定全10k论文复现。
保存三威胁逐样本success bit、扰动范数、clean label；交集才是union robustness。
不替换AA为单次PGD、不把原始无限时攻击悄悄截短还叫原AA成绩。
需要预算上限时单独列不完整攻击状态，未完成不自动视为鲁棒。

### A-RE

先在**独立兼容副本**修复缺失的`deeplabv3plus.sync_batchnorm`依赖，保留原失败和diff。
修复不得改变标准BN、gate或专家数学；如只能实现其他语义，必须改标变体。
随后Hydra配置展开、关闭W&B/ClearML上报、单batch真实CIFAR100训练及PGD7/20/APGD控制，
确认loss、梯度、扰动预算、checkpoint保存/恢复、实际路由和正常数据增强。

训练分为两个明确身份：默认源配置（100epochs/lr.1）；论文目标配置（200epochs/lr.01）。
不必全跑两个昂贵训练，但选定哪个必须在看成绩前写明。推荐以论文目标配置复现研究结果，
同时保留默认配置差异；这不是无声修复作者代码。
最低对照dense ResNet18 vs ConvMoE或BlockMoE4专家top2，固定同一train/val划分和选择规则，
共同SGD/augmentation/PGD，不按验证容易程度挑checkpoint。数据集为CIFAR100，不偷换CIFAR10。
若作者权重可取得优先评估，不强制为了部署而重训；当前未确认公开权重。

### 与ACT比较的入口限制

RoME多层token/patch混合、Robust Experts中间层路由均超出当前ACT生产入口。
阶段1可以做真实模型RA/route telemetry和静态义务后端兼容，不能填完整ACT SAFE栏。
扩展模型前必须覆盖完整共享backbone、所有路由历史、真实gate（含归一化小常数），
不能只导出clean path或冻结权重。实现不了则诚实报`UNSUPPORTED_ORIGINAL_SEMANTICS`，
不是该作者方法性能失败。

## 6. 共用验收和冻结要求

| 阶段 | 必需交付 | 失败怎么处理 |
|---|---|---|
| 来源 | 论文版本、作者commit、许可证/使用限制、权重hash、后端版本 | 无代码/权重/权限独立列，不计实验失败率 |
| 部署 | 原样失败日志、隔离环境清单、必要兼容diff、模型/CLI控制 | 不修改旧环境；不因导入成功宣称复现论文 |
| 语义 | 输入物化、预处理、输出类别、tie、softmax、BN、完整性质 | 不相同则分表或拒绝，不偷偷简化模型 |
| 冻结 | 原始索引、seed、budget、停止规则、配置hash、执行顺序 | 不凭正界或路由数量选样本 |
| 执行 | 外层截止、资源限制、完整终态、每阶段实际成本 | 全部已发请求保留，不能失败重跑择优 |
| 审计 | 独立重计数、证据等级、反例复放、交集与增失 | JSON一致≠网络证明；统计单位按输入 |

共享GPU上先检查已有任务，CPU线程/数据workers限额，不能中断其他用户。
计时表要注明CPU/GPU、等待与实际执行、是否包含postflight核对；不横比不同硬件的speedup。
目前部署receipt将启动和preflight计入执行期限，postflight另外记录；
这是部署控制，不是未来表B的完整请求预算执行器。
