# HybridZ 传播的完整预算监督控制

本阶段把已通过控制的 checked-support 传播入口接入独立版本的监督执行，不改变
支持算法、选行数、精度、数学义务或旧生产入口。起点 `cec603728`；
[协议](../configs/hz_propagation_supervision_20261001.json)在实施前冻结。
全部是固定合成 CPU 请求，不运行 checkpoint、数据集、原生优化或 GPU。

## 完整执行与来源边界

一个至多 300 秒的调用依次执行 produce、check、receive。producer 内重新创建
小型输入/router HZ 和 ACT 网络，执行真实 analyzer、检查支持、ReLU 传播并序列化。
原生回退仅测试等待/异常接入位置，不执行求解器。checker 在独立进程检查完整层
与上下界义务、来源身份及全部已使用的有理数支持证据；receiver 接收父进程实际
锚定的 payload 和 checker 输出。worker 不得改写父进程截止或自报一个新身份。

正常控制沿用上轮 retained guard、disabled、guard discarded、two layers 四个
固定来源，要求源 scope 一致。新生成输出和检查界与已存参考做差分，但不读旧答案
用于运行。构造、导入、哈希、传播、检查、序列化、进程启动、接收、清理、终态和
返回都计费；内部时间是外层时间的子项，不能重复相加。没有外部观察到的返回，
离线文件不能独自证明预算内执行成功。

成功只表示 `CHECKED_PROPAGATION_EXECUTION_CONDITIONAL_ON_TRUSTED_LOWERING`。
网络到 HZ、guard lowering、公共因子意义和既有浮点传播仍受信任；每个实例仅涉及
一个 route/expert，不是完整 MoE 输出认证。已使用的支持证据不得缺侧或缺层。
检查失败、部分输出或迟到产物保持未接受；负界不被解释成 UNSAFE。

## 有界进程清理

旧执行器 killpg 后无界 wait，不修改它及其冻结审计。新 CPU 执行原语单独版本化，
在每个阶段内部预留清理时间，使用非阻塞退出观察、SIGKILL 和有时限回收，最后
检查该新 session 的存活成员。清理未确认必须记为 `CLEANUP_INCOMPLETE`，不能成功。
只操作本调用创建且仍可确认归属的进程组，不干预其他用户或测试 sentinel。

范围限定为受控、不 daemonize、不主动换 session 的 worker 及其同组后代。
不宣称可清理任意逃逸后代、内核不可中断状态或 GPU driver；实机 GPU 准入仍独立。
父进程文件系统操作不能由子进程 watchdog 强制打断，因此最终接受还必须检查
实际返回时钟；若磁盘/内核异常造成返回超预算，如实计 TIMEOUT，不声称严格实时系统。

## 冻结控制及停止规则

四次正常调用与十四次预注册故障全部保留。故障覆盖创建前截止、传播异常、模拟
原生阻塞、序列化截止、缺包、错误来源、检查异常/截止/缺输出、接收/发布截止、
启动失败、资源限额和 leader 退出后的同组存活后代。每个故障必须有实际到达标记，
不能把更早的导入超时算成通过。进程原语还做 bounded wait 模拟与无关进程隔离控制。

结构变异检查覆盖假造成功、删义务、删失败前缀、改变来源、环境、成本和外部返回。
全部正常支持界独立重检；归档审计不重复运行候选，不将 JSON 一致性称为网络重证。
不因控制耗时或失败而加时、扩样、提高容量或开启真实实验；先按记录修复接口。
