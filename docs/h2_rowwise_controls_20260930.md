## 实现与数学合同

[原生适配](../scoped_source/rowwise_native.py)在 SciPy 导入和浮点 CSR 构造前，
逐行验证全部原始 CSR，包括零对偶行、显式零、空行、指针与列序、RHS、有限变量盒
和目标。仍要求原生求解成功；候选必须通过原 LP 的独立精确检查才可返回。
实际原生求解尚未在本阶段执行，控制使用替身后端检查调用与拒收行为。

[独立检查核](../scoped_source/rowwise_bound.py)逐行累加精确残差。对于
`Az <= b, Ez = h, l <= z <= u`、`y <= 0` 和任意 `t`，保持旧规则：

```text
r = c - A^T y - E^T t
L = offset + b^T y + h^T t + sum_j min(r_j l_j, r_j u_j)
```

每个输入系数均以精确有理数解释；JSON binary64 按其实际二进制值解释，而非按
十进制显示近似。检查全部行后才接受 `claimed_lower_bound <= L`。原始 LP 和证书
在检查前后重算身份；普通别名／回调污染会被拒绝，不承诺检测恶意并发修改再恢复。
所有路径共用调用者的绝对截止时间，结果构造后仍检查截止。

旧原生 `evaluate()` 本来已逐行累加；本次改变的是原生**预校验**的
`list(rows(...))` 和来源检查核的全矩阵精确行构造，不把旧能力重新宣称为创新。
新的 JSON 来源合同要求显式 `offset`；差分针对共同的有效输入域，不声称新旧
接口对所有畸形 Python 对象的接受集合相同。

临时行生命周期控制观察到最多两个行对象：迭代器可能短暂同时保留上一行和新行。
这支持临时精确行存储为 `O(max_row_entries)`，不是总内存常数、RSS 上界或性能测量。
原 LP、向量、完整浮点 CSR、求解器工作区和 canonical JSON 身份序列化仍可能驻留。
合作式截止也不等于外层硬截止；一次长整数运算或原生调用仍需进程监督。
