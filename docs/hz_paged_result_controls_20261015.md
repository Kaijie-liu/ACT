# 默认关闭的分页结果：实施与有限控制

协议先于实施在 `2ea468ed6` 提交并推送：[冻结协议](hz_paged_result_protocol_20261015.md)。
本轮只使用固定候选、既有 half／guarded 标准库源；不运行真实模型、原生优化器或 GPU。
新功能通过 `method(..., shared=True, paged_results=True)` 显式开启；旧方法和格式仍默认。

## 实现与保证

`result_stream.Writer` 只保留当前最多 8 行、至多 64 KiB 的结果页，以及至多 32 个引用。
Session 仍核验全部候选 receipt、全部端点和全部性质，逐行生成精确下界／缺失哨兵；
不会先构造完整结果数组再切页。来源 reseal 成功后才发布 index。完整缺失证据得到
UNKNOWN；中途停止、缺页或未封存 index 不能接受。

方法、manifest、bundle、执行 invocation、worker report 和最终 receipt 使用新 schema。
上下文分别绑定来源、forest、forest index、性质 contract、方法、执行身份和私有计划的
完整端点 roster；index 再绑定有序原始候选引用。当前共享格式的 forest identity 就是
index hash，所以两种语义角色的值相等；旧静态说明中“必定不同”的说法不成立。

生产、portable replay 和父接收只报告摘要及结果引用，没有重复完整结果行。搬迁检查
仍重建来源／性质计划，完整消费原始候选，独立重算全部端点，再逐行与已保存页比较。
父进程另外从来源声明重建全部 pair/property 清单并检查精确符号和计数；这一步不是
又做一次底层数学证明。不能以引用哈希自洽替代独立重算。

新增模式使用固定错误码，不调用异常的任意 `str`／`repr`。启动读取失败也由受信任
监督器参数选定的最外层边界处理。最终 receipt 写入／读取失败时，返回无接受结果、
无虚构 receipt hash 的 `INCOMPLETE_TERMINAL` 审计状态；能够核对存储也不宣称完整
成本审计通过。晚到的成功文件不能补救超时。旧错误处理模式保持原行为。

## 验证与失败保留

实际运行和实现绑定见[机器记录](hz_paged_result_controls_20261015.json)。
最终第三轮 **171/171 通过**（15 项新控制＋156 项既有回归），约 91.29 秒完成整套测试，
不是单请求耗时或性能比较。监督记录含 15 次 COMPLETE（包括完整 UNKNOWN）、12 次
ERROR、6 次 TIMEOUT，以及另列的最终部分写入／晚到发布两项。每个预期失败均拒绝接受。
三轮控制证据各约 26 MiB，保留在项目 `runs/`，只提交紧凑记录与代码。
最终全部新成功请求和搬迁检查均绑定 300 秒；短截止仅用于故障。50 个代码／协议／
测试文件的归档 SHA-256 与当前实现一致，旧回归仍执行各自原注册控制。

控制覆盖 2 源×2 臂×2 profile 共 8 个组合、短页与 8+4 两页、完整 UNKNOWN、重哈希篡改、
缺失／重复／错序义务、身份错误、位数与页上限、别名污染、来源封存失败、部分输出、
截止、最终收据失败，以及两臂搬迁后 `python -I -S -B` 全部义务重算。
搬迁进程拒绝访问仓库和旧目录，未导入训练／数值库，也不调用来源 producer。

两臂的下界篡改控制更新 page→index→manifest→bundle 全部哈希，以新 bundle hash
进入检查；均必须在“独立重算结果行”处拒绝。此项比仅拒绝旧哈希更强。
252 行／32 页的大数测试仅为格式容量控制，不构造或接纳完整规模模型。

本批完整控制请求观测耗时为 0.552–0.749 秒，保留字节 339,511–474,174，最大 Work
为 21,686；只是固定微型控制的运行记录，不能推算真实模型耗时或宣称加速。

首轮完整回归目录 `runs/hz_paged_result_controls_20261015_r1` 保留两项错误：
默认 Driver 把 `sink=None` 作为新关键字传给原有截止控制的替身函数，触发 TypeError。
修复为默认路径保留原调用方式，不修改原测试。第二轮 `r2` 测试全过，但终审发现
成功控制与搬迁仍沿用 30 秒默认测试预算，不符合本轮冻结的 300 秒协议。它不是最终
协议完成证据。修正测试入口、增加主动旧路径拒绝探针后，在新 `r3` 目录重跑同一套
控制并通过；未改变任何额度或接受门，也不拼接各轮结果。
更早一次启动使用不存在的 `results/` 父目录，创建目录前即失败，未启动 worker；随后
使用项目既有 `runs/`。这些是控制执行记录，不是模型结果。

## 成本与仍未闭合的边界

全部创建、页编码、写入、来源 reseal、完整 replay、接收和清理仍计入同一不超过
300 秒的请求时钟。缩短的截止仅用于故障控制。Work 沿用旧计数定义；新增 JSON／
Fraction 解析和符号检查的实际时间计费，但不能把 Work 解释为所有机器操作和 I/O 次数。

结果页成功路径仍完整读取十遍：portable 两次 inventory＋逐行重算比较，archive
两次 audit，父层 inventory＋逐行聚合，以及三次 census。离线审计／搬迁另计成本，
不能救回在线超时。所有失败前缀保留在磁盘计账中。

实际 schema 比原提案新增了 replay context、页数及 stream snapshot。
[实际布局核算脚本](../scripts/assess_paged_result_implementation.py)沿用原条件化成功
布局假设，给出下列上界；旧报告不覆写：

| 项目 | 字节上界 |
| --- | ---: |
| 单页／index | 40,057／5,431 |
| 全部结果页 | 1,261,868 |
| Manifest／bundle | 36,929／111,344 |
| Worker report／父 receipt | 165,242／38,312 |

仅新增 2 个便携模块；便携代码 28 文件、执行绑定 47 文件。上述数字不是任意故障、
堆内存、完整 RSS 或真实模型的完成保证。单页在编码前做闭合类型／长度检查，编码
缓冲区有固定上限；整体 archive 剩余额度仍由 `Archive.put` 检查，不能称整体额度检查
早于每次缓冲区分配。原 8M Work、65,536 membership、128 MiB arena／归档、位数
门、严格正界门和 CPU／GPU 权限均未改变。

这完成的是结果与证据接口，不是新增 HybridZ 算法收益或真实证书。完整八专家容量、
内存／原生工作区仍不准入；G1–G6、历史主表来源缺口及封存边界保持原状态。
后续应先对实际版本做资源准入分析，不能把本轮控制通过当作真实模型或 GPU 执行批准。
