## 保证变化与不变项

| 项目 | 现行前置要求 | 替代合同拟采用的要求 |
| --- | --- | --- |
| 原生完整空间 | 在完整容量上界闭合前不准入 | 记录未知工作区；在另行获批且可核验的硬限制内尝试，资源不足可以失败 |
| 自有表示和存储 | 按绑定实现列出构造、检查、归档、部分证据与存活账本 | 保留；未知项仍为未知，不计零，不将命名载荷冒充整进程峰值 |
| Work与独立额度 | 保持计数含义、累计额度和各自拒绝门 | 不变；不会用原生内存监管代替 Work／字节／成员门 |
| 完整正结果 | 全部必要义务按原门接受 | 不变；原生候选仍须对原始绑定系数独立精确检查 |
| 时间 | 同一300秒接受期限，全流程计费 | 不变；OS延迟造成超期时拒绝，不承诺所有调用总能及时返回 |
| 科学结论 | 容量与控制不等于算法收益 | 不变；G1–G6均未因合同起草而完成 |

这里的“成功容量”是完成全部处理所需空间的容量保证，不是一定得到正证书或在300秒内
完成的保证。替代合同不把测得峰值、限制数值或成功的小控制反推为这种容量上界。
若以后批准替代方向，应明确修改第一里程碑的这一条资源前提；在批准前旧前提仍有效。

注册目录仍是八专家、共享十类输出、selected-softmax top-2、全部28个保守pair、252条

## 硬限制的范围和准入要求

后续冻结必须从可信外层协议绑定限制机制、具体值、角色、实现与环境身份、来源对象、
累计计数、绝对截止时间及attempt身份。候选或证据包不能选择、提高或重置自身额度。
本稿的机制、数值、实施身份及真实来源均未选定；任一必填项缺失即不准入。

逐进程 `RLIMIT_AS` 可以作为待审候选机制，但只能声称限制该进程的虚拟地址空间，
不能换名为聚合RSS、显存或系统内存保证。线程栈和映射属所在进程；RSS采样应按不同PID
统计，线程不重复相加，共享页可能跨进程重复计数，采样也可能漏峰。硬聚合约束若有需要，
其机制、权限及覆盖范围必须另行绑定；不得假定可写cgroup或修改共享资源配置。

[旧监督设计](hz_staged_memory_protocol_20261015.md)限定标准库固定候选，不能直接继承
其无额外线程／后代假设或 `3×AS` 包络到Torch。新冻结必须列出全部角色、并发阶段、
原生线程／后代和退出核验方式，区分受OS强制约束的部分与可信代码假设。无法核验覆盖、
继承或所有权时拒绝，不能退化为仅采样RSS后仍宣称硬限制。native不能通过另起未计费
进程规避限制；GPU单独冻结，CPU的AS机制不覆盖设备显存。

初始解释器和最小bootstrap在限额生效前的载入边界须显式说明并计时。后续模型、原生库、
来源及候选载入只能发生在获批限制安装、回读和身份核验之后；安装／继承失败即拒绝。
不得先导入大库再降低限额，声称载入也受该限额约束。监督器自身资源同样必须纳入范围；
其死亡或资源不足只能留下未完成结果，不能由成功文件代替监督证据。

## 完整检查和终态链

后续实现须保留两遍fresh完整来源／端点核验，以及独立结构接收。进程间传递绑定文件、
有限字节和累计计数，不以live checked对象、旧receipt或缓存代替新一遍检查。搬迁检查
只读证据包与外部批准的检查器身份，不依赖checkpoint、数据集、旧目录或求解器。
调用代码先经可信身份核验，不允许包内检查器自行授权自身。

正结果必须同时满足：全部义务覆盖、全部原数学／数值门通过、实现和来源绑定正确、
两遍结果一致、成本与归档闭合、受监督角色退出及所有权清理核验完成，以及终态发布／
读回和调用者确认在原截止内。资源监管不检查网络语义，不补上未完成的来源转换证明。
未闭合的网络→HZ／guard等仍列入可信基础，历史23个增益的来源缺口不会被本稿修复。

| 观察 | 终态要求 |
| --- | --- |
| 缺批准身份、限制无法安装／继承、已知静态必然超原门 | `ADMISSION_REFUSED`，不载入实模或生成候选 |
| 有充分记录的Work／字节／内存限制触发 | `RESOURCE_LIMIT`，记录具体机制和已知前缀，不接受 |
| 异常信号、MemoryError或ENOMEM但无充分归因 | 错误／未完成，保留原始码；不武断归为OOM |
| 300秒到期、晚到文件或调用者超期确认 | `TIMEOUT`或未完成；磁盘上的COMPLETE不能挽回 |
| 部分义务、缺页、监督／清理／接收链不完整 | 未完成；不能冒充遍历全部义务后的UNKNOWN |
| 全部义务遍历完整，但某必要下界非正或按schema缺证据 | 完整UNKNOWN；不据此认定模型不安全 |
| 完整动态模型见证有效复放 | 才可能按原契约接受UNSAFE；静态专家／松弛违规不够 |

所有失败保留分母和已生成证据，不自动重试、换额度或缩小义务。非正下界不等于LP最优值
非正，更不等于原模型不安全。检查成功也不升级为原生PyTorch／CUDA浮点执行证明。

## 统一时间和失败成本

`t0` 在首次监督启动前记录；所有阶段共用 `t0+300`，准入等待有界且单列，执行内等待
收费。加载／捕获、构造、限制安装、原生调用、检查、搬迁、序列化、接收、清理和终态
均在同一预算。进程分开不获得新300秒，也不把生产与在线独立重查拆成两个免费请求。

墙钟按不重叠阶段区间汇总，内部剖析是子项，监督轮询不能重复加到总时长。进程被杀后
最后核验计数只作下界，缺失值为 `null`，并记 `cost_complete=false`；不能填零或直接
把观测时间裁成300秒。OS延迟导致的实际overrun另报且不接受，失败终态若未及时生成
也如实标记。离线取证成本单列，不能补成在线成功。保留旧有收尾预留，具体新增字段与
归档预留在实施冻结时闭合，不凭本草案额外分配空间。

CROWN数值正过滤不冒充严格证书，也不因缺少本检查器就算同等级失败。硬限制下取得
完整结果只支持该受限执行协议下的覆盖，不支持全形容量或普遍领先；G1–G6验收不变。

3. 控制通过后，分别审批完整容量尝试、有限真实development和独立确认。GPU需单独
   物理准入与协议，封存输入／搜索不重开，模型与样本不按结果选择。

旧协议、失败及额度原样保留。当前限制是起草权限而非执行权限；该草案本身不产生
