# 设备候选执行的有界清理与归还合同

本阶段只把现有设备可选候选核接入新版本监督，保持四个既有合成 CPU 来源及八条
支持义务不变。先冻结[12 次调用](../configs/hz_device_lifecycle_20261001.json)，
不运行 CUDA、原生优化、真实模型或新性能比较。旧协议和执行器均不修改。

流程为准入、创建/候选、清理后归还观察、独立精确检查、接收。producer 异常或
超时也必须经过归还记账；只有进程清理未确认时停止后续启动并记明归还未执行。
所有阶段、冷启动、源创建、失败前缀、检查、序列化和返回共用不超过 300 秒时钟。
控制通常用 30 秒，两个截止控制用 8 秒；不根据结果加时。

必须区分三个命题：

1. **进程清理已确认**：leader 已回收、所属组无存活成员。范围沿用 bounded CPU 原语，
   不涵盖逃逸 session、所有孤儿 zombie 或内核/GPU driver 的完整正确性。
2. **已观察到本调用的 GPU 进程消失**：两次新鲜、完整、UUID 绑定的清单均不含父进程
   所绑定的本调用 producer PID。清单不完整、PID 重用/所有权有歧义或观察逾期均拒绝。
   这是进程可见性观察，不是物理显存字节全部恢复的证明。
3. **设备适合下一次准入**：另行应用空闲度、空余显存和其他租户清单规则。
   新租户到来可以使第二项成立、第三项不成立；不等待或终止其他用户来伪造归还。

CPU 正常记录明确无需 CUDA 归还。模拟观察必须标注 simulated，不能产生真实硬件
已检查标签。GPU 清单解释与数学下界检查互不替代。

父端绑定协议、源码、绝对截止、worker 身份和各阶段实际输出字节。checker 仍针对
原始给定 HZ 的全部目标，CPU 精确重算；不信候选收敛、最优性或自报正界。新监督器
只能组合既有数学函数，不猴补旧 worker 的冻结全局变量以绕过 CUDA 禁止条件。

四次正常调用与八次故障/归还情景全部保留。另做不启动求解的变异控制，覆盖错误
UUID、PID 歧义、跨请求记录、缺失归还证据、截止、NaN 成本、改写 checker 输出及
删除失败前缀。已有数值控制做回归，不重新复制全部故障表。

验收是完整账本、同源八界差分及正确的拒绝/继续规则，不是 GPU 加速或 MoE SAFE。
任何真实清理未确认都停止后续执行；模拟未确认仅说明控制到达，不能据此宣称
硬件异常。通过后才另行冻结实机小控制并检查共享资源，不自动启动真实或全尺寸任务。
