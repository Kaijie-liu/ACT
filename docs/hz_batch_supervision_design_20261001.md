# HybridZ 批量支持的硬预算执行合同

本阶段只把[已通过 CPU 控制的接口](hz_batch_support_controls_20261001.md)接到
现有 owned-process 执行器；不改变候选算法、原始 HZ／目标、接受公式或阈值。
[配置](../configs/hz_batch_supervision_20261001.json)先于实现与执行冻结。
四个固定合成来源沿用已存整批身份，但每次计时内重新创建 HZ、导出和生成候选，
不读取旧候选／历史求解答案。完整支持执行不是全部正界或 MoE SAFE。

## 调用方身份与阶段

父调用方固定 case、原 batch hash、query ID／方向及协议身份，再生成本次 invocation。
生成、检查和接收各在受控子进程中执行；不同阶段共用同一绝对截止时间。
生成预留 min(5 秒, budget/4)，最终发布预留 min(1 秒, budget/5)。
正常小控制使用 30 秒，故障控制按配置使用更短上限；真实请求仍为 300 秒，
本协议不启动任何真实请求。资源上限 2 GiB 为采样监测，不是 OS 硬配额。

生成包含导入、合成 HZ 创建、导出、候选与序列化。父进程在生成器退出后锚定
实际 bundle 字节；检查进程验证固定 batch 身份并调用原精确接收器。
父进程在检查器退出后自行锚定 check.stdout，不能接受 worker 自报的输出 hash。
接收器检查同一 invocation、请求、batch、完整义务清单及保证等级。
缺候选仍保持原清单，保存部分文件并拒绝完整接收，不修改数学检查器使之通过。

每次 execute 返回后先保存阶段成本，再处理缺失／损坏输出；启动失败和检查器
运行后丢失 stdout 均不能漏记。终态、最终发布和实际 API 完成观察共同决定
预算内接受；离线重新检查不能补成在线成功。晚到、异常、资源限制和清理超时
优先于已生成的候选。只清理本调用所属进程组，不干预别人的作业。

## 控制及停止边界

四个正常例分别检查双侧 guard、非正性质、等式耦合和私有二元列。
16 个故障调用覆盖生成／准备／检查／接收／发布阻塞、候选异常／缺失、错目标、
错 invocation、改写已锚定 stdout、缺 stdout、残留子进程、启动失败与资源限制。
另检查错误／空 hash、重绑后终态成本篡改、发布过期、无外部完成观察与清单删除。
不因控制失败调整 fixture、算法、预算或结果门；实现错误可在保留首轮后修复。

原 production fallback 不变；本支持控制不启用原生回退，也不宣称这部分已接入。
独立检查进程仍通过普通 ACT 环境导入；本轮不宣称 python -S 可搬迁或不加载依赖。
没有模型传播成本可以测，不能用这些合成支持的秒数替代真实 MoE 端到端成本。
GPU 继续禁用。通过后才研究下一门的 GPU 候选／准入，或单独的生产支持接入。
