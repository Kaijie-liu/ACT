# HybridZ 设备监督与资源准入控制

本阶段把已通过 CPU 参考的设备候选内核接入独立版本的完整监督。候选算法、
原始 HZ、目标及独立精确接受规则不变；不修改旧 CPU 监督器或生产入口。
固定配置为 [device supervision](../configs/hz_device_supervision_20261001.json)。

## 范围与资源边界

本轮固定执行四个既有 CPU 来源以及十八个拒绝／故障控制，没有实际 CUDA 调用。
CUDA 准入代码只读查询 UUID、利用率、空闲显存和计算进程，要求两次间隔观察都通过。
繁忙、缺失／畸形查询、超时或身份变化时拒绝；不以剩余显存足够覆盖利用率或进程门。
快照不是排他锁或预约，跨用户启动竞态仍存在；未来硬件控制必须另行冻结和准入。
测试注入明确带 stub 标签，不能作为物理 GPU 证据。

只允许 producer 新进程看见指定 UUID；parent/check/receive 不初始化 CUDA。
上下文由监督器绑定同次 invocation、原始 batch、produce 绝对截止和 allocator 限额。
内核启动前重验设备状态；如不再可用，不继续执行。1 GiB 仅为缓存分配器限额，
不是 CUDA 上下文或 OS 显存硬配额。owned-process 清理不自动证明驱动显存释放完成。

## 统一成本与接受

复用既有 owned-process execute 和 append-only I/O，新增 admit 阶段；准入、导入、
创建／导出、初始化／传输／同步、候选、CPU 精确评价、序列化、独立检查、父进程
锚定、完整清单接收、清理及终态发布都在同一绝对预算内。admit 阶段至多三秒，
不在本轮增加后台等待；真实实验上限仍为 300 秒，正常控制三十秒。
候选 cost_seconds 是 producer 阶段的子费用，不与阶段墙钟重复相加。
失败缺少候选费用时，保留父阶段总耗时和事件前缀，不能默认为零。

父进程锚定 admission、payload 与 checker stdout。每个输出继续绑定原 batch、
query 顺序／方向及完整义务数；部分、错设备元数据或晚到证据不能完成接收。
正常状态仅指给定 HZ 支持执行完成，负界也可正常完成，不代表 MoE SAFE。
硬截止控制只终止自己启动的进程组，不修改其他用户任务。

## 验收和后续

四个正常来源必须与旧精确界一致，故障需证明实际到达注入位置，不能只匹配状态名。
覆盖准入阻塞／异常、生成／检查／接收／发布截止、候选异常、模拟 OOM／同步／
回传阻塞、部分证据、设备篡改、缺输出、晚改写、启动失败和 RSS 超限。
另查必需 hash、身份污染、计费和完成观察、准入 UUID／畸形数据与缓存过期边界。

保存所有执行、失败、实现身份和紧凑独立审计；不扩样、不改数学门，不运行真实
LP/MILP、checkpoint、数据或训练。通过后才考虑单独冻结微型 CPU/GPU 实机控制；
未运行时不宣称加速，生产传播接入、同源完整证明与外部比较仍为 OPEN。
