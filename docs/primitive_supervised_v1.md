# Primitive integer reconstruction: separate budgeted supervision V1

## Result and scope

The 2026-09-20 instruction was to integrate the optional bit-growth-control
component under unified supervision, check deadlines/partial evidence/full
costs, and **only then consider** a separate real diagnostic freeze.
This integration is complete. It does not rerun or relabel any real obligation,
change the production MoE verifier, or replace the frozen V2 path.

`primitive_supervised/` is a separate supplied-LP execution identity. Controls
`primitive_supervised_controls_attempt001.json`: **101/101 PASS**, comprising
32 integration tests, seven native-fidelity regressions, and 62 arithmetic /
original-LP regressions. Fresh-process review `primitive_supervised_v1_review.json`
checks **1,677 artifacts, 23 terminal records and all recorded cost fields**;
five relocated packages run with `python -I -S`, PASS with zero issues. Four
points are exactly feasible; the fifth is correctly rejected for an original
LP equality discrepancy. The terminal label `CHECKED_LP_DIAGNOSTIC` means the
check completed, not that its proposed point passed feasibility.

No real network LP calls or reconstructions occurred. Synthetic/native controls
are not real-model efficacy or performance results. Historical source identities
and the four V2 real diagnostic artifact hashes are checked before and after
controls and fresh review. All historical limits and failed attempts remain.

## Unchanged mathematics and acceptance

The new constructor copies the frozen original-coordinate assembly and uses
`primitive_basis.engine.eliminate` unchanged. It adds instrumentation, not a
new pivot rule or arithmetic fallback. An exact differential control checks
bundle, row residuals, assembled-system hash, operations, statistics and bit
metadata against the uninstrumented component.

The native stage remains `fidelity_supervised.native`: the same 1.14.0 options,
kOk-only import and complete intended-binary64 before/after readback. Its policy
identity is distinct from the primitive arithmetic policy and both are bound
in the plan. No warning bypass, pruning, dependency change or scaling is added.
One native call, at most ten seconds; one basis and one reconstruction attempt.
The 4096-bit, dimension, entry, fill, heap and operation caps are unchanged.

Construction remains candidate-only. A separate, unchanged original-LP checker
must check every equality, inequality, finite box and objective. Singular bases,
LIMIT, TIMEOUT and exceptions never establish infeasibility or network UNSAFE.
Even a checked negative feasible LP objective is not a concrete network witness.
No network SAFE/UNSAFE flag is set by this interface.

## One original clock

All stages receive the original monotonic request start:

| Window | Absolute cutoff relative to original start |
| --- | ---: |
| Load, native capture, mapping, exact construction | 218 seconds |
| Packaging, isolated checking and candidate review | 298 seconds |
| Terminal publication | 300 seconds |

No stage resets the clock. Owned subprocess groups are terminated at the
relevant cutoff; cleanup delay remains charged. Late proof/publication is not
accepted. Existing other-user jobs are not interrupted. Fault tests advance the
supplied original start to exercise cutoffs quickly: their reported 218/298/301
second clocks are **not** newly consumed wall time or timing benchmarks.

The whole supplied-LP clock includes startup, loading, imports, fidelity checks,
mapping, assembly, elimination, serialization, portable packaging, checking,
in-request review and terminal publication. Historical network propagation,
range proofs and F0 construction are not silently added or treated as free
end-to-end work: this is explicitly a **supplied-LP diagnostic**, not full MoE
latency. Resource inspection and post-terminal fresh review are separate.

## Partial evidence and cost ledger

The new bounded journal records immutable numbered snapshots at arithmetic
phase changes and every 100,000 counted operations (maximum 256 records).
Snapshots bind the request plan, LP, statement, hint, original start and deadline.
They save the current phase, completed phase windows, operation/bit maxima,
first limit context and bounded pivot metadata. Phases are setup, assembly,
row clearing, elimination, back-substitution and candidate construction. These
are instrumented code regions, not a claim of independently measured kernel
times; journal serialization is charged within these regions.

Every snapshot is labelled `PARTIAL_DIAGNOSTIC_NOT_PROOF`. It is not a checkpoint
for resuming a search, a complete elimination transcript, or a feasibility
certificate. A killed operation cannot guarantee a snapshot of its final
machine instruction. The retained prefix reports only what was observed.

The reviewer checks numbering, identity, monotonic clocks, unchanged completed
prefixes, bounded record counts and agreement with the completed constructor.
A malformed final write is retained as censored only for an interrupted/error
path; a missing middle record or incorrect binding rejects. Missing elapsed
time is `null`, not zero. A closed arithmetic journal followed by an interrupted
result write is still not an accepted candidate.

`construction_write_entered.json` and `construction_write.json` separately
account for candidate/result serialization. Their receipt/hash write and other
overhead stay inside the outer construction phase. Accounting is hierarchical:

```
whole supplied-LP clock = disjoint recorded phase windows + residual
constructor = arithmetic regions + constructor residual
native / constructor / serialization costs are nested, not added again
```

Batch helpers preserve every denominator row, stop after ERROR, and mark later
rows NOT_RUN_AFTER_ERROR. TIMEOUT/LIMIT remain unresolved. Missing or unstarted
costs are not imputed as zero.

## Controls and fresh review

Controls include complete/redundant LPs, a 4,096-variable / 8,192-equality
synthetic sparse system, exact rejection of a subtly inconsistent equality,
native admission limits, no implicit retries and original-clock expiry.
Test-only injections interrupt native capture/readback, row clearing,
elimination, back-substitution, serialization, checking and the outer process.
Arithmetic exceptions and bit-limit terminal handling are tested separately.
The injected bit limit is a supervision control, not evidence that a real basis
crossed that limit. Production has no fault-selection flag.

Mutations cover source/policy and request identity, missing proof records,
resigned cost overclaims, phase clocks, journal binding/omission/prefix errors,
late publication and checker execution flags. Exact arithmetic regression
controls retain the previously established positive and adverse bit-growth
examples; the method is not declared universally superior.

The retained test suite ran in 37.916 seconds (receipt 39.714 including surrounding
work). The synthetic large native pipeline's whole supplied-LP clock was 2.789
seconds; this is only an observed control cost, not a real-LP speed claim. Its
portable recheck and four smaller rechecks reproduce all mathematical outcomes
with no solver or model import. Fresh review reconstructs the cost ledgers; it
does not independently prove the native implementation or elimination trace.

diagnostic** may now use the same four original LPs and one immutable basis
attempt per request, with all caps unchanged, a fresh output directory and the

comparison. No alternative basis, enlarged cap or automatic old/new portfolio.

Acceptance is complete original-LP checking, not merely completing elimination.
Report first-limit phase/bit sizes, exact feasibility/rejection, partial evidence

opened by this implementation stage.**
