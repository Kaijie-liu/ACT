# H2 分块来源与逐 pair 证据表示

本阶段接续 `feat/moe-route-verification`、`c46ae20eb3e6313a805a868fe517ef243fcac5f8`
上已经开始的八个未提交文件，完成同一表示阶段，而非另开真实实验。新格式将原始系数
分块保存、来源约束各保存一次，并在生成与检查时一次处理一个 pair 的基础 LP。
四个固定合成请求的全部性质与旧展开表示精确一致；它没有改变数学、增加正结果或
证明真实模型已能在 300 秒内完成。

这一步针对[容量审计](h2_model_intake_20260930.md)发现的单一大源文件及逐性质重复
矩阵问题。硬预算监督、可搬迁包、流式模型捕获和真实容量准入仍未完成，因此不能
直接启动真实请求。生产 ACT／HybridZ 入口、旧结果、封存输入和接受门均未改变。

## 冻结对象与表示

[控制协议](../configs/h2_factored_controls_20260930.json)在首次运行前固定，canonical
SHA 为 `d3120813b9613c9e4430728a77416bb3e8bb7351ca445e0f2cc87ed34997822a`。
沿用四个既有声明及 endpoints／McCormick 两臂，不选择新模型、样本或半径。
协议固定全部 unordered top-2 pair、全部非标签性质、gate、复用规则和 `1e-7` 严格
正接受阈值。空 guard 仍有义务；未提供证据不能作为正结果。

[来源层](../scoped_source/factored_source.py)将 binary64 原始字节保存为有顺序、长度、
偏移和哈希约束的块。模型状态仍绑定原 dtype、shape 与原始字节身份；包括有符号零，
不通过浮点十进制文本回转替换源数据。新 source manifest 是新的格式身份，不冒充旧
整体 JSON 的 SHA。默认块上限 1 MiB，本控制用 64 字节，覆盖多块顺序与污染检查。

来源头上限 4 MiB，普通成员 16 MiB，来源总计 256 MiB，包总计 2 GiB；每 tensor
最多一百万元素。新格式另限制最多 1024 类及更严格字段语法。这些是拒绝超限的接口
规则，不是可用 RAM、运行速度或所有旧 source 无条件兼容的证明。

[生成器](../scoped_source/factored_build.py)逐层读取源系数，发布一次性的输入、仿射、
ReLU 约束块。pair 记录绑定有序私有变量映射、guard、gate 和基础矩阵身份，性质记录
仅附带目标身份与证书；不在每条性质中保存基础矩阵副本。两端仍分别生成候选；
McCormick 仍重建差值界、乘积变量和四条外包络行，没有删除必要检查。

当前没有全部 property 的基础矩阵库存，但仍保存全节点范围、引用、输出和义务账本；
候选调用前复制单 pair 的目标 LP，返回证书也隔离复制。McCormick 会临时持有基础与
扩展 LP。**这不是恒定内存算法。** `pack()` 目前从已有完整声明生成分块，也不是
从原生模型直接流式捕获；不能把接口后的改进说成完整上游已避免全量驻留。

## 检查器检查了什么

[独立检查器](../scoped_source/factored_check.py)不调用生成器、数值库或求解器。
它完整遍历来源，从原字节精确解析有理数，独立重建输入盒、仿射／ReLU 范围及行，
再重建每个 pair 的变量、guard、gate 和每条性质目标。成员哈希只绑定身份，不代替
数学重建。未使用参数在遍历末尾拒绝；不能仅消费来源前缀就出结论。

全部不同 gate 端点都保留，即使两个端点恰好对应同一目标 LP。复用按性质进行；
MC 的源区间事实仍绑定重建后的目标 LP，并与真正的 LP 下界检查分开计数。
负界只得到 UNKNOWN，不是模型 UNSAFE。最终库存来自 manifest 固定成员集，检查
过程中新增来源文件也会拒绝；这不等于提供了文件系统原子快照。

[归档重检](../scripts/check_h2_factored.py)除了重检每套证明，还比较新旧完整有序源
节点、请求和输出，逐项比较来源块、pair 基础矩阵、性质表达、gate、实际 endpoint／MC
目标 LP，以及显式复用清单。只比较下界相同不足以支持表示等价，因此这些比较不是
可选摘要。该小控制 oracle 会展开旧格式，仅用于归档复核，不进入新格式核心路径。

## 结果与失败保留

[R2 紧凑归档](h2_factored_controls_20260930_r2.json)包含四个请求、两臂，共八套新包。
每臂都另外生成同源旧表示证据；没有复制旧历史正界。下表是完整覆盖中的正义务数，
不是独立输入数，也不是本轮新增证书收益。

| 固定请求 | Endpoints | McCormick | 新旧表示比较 |
|---|---:|---:|---|
| weighted_sign | 3/3 | 2/3 | 全部相等 |
| tied_partial_reuse | 18/18 | 18/18 | 全部相等 |
| unsafe_tied | 0/6 | 0/6 | 两臂均 UNKNOWN |
| unresolved_sign | 6/6 | 6/6 | 全部相等 |

归档独立比较 66 条 pair/property 义务、75 个目标 LP；核验 72 个 LP 下界，另三条
MC 义务使用有来源的区间事实。每臂四请求共有 15 个 pair 基础矩阵，不是每性质重建
并存储一份基础。原有端点机制的收益仍属[此前来源控制](h2_source_controls_20260930.md)，
本轮没有声称格式本身改善松弛或完整覆盖。

小对象上格式元数据可能更大。例如 weighted_sign 端点新包为 23,039 字节，旧紧凑
证明 JSON 为 15,275 字节；tied_partial_reuse 对应 38,503 与 51,294 字节。
**两项体积口径也不同：新包含原始分块源，旧数字不含单独来源声明。** 这里只记录
序列化大小，不能据此计算公平压缩比、真实规模峰值内存或端到端加速。

## 保证边界和下一门

正结论为 `CHECKED_DECLARED_SOURCE_POSITIVE`：对已绑定的声明实数图、输入域及全部
路由／输出义务检查成立。源解析器、精确检查器实现及声明图与原生程序对应仍受信任；
不是原生浮点逐操作 SAFE，也不是生产 HybridZ lowering 差分、外部胜负或真实模型结果。
当前仅有协作式不超过 300 秒截止，未接入独立硬预算监督。

下一步是为新格式建立独立可搬迁检查包，并将完整捕获、分块构造、候选生成、检查、
接收和清理纳入同一硬预算，先通过截止、异常、部分证据、资源上限、完整成本与迟到
正结果拒收控制。随后对原已注册模型重新核对完整源头、单 pair 峰值、成员上限和
所有义务成本；通过容量门后才能另行冻结真实请求。不得提高上限后直接盲跑。

输入 98/4088/4096/4098/4099、旧 holdout、后端搜索和 H1 稠密剪枝保持封存。
不重新训练、选容易样本、修改 25%、接受门或扩大时间。MetaMoE top-1 与其余六篇
工作的语义与外部竞争目标没有被这个 weighted top-2 表示阶段替代。
