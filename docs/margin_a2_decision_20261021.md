## The remaining falsifiable research question

Can a finite collection of global margin-tilted supports amortize verification
work across margin cells, reaching a useful checked bound at less complete cost
than strong fresh supports over those cells? Adding nu*m to an objective is not
a new support algorithm. A positive answer would support a bounded algorithmic
organization claim, not a universally stronger domain or full-network proof.

The [exact transfer derivation](margin_slice_transfer_20261021.md) already gives
a same-query sliced reference that reproduces the current scalar rule. Combining
its duals before residual compensation can improve it. Thus a claim that the
scalar representation is intrinsically tighter has been ruled out for this
particular rule. Do not spend another experiment trying to prove that claim.
The saved transfer run has zero complete-bound gain; do not search its cuts,
certificate pairs or source parameters again.

## Minimum defensible comparison

All arms use one unchanged continuous P, original shared/private factor maps,
full property/constant and common checked gate ranges. Integer-only ranges are
invalid for this comparison. Fix source identities, anchor values, tilt rule,
closed cells, order, per-query/whole-batch caps and effects before execution.

| Arm | Originating query charge and distinct role |
| --- | --- |
| Global zero tilt | Two original anchor supports; same scalar checker |
| Fixed finite tilt | Original zero supports plus the registered finite tilts; no adaptive search |
| Transferred/blended slices | Pays for all originating global supports; exact transfer/recheck charged, no free certificates |
| Fresh slice endpoints | Up to2K supports on K exact closed cells; valid constant/sign-stable reuse allowed and identified |
| N1 | Fresh slice-conditioned d/−d ranges plus product supports; global zero-dual ranges alone are not the strong comparator |
| M3 | Same paid ranges, existing sign/Lipschitz relation rows and product supports; label these as existing capabilities |

Do not call these equal-query arms: endpoint2K and range/product3K counts differ
from the finite global roster. Report bound-versus-charged-cost frontiers and
objective counts. Price all dependencies even when implementation caches them
within a method. Transfer reuse is an explicit reference, not an independent
method that receives the candidate arm's answers for free. Shared experiment
setup and per-arm cold/start assumptions must be reported, not hidden.

For N1, a checked nonnegative d range makes the lower gate endpoint sufficient;
a nonpositive d range selects the upper endpoint. A collapsed gate also reduces
to a linear support. Use valid checked facts without silently redoing skipped
queries. This does not remove M3's relation constraints or establish finite-time
dominance. Combine endpoint and product certificates only when their common
source/domain/property binding is checked.
An endpoint fallback costs another2K supports when those certificates were not
already obtained by that same arm; it is not free on top of a3K product arm.
A post-hoc best-of-arms frontier is descriptive oracle information, not a
deployable portfolio at the cost of its cheapest component.

## Strong LP proposal bridge

The default-off `provider="highs"` option now connects all three existing
producers: global shared-HZ supports, rational closed-slice supports/ranges,
and N1/M3 product LPs. `margin_lp_candidates.columns()` bounds and freezes each
original exact LP before calling the shared SciPy/HiGHS proposal core. The
provider, explicit native query allowance and caller-owned event sink must be
supplied; no production dispatch or default was changed. The existing128-step
candidate remains the default and must not stand in for a strong LP reference.

The opt-in `rowwise_native.propose_duals()` returns only raw marginals and
bounded metadata. It does not call the legacy `_evaluate()` or generic
`rowwise_bound.check_bound()` paths, whose additional Fraction operations lack
this Work/bit contract. The legacy `propose()` API retains those checks.
New-path parsing/conversion uses the same cumulative Work and4096-bit stored
contract; existing metered producers perform8192-bit-limited residual arithmetic,
then the unchanged independent source/slice/product receivers check acceptance.
This reuses the solver capability, not a new optimizer or proof checker.

Original inequality marginals map to y≤0 and equality marginals to free z.
Slice records split the final two marginals into their ordered slab rows.
Product records retain the whole vector and finite lambda/w boxes. Original
LP identities and live HZ snapshots are checked before/after proposal. The raw
API is a low-level interface: its caller must bound/freeze the LP before native
allocation, as `columns()` does. This does not prevent arbitrary concurrent
mutate-and-restore attacks; the existing ordinary-alias contract is unchanged.

HiGHS makes one invocation per objective, not one invocation per batch. The
event sink receives intent before each numerical call and return/status or
exception afterward. Intent means not-yet-confirmed entered; it is not proof of
solver completion. If a later objective fails, earlier status0 events are only
partial numerical proposals, not checked partial certificates. No truncated
roster or unsuccessful-solver zero-dual fallback is returned. The existing
checked zero-dual comparison remains available after successful full proposals
and its selection is reported explicitly.

Only successful status0 with complete finite marginals reaches exact claim
construction; other outcomes retain their status and cannot exclude a cell.
Native status0, objective and unchecked primal values do not certify exact
optimality. The query allowance limits HiGHS's cooperative solve time, not the
whole adapter; import, parsing, conversion, callbacks, hashing and reception all
use the common outer deadline. Native kernel operations are reported separately
from Python Work visits. No new supervisor, environment or backend installation.

This preparation has AST/diff checks and two read-only static AI reviews, not a
runtime test. Static review corrected a legacy stub compatibility issue: the old
given-LP API does not require result status/message fields that its original
stubs never provided. No old control was replayed. Next implement the bounded
A2 comparison driver and freeze its full roster/effect/cost/stop rules; this
adapter's existence does not authorize an unfrozen numerical call.

This is a bounded adapter task in service of a concrete comparison, not a new
supervision or RSS project. Preserve fault evidence, do not repair/rerun the
consumed product roster. The next fresh mechanism execution must include checks
for finite, nonnegative, deadline-consistent reported durations, including the
worker subduration, before accepting its final cost record.

## Decision rules to finish before freezing

1. Fix numerical minimum bound improvement, minimum practical cost reduction,
   neutral region and no-loss conditions in advance. A single small control
   cannot establish a population effect; statistical uncertainty belongs to
   later input-level paired development/confirmation.
2. Separate candidate optimization gap, finite anchor/tilt restriction,
   sigmoid enclosure and scalar-cell aggregation losses. Without a checked
   feasible point, an LP solver primal value is not an exact feasible upper
   bound and a nonpositive dual bound does not prove non-certifiability.
3. If global finite supports give no credible improvement over zero tilt, or
   strong fresh/reference supports attain equal-or-better bounds at no greater
   full cost, stop this candidate on that registered population. Do not change
   the source, cells, tilts, iterations or time to manufacture a win.
4. If only query-count savings occur while exact checking/setup erases them,
   report no practical net benefit. If a charged tradeoff remains, freeze the
   limited new-input complete-request test before claiming G1 progress beyond
   mechanism evidence. All real calls count toward the shared stage ledger.

No effect threshold or executable roster is finalized here, so this is not a
license to launch A2. Its next freeze must fill those values, not choose them
after new outcomes. Real-development ledger remains0 stages/0 calls/0seconds.
G1–G6 remain OPEN; old source gaps, failure records and sealed inputs stand.
