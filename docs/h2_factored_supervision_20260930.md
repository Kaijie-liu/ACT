## 可搬迁检查与接受规则

包将 `proof/`、`code/` 和 `verify.py` 分离。原数学检查器继续要求 proof 子树库存
完整；外层另外绑定所有成员、长度与代码身份。[发布器](../scoped_source/factored_portable.py)
直接包装本请求生成的证明树，不复制全量旧格式 LP。外层逐文件流式核对哈希，不将
全部 JSON 矩阵同时解码。检查前后均核对完整外层库存和身份；这不是文件系统原子快照。

[独立入口](../scoped_source/factored_verify.py)使用 `python -B -I -S`。搬迁控制隐藏原包，
从仓库外运行，得到与核心检查器完全相同的数学结果；不加载模型、checkpoint、数据或
求解器。读取策略拒绝仓库外部读入、包内写入及额外子进程。它是已审阅检查代码的
读取约束，不是抵御任意恶意 Python 的安全沙箱。`factored_source` 同模块含生产函数，
所以准确表述是“不执行生产函数”，而非“不导入任何含生产函数的模块”。

接收层从已绑定来源重建全部 unordered top-2 pairs 与非标签性质。每条端点义务
按不同权重核对数量、缺证据状态和最小下界；MC 的来源区间事实不计作 LP 证书。
阈值保持严格 `>1/10000000`。缺证据为 UNKNOWN，缺义务或非法身份为 ERROR，
负下界不变成 UNSAFE。parent 在 checker 正常退出后锚定实际 stdout，再启动接收；
接收者重写成自洽的正摘要也无法绕过原哈希。

## 预算与成本

时钟从 API 入场开始。模型创建与捕获、来源验证、分块、约束构造、候选提议及保存、
打包、检查器启动和输出、接收、终态落盘与 owned process group 清理全部收费。
不按 pair 重置预算，不将事后数学重检免费算作在线成功。

终态使用 invocation、terminal、receipt、finish 的身份链。单靠留存文件不能证明
外层调用已完成；正执行还要求实际完成的 API 返回观察。最终发布超时控制中，三阶段
均已完成且候选原本为正，但 5 秒预算下实际返回约 7.36 秒，因此最终为 TIMEOUT。
操作系统可能使清理与落盘晚于截止；本入口保证迟到不接受，不保证严格按时返回。

38 次控制的观察成本总计约 76.226 秒，执行阶段约 69.761 秒，余下约 6.465 秒为
parent 与最终发布等开销。这包含故意等待和故障，**不是算法速度实验**。逐操作事件
保留创建、捕获、分块、构造、候选和发布时间；嵌套事件不能简单相加作总成本。

## 保证与下一门

检查的是声明实数图、来源范围与行、全部路由和输出下界。声明图与原生程序的对应、
源解析器及精确检查器实现仍在可信基础内；不是 PyTorch/CUDA 的逐操作浮点证明。
核心的 `hard_budget_supervision=False` 保持不变，完整执行预算由外层观察与审计给出。

新格式仍由完整声明开始，捕获与当前 tensor 的 base64 解码仍全量驻留；候选还会复制
单 pair LP。搬迁与监督通过不等于全上游有界内存，更不等于 bal010 的容量准入。
卷积捕获仍不支持 Conv/Pool，不能借此宣称跨家族能力完成。

下一步仅做独立版本的全路径容量审计：评估已有允许范围内的分块策略，核对来源头、
成员和包体积、单 pair 基矩阵、原生候选适配器及检查器的同时驻留对象。不能因为
64 字节小控制通过就直接冻真实请求，也不能先假定流式捕获是唯一主要成本。元数据
不能确定的精确范围位数、实际稀疏度、内存峰值和 300 秒完成性必须保留为未定。
不扩上限、不换容易模型，不重开输入 98/4088/4096/4098/4099、H1 稠密剪枝或旧后端搜索。
