# Optional request-budget evidence mode: separately frozen development V1

Scope: **one previously observed positive control, convolutional input98**,
same checkpoint/materialized2/255 box, label0, pair{1,2}, all9 properties.
This is postselected engineering development, not new-input confirmation,
not a general claim of production improvement, and not a route-changing proof.
Input16 and the three ACT-only cases are not queried. No retries or extra
queries after this two-call smoke. Old directories/results remain immutable.

Two arms, fixed order: production matched V2, then optional checked evidence.
Both load/verify their own checkpoint and raw tensor identities and compute
routes/common facts afresh. No old HZ, bounds, route census, solution or proof
is read during either request. Existing immutable code is reused through
process-local adapters; on-disk ACT algorithms/configuration remain unchanged.

Each has **one300s wall clock beginning before job publication/worker launch**.
The outer process-group watchdog stops work at298s to reserve terminal writing;
any complete result published after300s becomes TIMEOUT. Startup, identity
checks, loading, propagation, support, exact projections, proposals, local
checks, writes, packaging and final independent checking are all charged.
Offline final audit is separately measured, as for other experiments.

Evidence arm sequence:

1. Capture fresh shared pre-F0 HZ using the original propagation/support recipe.
2. Propose/check the original two order and sixteen difference bounds, then
   eight rational McCormick bounds (or the resulting frozen obligation count).
   No tighter gate, extra grid or new numerical tolerance.
3. Locally check complete aggregation; package its candidate result.
4. Run portable `python -I -S` independently and require complete agreement.

The local precheck is not credited as independent acceptance. All its costs,
plus packaging and final checking, remain in the one budget. Proposal limits
are min(original60s, remaining−80s), with a recheck after durable grant writes.
The80s reserve is an explicit engineering allocation for aggregation/pack/final
checking, not a tuned optimal ratio. If exhausted, preserve incomplete evidence
and return TIMEOUT. The original production status0 acceptance gate remains
unchanged; no scalar dual value is itself a certificate.

Results use separate evidence-level columns: HZ-policy production status vs
`CHECKED_CONDITIONAL` rational evidence. Nonpositive/missing evidence remains
UNKNOWN; late/incomplete checks cannot produce a positive terminal. Upstream
network→HZ/source binding, guards and route exclusions remain trusted.

Success means a faithful same-budget engineering measurement and complete
terminal audit, **not necessarily a positive proof or a speedup**. One fixed
order/input does not establish a statistically stable timing advantage. Freeze
source hashes and this protocol, tests, commit/push, live remote equality and
resource inspection all precede launch. Any ERROR stops, preserving the attempt.
