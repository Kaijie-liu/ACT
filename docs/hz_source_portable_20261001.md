## What is now independently rechecked

Each bundle contains its original declaration, source-to-HybridZ traces, endpoint
evidence, eleven unchanged checker/parser leaves and eight empty package
initializers. The leaves are bound through the frozen R4 report, summary and
implementation inventory, not merely compared to today's working tree. A caller
anchors code, manifest, source and package identities outside the bundle.

The parent captures verified bootstrap bytes and executes those bytes with
`python -B -I -S`. The bootstrap then loads only verified in-memory module bytes;
it does not insert the bundle or repository into `sys.path`. Actual read/import
observations exclude repository code, checkpoints, datasets, numerical libraries
and optimizers. The copied leaves still contain a lazy solver proposer; it is not
invoked. These restrictions concern the fixed trusted checker, not a Python
sandbox for malicious code. External identity selection and checker correctness
remain trusted.

All input containment, affine/ReLU compensation, factor correspondence, route
coverage, gate ranges and output checks in the existing finite checker run again.
Every returned mathematical field matches the prior source archive, including the
inner `portable_distribution=False` field: relocation is a separate outer result,
not a retroactive edit of the earlier mathematical evidence.

## Controls, accounting and retained attempts

Eight groups cover relocation, original checker bytes, external anchors, complete
file inventory, mathematical mutations, import/read isolation, expiry and result
receipt binding. Four rehashed mathematical mutations must fail for the specific
missing-pair, property, factor or inward-input reason; an unrelated import failure
cannot pass those tests. Seven additional child invocations cover these refusals,
cwd/PYTHONPATH shadows, read/import restrictions and expiry. Their logs, process
records, costs and the entire corruption inventory are included in R2's audit.
All five normal and seven auxiliary children have confirmed cleanup.

The normal 30-second clock includes reading the earlier archive, publication,
copying, code/data verification, process startup, mathematical checking, result
receipt, cleanup and final record publication. Source/proposal generation was
performed in the earlier experiment; it is explicitly **not** included in these
offline times. The original full source pipeline has its own
[cost record](hz_source_supervision_20261001.md). Parent filesystem operations
remain cooperative; no guarantee against arbitrary OS stalls is claimed.

R1's eight groups passed, but subsequent read-only review found wrapper/archive
gaps: mutation evidence was not audited, generic ERROR could hide a wrong refusal,
stage receipts were insufficiently strict, leaf identity was not anchored to the
older execution, and bootstrap bytes were reopened after preflight. R1 and its
[pre-hardening report](hz_source_portable_20261001_r1.json) are preserved, not the
accepted portability result. R2 corrects those boundaries and final-publication
deadline handling without changing mathematical leaves, sources, budgets or the
eight-group roster. The batch stops on the first test failure; child stages are
saved before checking their outcome.

The independent archive audit validates saved identities, complete results,
failure reasons and cost/cleanup records. It does **not** rerun the mathematics;
the original isolated children performed that recheck. This is not an independent
human review or a clean-machine reproduction.
