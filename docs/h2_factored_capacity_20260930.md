## 计数及其适用范围

[可重算账本](h2_factored_capacity_20260930_r1.json)绑定训练配方、三个登记模型的
状态摘要、当前格式和执行源码。[审计程序](../scripts/audit_h2_factored_capacity.py)
不导入 ACT、PyTorch、SciPy 或求解器，只解析明确白名单中的源码和 JSON。
文件哈希、AST 调用点与人工源码解释共同支撑这里的实现描述；这不是对 Python
程序语义的静态证明，也没有重新确认 seed 0 checkpoint 的原生拓扑。

配方为 router `3072→128→8`、八个 expert `3072→256→128→10`。
登记参数数目和张量数均与配方一致。全部 28 个 unordered top-2 pair 都保留，
每 pair 有九条输出性质；没有按潜在可达性或结果删义务。

| 元数据可计算项 | 数值 | 含义 |
|---|---:|---|
| 模型参数与参数张量 | 6,961,368／52 | 不含输入中心 |
| 含输入中心的 binary64 字节 | 55,715,520 | 不等于 Python 驻留内存 |
| 最大张量元素数 | 786,432 | 未超过现有 1,000,000 上限 |
| 全部 source node blocks | 9,560 | 配方推导，不是加载后的计数 |
| 单 pair 变量／仿射等式／ReLU | 4,892／924／896 | 每 pair 另有 12 个 guard 行 |
| 全部输出义务／最多端点 LP | 252／504 | gate 退化或复用可能减少提议，但不得漏义务 |
| 单 pair 稠密仿射项场景 | 2,036,124 | 包括等式左端；不是实测 nnz |

若全部 ReLU 均不稳定，单 pair 最多有 2,688 条 ReLU 不等式和 4,480 个相应
非零项，另加 guard。实际稳定性、权重零项和有理数位数未知；不能据此伪造 RAM 估计。

## 两种分块策略不能混称已执行协议

[已冻结合成协议](../configs/h2_factored_supervision_20260930.json)继续使用 64 字节；
worker 显式传入这个值。`pack()` 已有的默认值为 1 MiB，没有为本审计增加上限、
修改旧协议或执行新的真实协议。

| 布局检查 | 64 字节控制策略 | 现有 1 MiB 默认值 |
|---|---:|---:|
| 每张量分别取整后的 chunks | 870,561 | 95 |
| 仅引用的通用 JSON 字节下界 | 108,820,125 | 11,875 |
| 完整 tensor descriptor 列表字节 | 未物化 | 18,045 |
| 外层 portable 成员数 | 未物化 | 9,698 |
| 外层 envelope 字节上界 | 不必计算即可拒绝 source header | 1,136,168 |

125 字节是单条 chunk 引用的通用下界，未加数组逗号或来源声明；因此 64 字节
方案确定超过 4 MiB source header。审计没有为了证明这个结论创建 87 万条引用。

默认方案的 18,045 字节只覆盖 `tensors` 列表，不是完整 source manifest；
node 引用数组也不是完整 proof manifest。外层 envelope 上界包含全部六个字段，
采用当前文件名、代码清单、32 位十六进制 invocation、64 位 hash 和允许的最大
member 大小。它不包含成员正文大小的证明。上述结构检查通过不能改写为全路径 PASS。

当前有效限制仍是 source 总量 256 MiB、单 node/pair member 16 MiB、
source/proof header 和 portable envelope 各 4 MiB、完整包 2 GiB。
包总量包括源码和 envelope，比只检查 proof 树更严格。built/capture receipt
各 1 MiB，checker stdout/accepted 各 8 MiB。统一 API 预算至多 300 秒；
RSS 参数默认 2 GiB，但不是不可修改的全局常量。当前监督器只接收五个固定合成
case，尚未提供任意真实请求准入。本轮没有改变这些限制或接口。

## 完整路径仍有整对象驻留

账本列出 14 个阶段的函数与行号。以下对象在各自阶段可能同时存在，互斥阶段
不能简单相加成峰值；不可变字符串可能共享，也不能机械算两倍系数字节。

| 阶段 | 源码确认的驻留对象 | 尚未测量的部分 |
|---|---|---|
| capture 和验证 | 活模型、全量 base64 来源、当前张量 float/Fraction、整层 affine 字典 | 实际峰值、连续化是否复制 |
| pack 和读取 | 全量声明及当前解码张量；逐 chunk 读后仍累积整张量 Fraction | 分配器保留量 |
| pair 构造和候选 | 全部命名行、CSR 容器、候选 deepcopy、目标；MC 另有增广约束 | 实际行数、位数、候选大小 |
| 原生适配 | `list(rows(...))` 完整精确行校验后再生成浮点 CSR | SciPy/HiGHS 工作区 |
| 独立下界检查 | 每端点 `csr()` 生成完整精确行字典；构造 E 时旧 A 可能尚未释放 | 完整请求累计成本 |
| 身份与发布 | canonical JSON 字符串和 bytes、文件清单、结果摘要 | 实际正文总量、序列化峰值 |

outer envelope 采用流式字节哈希，不代表内部 LP identity 也是流式；分块读取
也不代表常数内存。当前 producer、checker、receiver 分进程执行，需分别考虑
parent 与活动子进程；采样 RSS 不是瞬时峰值的严格上界。

所以本次不能证明单 member、完整 source/proof header、总包、RAM 或完整 300 秒
执行都可通过，也不能承诺只改 capture 就能闭合请求。卷积的 Conv/Pool 捕获仍不支持。

该改动。旧模块和归档执行身份保留；任何真实 freeze 仍需另外的全路径容量准入。

这不是重启 H1 稠密剪枝、缓存计时、输入 98/4088/4096/4098/4099 或旧后端搜索。
