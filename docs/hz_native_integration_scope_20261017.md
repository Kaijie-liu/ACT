# 共享来源原生候选接入与行块对照提案

本提案将下一项实施收敛为一条完整接线和一个表示因素：**同一声明来源、同一精确
检查链，比较原V3全局COO与首层来源行块。** 不另造优化器、不改松弛、不剪pair，
也不再以固定候选stub作为原生对照。当前只有静态设计权限，尚未实施或运行。
基线为`01771307fc19a322a341ff44bc44d5ffecb6b8f1`；
[范围与源码绑定](hz_native_integration_scope_20261017.json)不是执行配置。

## 唯一对照因素

两臂共同使用已检查的`CheckedSharedForest`、相同来源构造、pair-scoped检查宽2、
候选宽8、128次更新／129次界评估、CPU float64及全部两角色候选。原生强参照是
[现有V3 Operator](../act/back_end/moe/scaled_forest_endpoints.py)，不是`FixedProposer`。
新两臂共同获得无字符串的profile0出口、fresh重查及完整监督；这些公共接线成本
不归因于行块算法。dense8与scoped2的检查因素、H2表示和GPU不混入本次对照。

设原算子为`C=(I-R)^(-1)LD`。新臂仅用
`L=E_aux+sum_B S_B W_B P`替换首层`SourceLocal`的全局COO物化。
`W_B`按原自然层一次转码，`S_B`保留node身份，`P`保留同一输入因子。
`E_aux`包含输入单位行、全部其他local项，以及每个首层行的全部误差／lift尾项。
forward先施加`D`、local乘法再传播`R`；adjoint逆序传播`R`后计算local转置，最后施加`D`。
共享输入残差必须合并后才取范数；bias／center仍在目标offset和约束RHS中。
完整推导沿用[既有行块合同](hz_native_source_blocks_20261016.md)，不重复称为新理论。

来源映射须来自[独立来源检查](../scoped_source/check_shared_source.py)，不能凭相同
尺度或数值相等合并因子。原生bank另有私有存储，不向不可变来源字节暴露可写Torch别名。
两种原生乘法的浮点轨迹可以不同；**同一个候选对同一原始来源的精确接受必须相同**。
只有后续完整请求比较能说明净证书或成本收益，命名tensor载荷减少本身不关闭G1。

[共享来源](../scoped_source/shared_archive.py)和

旧worker的“无数值导入”检查。新版本的生产／搬迁／接收清单必须分别绑定真实实现。

best-dual句柄正常返回时只保留当前tile的eq／ine张量及必要身份；不得用yield保留

负零规范为正零，advisory lower保持0；完整显式零角色、同时缺失规则、全部query／slot／
ordinal和两类对偶维度不变。预检原4MiB tile与累计候选流额度后才分配，发布后再检查。

## 来源保证边界

实现范围是当前声明图支持的输出层selected-softmax top-2、共享类别、
CPU float64、eval、Linear／ReLU／Flatten；不增加卷积、BN或多层动态路由语义。
来源不能只取clean pair；完整保守pair目录和每条分类性质均由请求重建。

一般声明来源入口要拒绝未知字段／schema、越界路径、别名、来源／输入／性质身份
替换和不受支持的图。原文件从何处生成、生成成本是否在本请求内须分栏记录。
固定声明控制的生成和读取都计费；未来真实模型的加载、输入物化、capture及归档亦须
从同一`t0`计费，不能免费借用旧来源证明。

[现capture](../scoped_source/capture.py)只记录promoted状态及声明图；`TensorRows`
核对捕获声明，不独立证明训练checkpoint、原预处理或原生程序对应。新接口因此不能
把声明来源正结论升级为G3真实同源证明。实际checkpoint／输入绑定与受限capture仍是
真实执行前的独立义务，本提案不选模型、不读取checkpoint、不重开封存输入。

## 已采纳合同下的监督和成本

[采纳决定](hz_resource_contract_adoption_20261017.md)只解除原生未知开销的静态成功容量
前置。新监督必须在原生导入及来源载入前安装并回读获批硬限制，绑定解释器、实现、
已有环境及线程／后代范围。生产可使用现有act-py312中的Torch；独立重查及接收保持
`python -I -S -B`标准库路径，先由可信bootstrap核验获批代码，不由包内代码自批。

当前直接监督路径只有文件大小限制及采样RSS停止门，没有可直接继承的原生AS硬限制。
仓库[旧dense容量入口](../scripts/run_scaled_dense_capacity.py)曾安装16GiB AS，但它
绑定旧的单次容量／两端点执行及另计预算的搬迁，不是本提案的统一全流程限额授权。
**本提案不指定或启用AS数值，也不把2GiB采样RSS换名为2GiB AS。** 原256MiB待批
方案已不足以覆盖安装库的映射，不能套用。数值、机制、bootstrap、线程／后代和
监督器本身的覆盖范围必须在执行冻结前另行明确；未绑定就拒绝，不先试跑后调值。
逐进程AS不是聚合RSS／显存保证，可信不逃逸假设与实际受强制限制的部分分别列明。

| 阶段 | 必须计入的工作及终态条件 |
| --- | --- |
| BOOTSTRAP／SOURCE | 启动、实现／环境身份、限额安装、声明生成或读取、来源所有权与全部检查 |
| PRODUCE | 来源构造、COO或行块准备、目标与候选、发布、第一遍精确接受及关闭；全流程同Work |
| REPLAY | 前actor退出后新进程重建来源／全部义务，重查两角色、输出页和聚合；不运行优化器 |
| RECEIVE／FINALIZE | 新进程核对角色／来源／方法／计数链、全部页和完整成本；监督清理、尾部文件及调用者观察 |

所有阶段共用`t0+300`及原收尾预留；不重置Work，不把搬迁重查送到预算外。
新source适配、bank转码、句柄／帧复制、原生内核、哈希／序列化、进程启动、同步等待、
接收与清理均收费。墙钟分项不重叠，原生浮点操作、已计Work和观测内存分栏。
生产端完整检查与fresh标准库重查共两遍，另保留结构接收；进程退出而非`gc.collect()`作为原生对象
寿命边界。旧raw strings路径的成本不能作为新出口实测。丢失计数为null／下界，
部分证据、异常、超时、迟到包或清理未确认均不能接受；离线补查不挽救在线失败。

原Work／成员／候选流／位数等限制仍在。行块仅改变原生local表示，**不会消除
来源双遍13,922,736＞8M或现表示126,632＞65,536的拒绝**。因此本提案不能作为
八专家完整形状准入。完整新接线的自有成本应在实现后按实际调用核对，不把旧的
条件化post-capture上界冒充新代码总账，也不生成新配额。

## 有限控制范围建议

以下是待批实施的验收范围，不是已经冻结可执行的实验。最终冻结须绑定具体实现、
环境、硬限额及case身份，任何扩展须先说明原因，不按结果调整。

1. **六个完整原生控制位置。** 沿用既有`mixed`、`clipped`、`guarded`三份声明构造，
   每份分别运行COO／行块两臂。不读取历史正界，重新构造、提议、检查和搬迁。两臂
   均使用相同scoped2接受规则；不要求两种浮点轨迹或最终界逐位一致。
2. **一个组件差分批次，至多32个具名变异。** 覆盖首层全部行及尾项、零宽／异尺度、
   同输入累加、offset／RHS、来源与方法身份、roots失效和别名、eq／ine顺序、
   非有限值／负零／错误符号／伪零角色、缺失／重复／换序义务。精确代数用既有
   有理数展开oracle，同候选检查比较原消费者、scoped2及搬迁结果。非零误差／lift
   必须实际覆盖；既有fixture不足时只使用预先绑定的组件构造，不换真实样本追结果。
3. **至多20个监督故障位置。** 两臂各覆盖来源拒绝、native setup异常、proposal阻塞、
   close异常、候选部分发布、重查数学篡改、接收截止、迟到终态、限制安装／继承失败、
   受管进程清理未确认。真实限制控制与注入故障分别记录；模拟错误不证明OS限制有效。

总上限为26个完整监督请求加一个组件批次；每个预算最多300秒，登记累计请求预算8,100秒，
固定一次资源准入，无自动重试、追加case或调额度。截止控制也沿用原绝对预算；
若实际测试方法／覆盖尚未绑定，不能执行这些位置。这里只评估新接线的正确性，
不将小源性能升级为真实模型或GPU收益。
这不是OS调度、清理及调用者返回的绝对壁钟保证；实际超额完整计费、不截断记录，
迟到或清理未确认不得成功，累计预算耗尽后不得继续准入。

特别区分两类故障：来源／证明绑定或数学证据损坏必须拒绝；**仅污染候选生成器
不一定使候选非法**。它若偶然给出合法对偶，原系数精确检查仍可接受；测试要求
不能信任其自报下界，不是强制拒绝所有不同的候选轨迹。原生算子的映射／转置正确性
由独立代数差分检查，不由“checker最终拒绝了候选”代替。

## 请求的最小后续决策

下一步请求批准上述**默认关闭的单一实施范围**，不是再次批准资源保证方向。
实施与原生CPU控制权限须明确区分；运行前还需批准具体硬限额及冻结完整控制身份。
当前两者都未获批。完整形状／真实模型／GPU另批；在旧静态拒绝仍存在时不启动它们。

若新行块没有准确复现原实数算子，先停该臂；若完整同候选接受不一致，停整个接线；
若控制仅证明接线可用，则只报告工程完成。不能因资源政策放行、局部省内存或更多
控制通过关闭G1–G6。后续有限真实对照必须使用同一新政策和合理强COO参考，以完整
正结果gain／loss及全流程成本判定，不继续累积无关监督或缓存控制。
