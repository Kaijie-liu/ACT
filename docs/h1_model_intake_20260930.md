## 实际交付

[对象入口](../scoped_source/sparse_intake.py)复用 `capture()`，没有重写网络转换器。
新 `H1_CAPTURE_CONTROL_V1` 只允许注册的合成模型工厂，不接受任意 import、pickle、
checkpoint 或数据路径。[监督器](../scoped_source/sparse_supervised.py)仍是同一套三阶段
执行、硬截止、候选接收与外层返回观察规则，最大预算保持 300 秒。

本轮固定模型是三专家、三类别、四维输入，router 和专家均为
Flatten → Linear(4,4) → ReLU → Linear(4,4) → ReLU → Linear(4,3)。
使用 seed 0 的标准 CPU/float64 初始化，分别初始化各网络，不挑选权重或输出正界。
中心为零、半径 1/8、标签 0、margin 1/100、clip 为 [-1,1]。
它是未训练的结构控制，不是 clean-correct 测试集、准确率实验或新模型效果确认。

准备阶段冻结完整源 SHA，计时 worker 重新创建模型、捕获和验证同一源后才生成 LP。
模型创建及导入、捕获、完整语法/参数/输入/性质校验、构造、候选求解、序列化、
隔离检查、接收和最终发布都在同一请求时钟内。准备期选定源身份与后续只读归档单列，
不将其当作预算内完成的证明步骤。正常控制使用 30 秒，捕获截止控制使用 8 秒；
没有改变生产请求预算或接受门。

父进程还固定工厂、捕获器、生成器和模型实现文件的身份。新入口拒绝模块的实例方法
覆盖、执行/序列化 hooks，以及输入、参数、buffer 的 callable 属性；这些对象可能
在保持类名不变的情况下改变 `route`、`state_dict` 或 `detach` 的结果。
旧 `capture.py` 本身未被改写，历史来源也未被追溯升级。

这些防护不是任意 Python 类替换或原生浮点执行的证明。实际保证仍为声明的实数图，
信任图与程序的对应关系、解析器及检查器实现。两个有限点上的分量输出探针通过，
仅是实现一致性控制，不能把它当成全域 PyTorch 等价证明。

## 缺证据能解释到哪里

四个缺候选的位置是 pair {0,1}、{0,2} 的全部分类性质。原候选接口只记录了
`proposal solver did not complete`，没有原生状态码；不能据此称为超时或数值失败。

另行只读检查完整源范围后，可以得到 router 0 的负上界和 router 1、2 的正下界，
因此这两个 pair 各有严格违反合法 guard 的分数顺序。机器归档保留了精确有理数
范围及严格差值。这是基于已检查源范围的域空解释，**不是恢复原求解器退出状态**。
当前 H1 不接受路由排除证书，这些离线事实没有用于补全在线终态。

即便今后加入合法的空域证明，这四项消失也不能使当前请求闭合：pair {1,2} 的两条
检查下界仍为负。下界非正不证明真实模型不安全，也不证明 LP 的最优值一定非正。
不围绕此控制换标签、改范围、改 gate 或追加求解追正例。
