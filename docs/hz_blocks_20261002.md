# Block native support on shared HybridZ expert templates

The [frozen design](hz_block_support_design_20261002.md) is now implemented in an
opt-in source path. Eighteen control groups and the final independent archive
audit pass. All 15 pair domains/objectives agree with freshly materialized joint
HZs. Eighty-four bidirectional transfers of the actual candidates produce exactly
the same residual vectors and lower bounds. All 42 final endpoint bounds also
agree; the four complete declarations retain 3/3, 18/18, 0/6 and 6/6 positive
properties. Missing evidence remains UNKNOWN.

This changes the HybridZ support computation, not its domain or precision. It
does not establish production speedup: three of four tiny requests take longer
overall despite cheaper construction and checking. No real model, native solve,
CUDA execution or sealed request ran. G1–G6 all remain OPEN.

## Algorithm and proof contract

The [block producer](../act/back_end/moe/block_support.py) consumes actual common,
guarded-entry and two expert-template SparseHZonos. It retains entry constraints
in full and the expert constraints after their **common** prefixes. Guard rows
are absent from the templates, so skipping the longer entry prefix would lose
expert constraints. The global factor order remains shared/A-private/B-private
continuous, then the corresponding binary factors. Binary factors are explicitly
relaxed to the same continuous boxes as the reference.

The three local blocks select coordinates of one global vector. For each output
objective, the algorithm accumulates all local transpose products into a single
global residual, takes one box argmin and gathers it back into the three blocks.
All blocks save the same objective's best iteration together. The 128 projected
updates, step rule, exact zero fallback, endpoints and positive threshold are
unchanged. It never assembles the full joint HZ or full global sparse LP matrix.
Global dense residual/objective columns and parsed local matrices still exist.

The [independent checker](../act/back_end/moe/check_block_support.py) derives maps,
row spans and property projections from original snapshots, not candidate-supplied
coefficients. It validates every row, even with zero dual, and computes

    r = c - sum_j S_j^T (A_j^T y_j + E_j^T t_j)
    L = d + sum_j (b_j^T y_j + h_j^T t_j) - sum_i abs(r_i),

with y_j nonpositive and equality multipliers free. The residual's shared
coordinates are added before box support. This is the same weak-duality bound,
not a new tightening theorem. Independent expert argmins would not implement it.

The [source checker](../scoped_source/check_hz_block_source.py) independently checks
input containment, affine/ReLU references and storage enclosures, common entry,
expert-private identities, every conditional guard and gate range. It binds these
states to the four support snapshots and checks all pair/property endpoints.
It reuses mathematical checking leaves, not the old complete-source checker or
template specialization. The guarantee is the finite declared real graph, not
the native PyTorch/CUDA execution or an arbitrary trained model.

## Same source and complete obligations

Both arms recreate the same four declarations, propagate each expert once and
generate fresh candidates. They alternate order by declaration. The materialized
reference already supports multiple objectives; it is not a per-property weakened
baseline. Actual observed construction calls are:

| Quantity over the eight normal executions | Materialized arm | Block arm |
|---|---:|---:|
| Joint HZ constructions | 15 | 0 |
| Global column remap calls | 240 | 0 |
| Full LP export calls | 60 | 0 |
| Old complete source checker calls | 4 | 0 |
| Pair domains retained | 15 | 15 |
| Endpoint obligations checked | 42 | 42 |

Only the diagnostic comparator materializes a global reference. It independently
compares all rows, right-hand sides, boxes, binary relaxation and objectives,
then checks each arm's dual on the other representation. Query IDs and original
LP identities are checked; old candidate records may be validly reordered.
Same-candidate equality is required, not equal floating optimization trajectories.

Two existing given-HZ fixtures separately check shared/private continuous and
binary columns, a nonzero equality dual, min/max and a nonzero property offset.
The shared-input cancellation fixture checks a lower bound of 1/4; its actual
independent-input product checks -3/4 with zero duals. These are given-HZ controls,
not additional source-complete model results. The product's execution-local frame
is checked to be disjoint, then consistently renamed during reconstruction; all
coefficients, source identity and proof records are still compared.

## Cost observations

Final R4 took 3.8593 seconds including imports and test orchestration. Normal arm
intervals include declaration creation, propagation, preparation, proposals,
serialization and independent checking under one cooperative 300-second deadline.
Auxiliary faults, independent diagnostics and test windows are also recorded.
This is not a production hard-budget experiment or a timing confirmation.

Block proposals are slower in every observed tiny control. Omitting joint
construction does not guarantee overall acceleration, and these timings do not
identify a unique cause. Source snapshots and live templates are still repeated
per pair; no global storage deduplication or peak-memory improvement is claimed.
The archive separately counts actual block nonzeros and snapshot storage entries.
No query, source row or original capacity limit was reduced.

## Continue or stop decision

Retain this as an optional representation, not a faster default. Stop optimizing
these four fixtures for better times or more positives. Before another execution
protocol, assess which already-recorded real-capacity obstacles the representation
actually removes and which remain: source row widths, global factors, unsupported
operators, repeated snapshots and portable limits have not been resolved merely
by eliminating joint allocation. This assessment needs no model load or new solve.

Any later full-budget/portable admission must explicitly bind this new source and
block schema; old source supervisors cannot silently accept it. A GPU version of
this block algorithm is a separate factor, not inherited from the existing flat
device kernel. No physical retry, higher cap or sealed-input rerun is admitted by
this result. Real same-source closure and external competition remain unfinished.
