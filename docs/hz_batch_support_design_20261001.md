# HybridZ 多目标支持的候选与检查合同

本阶段从实际 SparseHZono 接口研究同域多目标支持，不改变 HZ 约束、ReLU 编码、
gate 表示或原生产接受门。[有限协议](../configs/hz_batch_support_controls_20261001.json)
先于实现及控制执行冻结。只允许列出的合成 HZ 控制；无 checkpoint、真实输入、
原生 MILP 或 GPU 执行。初版是 CPU 参考及显式禁用的 CUDA 候选路径；不是完整 GPU
监督流程，也不满足完整 MoE／来源／性能验收。环境和依赖保持不变。

## 已存数据支持什么

[已存前缀](h2_capacity_prefix_analysis_20261001_r1.json)显示端点臂 first pair {0,1}
基础矩阵为 4892 变量、1833 不等式、1213 等式、2039610 非零元。
四个已启动目标是 competitor/weight 的 (1,0)、(1,1)、(2,0)、(2,1)，
LP hash 各异，最后一个未完成。同一基础矩阵不代表目标重复或可省去。
这些 gate 端点为 0 和 1，实际退化为各专家性质；批量求解本身不会改善表示精度。

三个完成查询的 native boundary 到 return 总墙钟约 139.21 秒；MC 四个完成查询
约 99.88 秒。包括最后未完成查询中已执行的验证／转换在内，两臂已记录的其他
验证、转换、精确评估与检查区段合计约 66.59／97.92 秒。它们不能与 API 再相加，
不能外推总加速或唯一瓶颈；未完成区段右删失，非零成本。
MC 为每条性质加入两变量、四条性质相关乘积约束，不能混作同矩阵多目标。
共同矩阵判断来自绑定 trace 和执行构造代码，尚未独立重建全尺寸原 LP 系数。
当前两臂仍是 TIMEOUT，零完整 pair／请求；负候选不证明 LP 不可认证或模型不安全。

## 原始因子坐标与义务身份

使用现有 HZ→稀疏 LP 导出及独立导出检查。仅接收规范、无重复、有限 CSR，
避免浮点合并重复项后把它称为原始精确系数。保留连续因子和二元因子的 [-1,1]
坐标，显式将二元松弛为连续区间。不借用生产 MILP 的 [0,1] 重参数化乘子。
每批绑定原始 HZ hash、request/domain/guard 上下文及有序查询清单。
每条查询包含唯一 id、原始输出性质 q、offset 和 min/max 方向。
max 转成负目标的下界，返回上界时仅精确取负；缺一侧不生成完整区间。

相同基础 A/E、RHS 和盒只供候选器共享，目标逐条保留。接收器用调用方预期的
整批 hash 验证清单，独立重建每个 q/offset/方向的导出，检查每条候选的原 LP hash。
只验证 HZ hash 不足以排除自洽篡改目标。底层 checker 的给定 HZ 保证不升级为
网络→HZ 正确性、私有因子来源证明或完整路由覆盖；不从支持批次生成 MoE SAFE。

## 多目标候选算法

对 A z≤b、E z=h、有限盒 l≤z≤u，各目标 c_jᵀz+d_j 共用 A/E。
GPU 或 CPU 候选器在 y_j≤0、t_j 自由的域上优化弱对偶函数：

    r_j = c_j - Aᵀy_j - Eᵀt_j
    L_j = d_j + bᵀy_j + hᵀt_j + sum_i min(r_ij*l_i, r_ij*u_i).

初值全零，128 次投影次梯度更新，步长 0.125/sqrt(iteration+1)。有限控制前固定，
不为结果调参。用同一稀疏矩阵乘多列，不构造重复块对角矩阵，也不合并私有变量。
保留各列最佳候选；这只是浮点搜索策略，不是可靠下界接受规则。
CPU 原始精确系数上的残差补偿与独立检查才决定可用下界；初值候选作为可检查
基线保留。检查失败、非有限或过期结果均无接收凭据。

使用 [PyTorch sparse.mm](https://docs.pytorch.org/docs/2.9/generated/torch.sparse.mm.html)
的二维 COO×稠密多列操作，不假设低精度 Tensor Core 自动获益。
CPU/GPU 候选可不同，但同一候选的精确结论必须一致。
本协议 cuda_execution_authorized=false，不初始化 CUDA、不把跳过记作 GPU 通过。

## 固定控制与下一门

小 HZ 使用两个相反 guard 固定 x=0，查询 x+1/4 与 -x+1/4，检查两侧；
负控制查询 x-1/4，不能报正。等式耦合 x=y 检验 x-y+1/4；
私有二元因子保留并松弛，不能错误变成共享变量。常数 q=0 检查零目标。
批量／逐条／换序比较绑定同一义务，检查合法结论，不要求浮点轨迹逐 bit 相同。
负控制包括目标/方向/域/source 替换、缺义务、重复 id、篡改 dual/claim、
非有限矩阵/候选、维度错误、过期、执行异常及未经准入的 CUDA。

每次调用的合作式 deadline 至多 300 秒，含导出、候选与检查，不另给每目标新预算。
这尚不是硬截止监督，也不保证不透明调用及时返回；统一外层监督是下一独立门。
部分证据保留为部分支持，不升级批次完整，不默认零耗时。小控制耗时不作性能结论。
资源规模限于配置，不允许运行大 H2 LP。

若控制失败，保留首轮结果与执行版本；可修复实现错误，但不改公式、样例、阈值
或迭代数追正。控制通过仅支持下一步硬监督，不自动允许真实／GPU 实验。
