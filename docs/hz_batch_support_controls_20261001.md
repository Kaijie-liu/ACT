# 实际 HybridZ 多目标支持：CPU 有限控制

2026-10-01；先冻结 `12278c5aa` 的[协议](hz_batch_support_design_20261001.md)，
再实现和执行。[R2 紧凑审计](hz_batch_support_controls_20261001_r2.json)
记录 16/16 控制通过，另外 15/15 原精确检查核回归通过。
这是实际 `SparseHZono` 的显式启用支持接口，不只是调度脚本；但不是新的通用 HZ
抽象域、生产传播的默认后端、完整 MoE 证明或 GPU 成绩。G1/G2 仍未通过。

## 实现与保证

- [支持接口](../act/back_end/moe/batched_support.py)接受一个带 guard 的 HZ 与有序
  多性质、min/max 查询。保留连续及私有二元列；二元因子显式松弛到 [-1,1]。
- 同一 A/E 用 COO 稀疏矩阵乘多列，128 次固定投影次梯度更新，逐列保留浮点最佳
  候选。与全零候选作精确比较后送检；没有调用原生 LP/MILP，也没有逐目标刷新预算。
- [独立接收器](../act/back_end/moe/check_batched_support.py)绑定调用方的整批 hash，
  逐目标重建 HZ→LP 的对应关系，并用已有 Fraction 残差补偿核重新检查。
  max 的性质和偏移均反号，返回上界仅精确取负，不经过最近浮点舍入。
- 缺失或重复义务不接受整批；给定 HZ 的非正下界不判 UNSAFE。只返回
  `CHECKED_GIVEN_HZ_CONTINUOUS_RELAXATION`，不产生 MoE SAFE。

为何候选不必最优：对于可行 z，y≤0 给出 yᵀAz≥yᵀb，等式给出 tᵀEz=tᵀh。
把 c=Aᵀy+Eᵀt+r 代回目标，再对每个有界残差项取盒最小值，得到合法下界。
接收器使用原始存储系数的精确二进制有理数，而不是信任 Torch 的目标值或收敛标志。
次梯度为 b−Az* 与 h−Ez*；投影保持 y≤0。这个弱对偶规则本身不是新理论。

网络→HZ、guard lowering、因子来源及调用方 request/domain/guard 语义仍受信任。
支持域可能是连续外包络；本阶段没有证明二元可行性、路由覆盖或原生浮点执行。
即使 frame_id 相同，也不能据此合并两个专家的私有因子。

## 已观察结果

| 固定控制 | 精确检查结果（小数仅为展示） | 解释 |
|---|---|---|
| x≤0、−x≤0；±x+1/4 的两侧 | [0.2496184192, 0.2503815808] | 包含真实 1/4；四个目标分别检查 |
| 同 guard，x−1/4 | 下界 −0.2503815808 | 保留非正结果，不宣称不安全 |
| 等式 x=y，x−y+1/4 | 下界 0.2499999418 | 共享等式关系参与下界 |
| 两个不同私有二元列的差 | [−2,2] | 没有错误合并成同一变量 |
| q=0、offset=1/4 | 两侧均为 1/4 | 常数与 max 偏移正确 |
| 4 条义务只给 3 条候选 | 拒绝；required=4、received=3 | 部分证据保留，不减少分母 |

给定 guard 例的全零候选下界为 −3/4，优化候选变正，说明实现确实使用了约束。
这不是相对强 HiGHS 基线的新证书收益；解析控制原本就很容易，也不是公平性能比较。
批量／单条／换序对齐 LP hash 和检查结果，允许浮点候选轨迹不同。

控制还覆盖自洽修改来源／q／offset／方向／request／domain／guard 后重算内部 hash，
仍被调用方原 hash 拒绝；错误系数、非规范 CSR、dual 符号、过高 claim、非有限数、
维度错误、别名污染、候选异常、过期及有效结果在最终接收前过期均不接受。
进程默认设备设为 meta 时仍明确使用 CPU；CUDA 请求在初始化前拒绝。
这个拒绝测试不是 GPU 算法已通过测试。

## 成本、限制与下一门

接口记录 preparation/proposal/checking 及其总时间；检查测试记录全部终态。
这些毫秒级小控制不是 GPU 加速或真实请求端到端成本；导入、模型传播、外层监督、
证据序列化、接收和清理还没有组成一条统一硬预算路径。
合作式 deadline 不保证不透明调用及时返回。既有 exporter/checker 仍会复制或
重建约束，不能因候选张量共享就宣称整个检查流程只解析一次。

下一步先单独接入硬预算监督，验证截止、候选异常、部分证据、晚到拒绝、原生回退
合同与完整计费；仍使用合成控制，不自动启动真实输入或重跑全尺寸容量。
随后冻结同算法 CPU/GPU 候选控制与资源门，获得不干扰其他用户的准入后才执行。
GPU 当前仍有其他工作负载，未分配 GPU、未装依赖、未启动训练。
生产 guarded 支持／传播接入与原强后端消融是之后的独立门；H2 表示改进不混入。

本阶段新增三个本地控制归档约 808 KiB，未删除文件；继续以 `-B` 避免字节码缓存。
