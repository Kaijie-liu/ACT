# H1 按性质构造来源证明的合成控制

2026-09-30：首版实现与合成控制完成，**尚未接入外层硬预算监督或真实请求**。
本阶段检验是否能从同一声明网络产生可检查的完整输出证据，且不先复制逐层完整 HZ。
不更新历史主表，不宣称超过外部工具，不解封旧输入。

[机器记录](h1_sparse_controls_20260930_r1.json)保存五个确定性合成案例、两种构造模式、
逐义务精确下界、构造计数、进程内观测时间、11 个源码绑定和测试历史。
这不是新样本确认实验，也不是与旧 HZ 表示的性能消融。

## 实现与独立检查范围

- [语法索引](../scoped_source/sparse_ir.py)沿用已声明的 Linear/ReLU/Flatten、
  eval、binary64 存储参数及精确输入盒合同；按源图赋予变量身份。
- [生成器](../scoped_source/sparse_build.py)在输出性质中做一次精确仿射代入，
  追踪所需变量与范围依赖；每个来源约束块只保存一次，各义务引用它。
  共享输入身份保留，专家内部变量各自独立，仍然覆盖全部 unordered top-2 pair。
- [独立检查器](../scoped_source/sparse_check.py)不调用生成器或求解器。
  它重新核对源范围、仿射等式、稳定/不稳定 ReLU、guard、性质投影、四条
  McCormick 约束和带精确残差修正的对偶下界，再聚合全部 pair×competitor。
- 可选复用仅接受本次源图独立推导的正区间事实；它们在整个输入盒成立，因而也在
  pair 域成立。它不是导入旧 Tier 1 或旧 HZ 的正界，也不是完整生产版 scoped reuse。

这里采用**连续 ReLU 三角形外包络和 gate 范围 [0,1]**。既有来源路径已经有稀疏
等式提升和标量 F0；本实现不把它们重新称为创新，也不把新三角形 LP 当作旧二元 HZ
的等价性能替换。两臂都使用同一新约束体系：

| 模式 | 实际构造 |
|---|---|
| dependency | 当前性质、guard 及范围证明所需的来源依赖闭包 |
| full | router 与当前 pair 两个专家的全量来源块；不包含无关专家 |

输入/参数的完整语法和身份校验仍执行；减少来源约束构造不等于省去模型读取。
省去的是可证明无须使用的约束/变量；不会省去路由或输出性质。

## 为什么足以推出声明语义上的输出性质

对盒中任一实数输入，用源图的实际节点值给变量赋值。输入界成立；仿射等式精确；
逐层区间归纳与 ReLU 三角形约束包含实际激活。因此每个保留来源块对实际执行成立。
删除来源约束只能放松该外包络，不能从中推出更强的假保证。

若某 pair 在该输入上 tie-legal，其所有非严格 guard 成立。
selected-softmax 的实际权重 λ 属于 [0,1]。令 d 为两专家性质差值、w=λd，
它满足由已检查范围构造的四条 McCormick 约束。于是完整输出 margin 是该 LP
目标的一个可行取值。经精确对偶/残差检查的下界大于 1e-7，足以推出这条 margin 为正。
若复用两个专家的区间正事实，凸组合至少为二者下界的最小值。

最后，检查器独立重建全部 pair 与全部分类 competitor 的清单；任一缺失/非正义务
均不能得到完整正结论。不做路由不可行性排除，因而无需信任外部路由排除结论。

这项论证与实现仍信任声明图与实际程序的对应关系、源 tensor 解析及检查器执行。
它不是 PyTorch/CUDA 浮点执行证明，也不是 Lean 等证明助理中的机器定理。

## 合成结果

每个案例有 3 个专家、3 个类别、3 个 unordered pair，共 6 条输出性质。
两臂都实际提出并检查 6 个输出 LP 下界；没有用输入 98 或其他真实请求。
下表计数按完整合成请求汇总。

| 案例 | 正义务 dependency/full | 来源块 dependency/full | LP 行 dependency/full |
|---|---:|---:|---:|
| 稀疏 ReLU | 6/6 与 6/6 | 7/33 | 84/234 |
| 稠密输出依赖 | 6/6 与 6/6 | 21/33 | 180/234 |
| 必须使用关系的案例 | 6/6 与 6/6 | 5/33 | 60/226 |
| 全并列常值案例 | 6/6 与 6/6 | 0/33 | 36/234 |
| 负控制 | 0/6 与 0/6 | 7/33 | 84/234 |

五个案例的两臂逐义务检查下界一致。负控制返回 `UNKNOWN_NONPOSITIVE`，
没有将负松弛下界标为完整模型 UNSAFE。全并列常值案例的目标无需任何源变量，
所以来源约束块可以为空，但三个 pair 及六条性质仍完整检查。

关系案例的专家 0 margin 为 ReLU(x)−x+3/4，其区间计算下界在扣除注册 margin 后
为 −0.26；另外两个专家的 margin 为 3/4。保留同一输入关系后，最小检查下界约
0.0733333，全部义务闭合。删除来源关系行的单独控制返回未决；仅允许区间事实复用时，
它不会把专家 0 的非正区间下界误当作成功。混合复用控制有 1 条复用、5 条 LP 义务。

router 为 (x,−x,0)，在 −1 和 1 分别有唯一合法 pair {1,2}、{0,2}。
该合成点的路由计算使用精确有理数，并在单独控制中检查。
主 LP 检查器没有把这项外部控制冒充为其自身检查的 route-flip witness；返回字段继续
明确 `route_change_witness_checked=false`。

**稠密控制是重要限制。** 21 个输入/隐藏节点全部位于义务依赖并集中；其余 12 个为
一次仿射代入后的 router/专家终点。它没有表明真实稠密网络可以大幅裁掉隐藏计算。
当前节省混合了终点代入、无关神经元省略与单个 pair/性质的依赖范围，不能归因成
普遍的“HZ 算法加速”。

报告中的时间只覆盖进程内生成、候选求解、证明 JSON 序列化及检查；不含导入和合成源
创建，方法执行顺序固定，也没有外层 watchdog。**这些时间不是端到端竞争成绩，
不计算或宣传加速倍数。**

## 控制和失败记录

H1 的 21 项测试通过，另有既有来源测试 35 项、导航/闭合/审阅测试 34 项通过，共 90 项。
新测试覆盖维度变化、全 tie、稳定/不稳定 ReLU、部分事实复用、来源/域/性质绑定、
缺失/重复义务、因子别名、伪造范围、依赖环、旧 LP 证书、对偶符号与非零残差、
候选异常、缺失证据和协作式截止后拒收。独立只读 AI 审查补充了 guard-only 输入依赖
与真正需要关系的正控制；它不替代人类技术审阅。

初次 17 项测试有 1 项失败：通过 ACT 包导入 LP checker 触发了 torch 依赖，
`python -I -S` 无法运行。改为标准库精确核验核心后，移动证据 JSON 的检查通过。
**当前仍从仓库加载检查器代码，不能称为已搬迁的自包含检查包。**
早期开发中的全量控制还包含无关专家，最终已改为 pair-local，并加测试禁止该退化；
早期计数/时间不进入本表。失败及调整原因保存在机器记录，不覆盖任何历史实验。

## 继续或停止判断

可以继续到**合成完整流程的统一硬预算控制**：已有同源的完整输出正证据和关系负控制，
不是只有源码 hash 或局部界。下一步须完整计入启动、读取、生成、候选、序列化、检查与
终态提交，验证异常、内存限制、部分证据和迟到结果；不能把协作式时钟当作硬监督。

尚不允许据此冻结真实比较。还需处理完整检查包搬迁和上游适配，并确认节省不是仅来自
合成图中明显的无用节点。若 dense 完整义务依赖近乎全图、预算内仍无输出证据，
应保留负结果并停止该因素，不能用新缓存微基准延长这条线。
旧生产入口、接受门、300 秒预算及所有封存输入保持不变。
