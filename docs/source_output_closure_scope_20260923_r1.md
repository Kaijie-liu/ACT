# Same-object source/output closure — finite protocol, NOT an execution freeze

This line is separate from the MetaMoE native-budget study. It does not repair
or relabel the historical 23 gains. The input containment failures in
`main_table_source_applicability_20260921.md` remain findings. Input98 is sealed.
No model, propagation, solver or new bound is run to prepare this protocol.

## One object, selected without a certificate predicate

Use **seed0, rank0 (CIFAR10 index4088, label7)** of the already archived
`schedule_confirmation_100_selection_r1.json`. The rule is first model key and
first manifest rank, not a gain, route count or positive-bound filter. This is
an observed engineering object, not a new holdout and not a high-accuracy model.
Bind its stored center and frozen checkpoint; do not import its old endpoints,
candidate exclusions, HZs, facts, matrices or positive certificates as evidence.
The machine protocol records SHA-256 identities and all 252 output obligations.

The new requested set is defined **in rational arithmetic** by the exact binary
value of each saved float64 center coordinate, radius `2/255`, clipped to [0,1].
This is an explicit corrected-source object, NOT a claim of equality with the
old rounded endpoint/HZ object. Classification requires all nine margins for
label7, with the exact binary64 value of the original `1e-7` margin. Stored
weights/biases denote exact binary rationals in an eval real-arithmetic graph.
Neither raw-pixel preprocessing nor native floating-point execution is proved.

## Required chain and explicit stopping points

1. **Identity/graph.** Load only the bound weights and stored center, extract
   the full router and eight expert graphs, bind every coefficient, operator,
   order, shape and factor map. Finite probe agreement is insufficient. Verify
   the supported Linear/ReLU/Flatten operator rules against the declared graph;
   any other operator or unresolved dispatch/source mapping stops the attempt.
   A declared-graph proof still trusts that the declared extraction represents
   the intended program unless that correspondence is separately checked.
2. **Input inclusion.** Independently check every rational requested endpoint
   against the new HZ enclosure. No small-radius deletion. If floating nominal
   matrices are used as proposals, add and check rational residual compensation;
   equality-linked affine factors must preserve dependencies. Reject any missing
   coordinate, inward rounding or factor identity mismatch.
3. **Router, guards and experts.** Continue through ALL layers using checked
   affine/ReLU rules and shared input factors; private expert factors must not
   alias. For pair {i,j}, retain the exact checked inequalities `r_i>=r_k` and
   `r_j>=r_k` for all k outside the pair. No relative ordering between i and j
   is required. Bound router coefficients used in the guards to the same source
   derivation; hashing old guard rows is not a proof of their construction.
4. **Coverage.** Enumerate **all 28 unordered pairs** of eight experts, including
   ties. This finite protocol uses no feasibility-based pair deletion, so it
   does not rely on historical route-exclusion proofs. Every pair has nine
   output obligations (252 total). Empty or unresolved guards cannot silently
   delete obligations. A checked lower bound on an empty outer domain is only
   vacuous coverage of that branch, not evidence that it is reachable.
5. **Output.** Construct new rational property projections and McCormick LPs
   directly from the new shared factors. Use the universally valid selected-
   softmax range [0,1]; no sigmoid-range search. Derive/check difference bounds
   from these same matrices. Relaxing binary factors is explicit and outward.
   Keep every necessary LP and exact dual residual correction. No historical
   reuse facts, old LP duals or newly selected rows. Certificate candidates may
   be numerical; acceptance is by exact rational checking, not solver status.
6. **Aggregation.** Check every (pair, competing class) identity, lower-bound
   source, source derivation, and manifest inventory. Only complete, strictly
   positive bounds on `E_y-E_k-margin` for all252 obligations support the stated
   real-graph request conclusion. Missing, timed-out or nonpositive evidence
   means NOT_CLOSED. A nonpositive lower bound is not an UNSAFE witness and does
   not establish that this LP or original network cannot be certified.

All28 coverage is deliberately an upper set, not an exact reachability census.
Do not label a successful request **route-changing** merely because this roster
contains many pairs. That label additionally needs two independently checked
legal-route witnesses for the same source and domain; this protocol adds no
witness search. It may close an output proof without establishing that label.

## One budget; no success hunting

The eventual attempt is capped at 300 seconds end to end, two CPU threads and
sampled own-group RSS8GiB. Loading, graph extraction, source checking, propagation,
range evidence, LP construction/proposal, rational checking, serialization and
terminal publication all consume that same budget. Administrative final audit
cost is reported separately and must not manufacture missing execution evidence.
No free old prefix generation, uncharged support solving or precomputed matrices.

First implement/check the generic graph-to-shared-source/guard adapter. Existing
`source_enclosure_v1` and `full_source_v1` supply useful rules, but their old
conv-prefix and pair-specific contracts do NOT already implement this complete
request. This protocol therefore does **not** authorize a model run or assert
that the new adapter exists. Before a later execution freeze, require controls
for inclusion, layer omission, affine error, ReLU/factor joins, tie coverage,
wrong guard/parameter binding, missing property and late/partial certificates.

If admission, an unsupported operator, resource limit, nonpositive evidence or
incomplete checking blocks closure, preserve that terminal and stop this object.
No extra samples, time, pair/row selection, tighter gates or input98 reopening.
The only follow-up is a saved-evidence assessment of whether a specific defect
or mathematical limitation was actually identified. Do not launch a search for
an easy positive example.

## Guarantee labels

Keep separate: requested-input inclusion; declared router/expert graph lowering;
guard/route coverage; rational LP/McCormick checking; whole-request aggregation;
and deployed floating-point semantics. Report each checked/trusted/unclosed
component explicitly. A successful LP audit cannot erase an unchecked upstream
component. This is a finite plan to connect those components on ONE new object,
not an existing source-complete certificate or a replacement for human review.
