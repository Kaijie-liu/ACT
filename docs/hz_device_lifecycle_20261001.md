## 接入与保证

[新协调器](../scripts/hz_device_lifecycle.py)与[薄 worker](../scripts/hz_device_lifecycle_worker.py)
直接组合原 fixture、批量准备、设备可选候选算法和独立精确检查器。
不复制数学实现，不替换旧 worker 全局变量，不改变旧生产入口。
每个子进程使用已有的 bounded owned-process 原语，阶段包含：

    准入 → 创建/CPU 候选 → 清理后归还观察 → 精确检查 → 接收

计算失败也执行归还记账；进程清理未确认则立即停止后续启动。
实际无存活进程组、有效 PID、已回收 returncode 对失败阶段也必须一致，不能只信
`cleanup_status` 字符串。父端锚定请求、源码、绝对阶段截止、输入/输出文件和失败前缀。

归还与下次准入分开：两次模拟观察均不含本次 PID，只支持“观察到本 PID 不在清单”；
其他租户存在时，这可以成立而设备仍不可准入。0.05 秒间隔的归还观察不满足旧准入
的 0.2 秒双观察规则，因此 `next_admission_established` 始终为 false；最后快照
满足阈值也不等于允许下一次启动。真实准入仍须另行执行。

CPU 正常路径明确标注无需 CUDA 归还。全部设备清单情景都是 simulated；没有查询或
发信号给模拟 PID。进程原语只保证 leader 回收与无存活组成员，不覆盖逃逸 session、
全部孤儿 zombie、不可中断内核操作或完整 GPU driver 正确性。未来物理 CUDA 的最小
合同还须限定只有受监管 producer 使用设备，不能把组清理推成任意后代的资源证明。

## 固定结果

| 终态 | 次数 | 解释 |
|---|---:|---|
| 给定 HZ 的 CPU 支持执行完成 | 5 | 四个原正常来源，加一例模拟新租户到来 |
| ERROR | 1 | producer 异常，仍完成 CPU 归还记账 |
| TIMEOUT | 1 | 读回卡住，有限清理后完成归还记账 |
| DEVICE_RELEASE_UNCONFIRMED | 4 | PID 仍在、观察异常、观察超时、跨请求记录 |
| CLEANUP_INCOMPLETE | 1 | 明确的未确认模拟；实际进程清理记录保留 |

四次正常总耗时约 2.986、2.776、2.831、3.025 秒，仅是冷启动小控制成本，不是性能
比较。八条正常界与旧结果一致；模拟新租户的成功调用另重检四条重复义务，共十二条。
“支持执行完成”不要求下界为正，不等于 MoE SAFE。全部十二调用的分母保留。

一个时钟覆盖导入、构造、准备、候选、读回、独立检查、序列化、父端哈希、清理、
归还、终态发布和观察到的 API 返回。候选分项是嵌套成本，不重复加总；接受时核查
其总数不超过 producer 墙钟并保留原 cost_scope。归还失败的成本不能记为零。
未观察返回时钟的离线审计不授予预算内接受；离线精确重检不补成在线成功。
文件系统操作并非硬实时可中断，晚到的最终返回必须被拒绝。

R1 及当时通过的测试/源码完整保留，不覆盖。只读复审后 R2 加固了：指定故障实际
到达、失败 producer 的清理一致性、原数值依赖锁定、候选成本范围/嵌套、缺失与污染
证据，以及“快照符合阈值”不等于准入。测试不得跳过或用 expectedFailure 获得通过。
没有修改对象、查询、128 次候选迭代、精确公式或冻结预算。
