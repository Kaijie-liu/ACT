# Exact parsed-source reuse: one-factor controls and finite saved-check study

Motivation: the valid source-cost diagnosis found60/24 and30/15 pair-check
unpack sites/distinct source identities. These are counts, not parsing time or
achievable speedups. Source checks were the largest of construction/checking/
publication phases, but no single checker component dominated. Do not infer
real4099's bottleneck or change encoder/relaxation/model/thresholds.

## Optional mechanism, no new proof claim

Reuse only `source_enclosure.format.unpack` results in the four pair-chain
checks: join, guards, property projection and output LP construction. The
checker functions retain IDENTICAL bytecode through private globals clones;
no global monkey patch and no acceptance predicate is skipped. Router and
per-network checks remain unchanged. No proof verdict, guard fact, bound or
previous request's result is cached. Existing production defaults untouched.

Every lookup binds complete current finite JSON content, including all source
coefficients, constraints, frame and factor IDs, to an explicit request/source
hash and invocation. A hash hit also requires identical canonical bytes.
Snapshot then parse that snapshot; never use an object address as authority.
This API accepts serialized JSON source objects, not arbitrary Python objects.
It does not promise concurrent mutation safety; each parser has one owner.

Internally store immutable tagged tuples and integer numerator/denominator
pairs. Return fresh containers AND fresh Fraction objects: even Fraction's
private slots must not offer an alias into retained parsed state. Keep limits
64 entries/64MiB payload/2,000,000 cells with eviction/oversized nonretention.
These bound retained payload/cells, not whole process RSS or temporary snapshot
memory; the existing sampled8GiB outer gate is still required.

Measure snapshot/serialization, identity/lookup, original exact parsing,
immutable freeze, defensive copy and retention separately. Full checker time
also includes every remaining predicate and telemetry publication. Keep all
overhead, including regression overhead versus the direct parser. Do not
interpret fewer parses as faster checking. Reject contaminated identities,
malformed CSR, wrong scopes, altered properties and missing duties on hits too.

## Controls before timing freeze

Direct-parser differential on fresh/tied/multipair/changed-dimensional/zero
synthetic objects; mutable source/container/Fraction aliases; simulated hash
collision and cross-scope entry transplant; invalid CSR/factors/exact flag;
eviction/oversized nonretention; inherited cutoff on hits and snapshots; same
guard/LP/mapping/property rejection with a warm cache; original bytecode and
module globals unchanged; fresh relocated python-S check without solver or
producer; failure statistics and cache lifetime.

Bind the optional path to the existing hard-budget supervisor with a new
worker and a separately watched receiver. Test actual cutoff, partial stats,
exception, bad saved source/result, missing receipt, receiver failure/cutoff,
resource termination, late terminal and full cost mutations. Successful source
checking is explicitly NOT a complete positive output certificate.

## Finite timing design, only after controls/commit/freeze

Use ONLY the two already-saved, hash-bound synthetic constructions from
`source_cost_supervised_20260925_r1`:small(E4/C3/w4/d1) and medium(E8/C10/w8/d2),
seed724. No source regeneration/propagation/proposal, dataset, checkpoint,
native solve, real request, extra fixture, or reopening of a sealed experiment.
This is a new saved-evidence check comparison; old results are untouched.

For each saved object, three repetitions of off/on in rotated order:off-on,
on-off,off-on. Exactly12 calls. Each call independently loads and binds saved
source+construction, executes all original source checks, publishes stats and
result, and runs the receiver under ONE300s budget with2s finalization reserve,
sampled8GiB and2 CPU threads. Existing act-py312, no GPU or installs. Never
share cache state across arms/repetitions. The saved certificate retains its
historical internal token; the parse cache uses the NEW supervised invocation.

The off arm uses the original unpack directly, with the same lightweight call
instrumentation; it does not pay invented snapshot/freeze work. The on arm
pays its own binding/snapshot/parse/freeze/copy cost. Both must reproduce the
full previously independently checked result exactly. Not an external-tool
comparison and not a full online MoE experiment.

Record loaded file sizes, whole call/caller wall, checker and input-read time,
cache counts/cost/retention, sampled RSS, all terminal states and failures.
All work/receipt/cleanup/publication is charged; enclosing return includes the
terminal write and hash. Later independent saved audit is separately costed.
Incomplete stats stay absent/censored, never zero or a valid timing sample.
Partial files stay preserved and cannot be accepted after a timeout.

## Predeclared interpretation and stop rule

Report medians/ranges of all3 repeats per object/mode, paired differences and
whole-call cost, with actual source/check equality. Preserve every outcome.
Lower parse count is a mechanism result only. Claim local speedup only if
complete checker costs improve; do not hide identity/freeze/copy costs or use
tiny timing differences as statistical generalization. No repeat until a
favorable timing, cache-size search, larger source, or end-to-end upgrade.

If protection/copy overhead consumes the saved parsing work, keep this version
opt-in/nondefault and STOP rather than weaken checks or relax alias safety.
Any subsequent representation/API change needs a separately scoped design and
controls. This stage cannot create a new output lower bound/certificate or
resolve historical23 input-source gaps. ISSTA competitiveness still depends on
complete same-object proof evidence and fair comparisons, not cache novelty.
