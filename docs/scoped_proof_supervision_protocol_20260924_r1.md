## Five supervised phases, no uncharged proof prefix

1. **Intake:** check all frozen source/environment/asset identities; load the
   checkpoint and center, instantiate float64 BEFORE strict state loading,
   extract and bind all declared router/expert coefficients and graph, serialize.
2. **Construct:** outward input enclosure, exact affine/ReLU factors, router-
   expert joins, conditional guards and fresh complete output LPs, serialize.
3. **Source check:** new `python -S` process, independent full source/guard/LP
   construction check. No torch, NumPy, SciPy, ACT initialization or solver.
4. **Propose:** one HiGHS LP call per lexicographic pair/class, no retries or
   tuning. Reconstruct each LP from this run; finite signed dual candidates
   are saved separately even if the native solver did not claim optimality.
   Missing/nonfinite native duals produce NO_CANDIDATE, never a positive result.
5. **Aggregate:** fresh `python -S` process rechecks the entire new source and
   all LP constructions, independently rematerializes each LP, checks every
   dual with exact rational residual correction, verifies all252 identities,
   serializes full evidence and a small candidate terminal. Partial evidence
   is checked/reported but cannot substitute for missing obligations.

Untrusted candidate context binds invocation, request, declared source,
construction bundle, pair, label, competitor, index and exact LP identity.
No producer LP materializer is used by the final checker. For `Ax<=b`, `Ex=h`,
finite `l<=x<=u`, candidate `y<=0` and free `z`, the checked bound is
`offset+b*y+h*z+sum(min(r_j*l_j,r_j*u_j))`, `r=c-A^T*y-E^T*z`.
Neither primal objective, solver status nor numerical success is proof.
Relaxed binary factors and McCormick remain outer approximations. Negative
checked lower bounds establish neither model unsafety nor LP uncertifiability.

This is a **new opt-in exact-certificate contract**, not removal of the old
production optimal-status/tolerance gate. All252 strictly positive bounds,
complete timely proposal publication and full successful checking are required
for `CHECKED_DECLARED_REAL_GRAPH_REQUEST`. Otherwise NOT_CLOSED, TIMEOUT,
RESOURCE_LIMIT or ERROR; no automatic UNSAFE from a bound.

## Budget, resources and publication

Exactly300s per entire request, two CPU threads, sampled own-parent plus owned-
group RSS ceiling8GiB; CPU only. Admission waits and later administrative audit
are separate, not hidden proof work. Model/source/hash checking is performed
inside timed intake even though freeze preparation previously checked files.

The supervisor owns each fresh worker process group and kills only that group
on its absolute deadline/resource breach. Orphan descendants after leader exit
are killed and treated as ERROR. Sampling is not an instantaneous memory bound.
Reserve2s INSIDE300s for terminal receipt/publication. Before proposal, half of
the actual remaining work time is made available to proposals; the rest remains
for the final exact check. Each native call receives remaining proposal time
divided by still-unattempted rows. This is a fixed first execution policy, not
a tuned optimal fraction. No new300s budget per row or phase.

On a proposal-stage timeout/error, the remaining request time can check the
saved prefix. A failed/late proposal process cannot yield a complete positive
verdict even if some files say positive. On other stage failure, execution stops.
No resume, restart, increased time, gate tightening or sample substitution.

Each phase ledger records start/end, return code, cleanup and sampled RSS;
worker event logs separate reading/loading/capture, source construction/check,
LP materialization, native calls, final exact checks and serialization. Partial
logs/files are retained after termination. Source construction currently groups
affine/ReLU/guard/LP construction in one event; it is not per-layer profiling.

Total charged cost includes all imports/validation/model loads/conversion,
checks/solves, serialization, supervisor overhead, worker termination and terminal
receipt. Final cost-ledger writing and a later saved-only audit are disclosed
separately. A deadline crossed during terminal/receipt/ledger publication writes
a timeout override and invalidates acceptance. Terminal candidates are never
standalone proof verdicts: consumers must validate the cost receipt and override.
As usual, failed storage or abruptly killed supervisor may prevent a complete
receipt; absent receipt is incomplete, never SAFE.

## Control and freeze gates

Use only synthetic checkpoint/input fixtures before real execution. Cover full
positive and nonpositive end-to-end runs, fresh solver-free recheck, wrong
source/run/property/LP bindings, exact residual differential, missing rows,
partial proposal then error, no candidate, hard cutoff with child descendants,
late complete positive file, low-RSS rejection, parent exception, absent result,
publication delay, duplicate/overwritten artifacts and total cost closure.
Keep prior35 source-conversion controls as regressions, unchanged.

After passing controls, commit implementation/control evidence, then freeze a
NEW output directory and execution identity; independent saved-only freeze
review checks all source hashes, original request assets, all252 obligations,
environment and resource rules. Freeze creates no real output directory and
loads no real checkpoint/tensor. Explicit later execution authorization is
required. Any unsupported source, budget exhaustion, nonpositive or incomplete
evidence ends this one bounded attempt without a search for an easier positive.
