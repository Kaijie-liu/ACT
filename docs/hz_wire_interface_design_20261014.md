# Frozen lossless evidence interface controls

The user authorized a new opt-in lossless codec, bounded checker intake and
archive interface on 2026-10-14. This protocol freezes their first controls
before implementation. It does not authorize a new resource policy, a real
model, GPU, source-capacity experiment or reopening any sealed input. Starting
HEAD is `ce8b473beda496de421982502d6f5044bd206b12`.

## Scope and invariants

Preserve the V3 logical forest, source identity, property contract, every
tie-legal pair, both candidate roles, exact residual arithmetic and strict
`1e-7` acceptance. The codec is not a new enclosure or candidate algorithm.
Old entry points and default behavior remain. Reuse the existing independent
affine, input, ReLU, guard and inventory checks; a wire hash alone cannot issue
a checked source handle. No arbitrary duck-typed checked handles are accepted.

Every old structural and logical-byte limit remains: 8M cumulative Work,
4096 stored bits, 8192 intermediate bits, 128 MiB forest/archive, 16 MiB proof,
4 MiB candidate tile, and the existing factor/root/nnz/reference limits.
Physical encoding is charged separately; it must not bypass logical limits.
Consequently the registered eight-expert full shape remains unadmitted.

This is bounded **consumption**, not yet bounded live capture or construction:
the first encoder may consume the existing V3 document, and the independent
decoder must not recreate its complete coefficient JSON/Fraction bank. The
native COO operator and full real-model peak RSS remain outside this stage.
The previous 110.6 MB proposal is not inherited as a measured or proven bound
for this implementation.

## Forest wire contract

Use a versioned little-endian binary file with a fixed prefix, a length-bounded
canonical JSON metadata header, binary64 scales, fixed-width root records,
fixed-width node descriptors and contiguous entry payloads. Each entry is a
32-bit index, an exact finite binary64 value and zero reserved bytes. Decode
only a bounded node row; metadata, norms and row offsets may remain resident.
Validate lengths/counts/offsets/padding and old logical limits before allocation.

The header carries the original source/request/frame/policy/factors/roles,
view identities and root counts, the complete source receipt, and the original
logical forest hash. Roots and scales reconstruct their canonical rational
strings. Preserve the old logical hash by incremental canonical serialization;
keep it separate from the wire hash. No whole-forest JSON materialization is
permitted in the new checker path.

A first-affine descriptor may reference a package-local source weight row plus
an explicit compensation tail. Bind manifest, tensor identity, graph/layer/row,
shape, owner and ordered input factor map. Read bounded source chunks with their
hashes, never an arbitrary external path or same-shape tensor. Replay source
validation completely and check all actual coefficients and zero positions.
Any source bytes retained across accesses must be immutable and privately held;
on-disk mutation must not produce mixed-identity data or an accepting terminal.
General non-binary64 references are refused without rounding. Source signed-zero
bits remain untouched; canonical rational zero is a distinct logical convention.

## Candidate and request contract

Tiles have a bounded canonical header and dense binary64 proposed vectors.
The zero role uses an explicit length/row/role-bound zero descriptor, not an
omitted candidate. Lower-value literals retain exact syntax and are never trusted.
Both roles are reconstructed and fully checked under the old mathematical gate.
Missing paired candidates remain explicitly missing; one missing role is an error.

Store each immutable raw tile once, before checking. Final manifests reference
those same bytes; no duplicated final proof body. The new consumer uses at most
one decoded candidate tile and does not accumulate all raw tiles in a Session.
Complete final aggregation recomputes the plan and checks exact tile/slot order,
absence of extra/missing duties, old canonical logical proof bytes/hash, and all
required properties. Stored receipts never replace independent recomputation.

Portable checking uses only package-contained source, forest, contract and tiles
under `python -I -S`, without a checkpoint, dataset, producer, optimizer or
numerical library. Returned statements retain captured-real-source and unchecked
live-program-correspondence limitations; no new real certificate is claimed.

## Archive and cumulative budget

One owned archive writer checks aggregate logical file bytes before writes,
including source, forest, tiles, metadata, bounded logs, failure prefixes and
terminal space. Partial files remain counted after exceptions. No overwrite,
symlink escape, external reference, silent log truncation or quota reset.
Source/tile reads, hashing, serialization, publication and checking are charged.
All operations use the same monotonic deadline of at most 300 seconds; no tile
or checker starts a new clock. Controlled child work uses bounded log reception
and owned process-group termination, not unlimited stdout/stderr archive FDs.

Relocation makes independent files and keeps both copies. Their actual bytes
are charged against the same unchanged archive limit before copying. Refuse
when they do not fit; do not delete originals, use hardlinks or change retention.
Offline rechecking has a separately labelled clock and cannot finish an online
proof. Final acceptance requires timely post-write reception; a success-looking
file created after the deadline cannot authorize acceptance. Failure cleanup
and diagnostic publication after deadline are explicitly nonaccepting costs.
The contract concerns owned logical file bytes, not whole-machine physical blocks.

## Frozen controls and stopping rule

Use only existing finite `mixed`, `deep`, `half`, `guarded` fixture definitions
and hand-constructed scalar records. No new large source, training or search.
Use explicit zero and fixed finite signed dual proposals, not an optimizer.
Compare the same decoded candidate's exact bounds and full results against the
old V3 checker; all gains are correctness/representation results, not speedups.

Control groups are: complete multi-pair/tie/property roundtrip; all ReLU cases
and compensation; dimensions and unchanged logical capacity; wrong source,
expert, row, factor/guard/property binding; alias and mid-read mutation; malformed
offset/count/padding/truncation/extra bytes; signed-zero/subnormal/nonfinite and
unsupported rational refusal; both roles and partial duties; missing/duplicate/
extra tiles; no eager coefficient/proof decode; portable relocation without the
original directory; combined-copy, small-record and log capacity; deadline before,
during and after write/check/reception; exception/partial preservation; complete
cost and failure accounting. Fix correctness defects before reporting controls
passed. Do not tune scientific outcomes, rerun frozen scientific cases or treat
test counts as G1–G6 completion. Any unresolved contract is reported explicitly.

The completed stage must include tests, read-only independent review, source
identity records, documentation, commit and branch push. A later capacity or real
execution needs its own complete Work/byte/lifetime assessment and authorization.
