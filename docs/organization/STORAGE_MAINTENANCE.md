# 工程存储维护

清理目标是回收可重建缓存，不改变实验对象、冻结记录或失败证据。用户于
2026-09-30 要求及时清理过时与冗余文件；文件旧、大、名为 cache/test/tmp
均不能单独作为删除依据。维护不会启动训练、求解或修改科研结论。

## 保留规则

- 原始数据、全部 checkpoint、冻结结果、失败现场、审阅包和安装收据原位保留。
- 隔离环境、作者仓库、pip 自编译 wheel 与 origin 溯源保留。
- 数据预处理缓存可能绑定输入身份，不按可重新计算就推定可以删。
- `cache_quarantine`、`quarantine_*_pycache` 是故障证据，不是普通缓存。
- 不把大型历史文件换成硬链接，避免后续修改造成别名污染；本次也不移动或压缩它们。

## 可执行清理范围

[清理入口](../../scripts/clean_regenerable_caches.py) 仅允许固定清单中的 pip
`http-v2` 下载记录，以及五处独立 Python 字节码前缀中仍有对应 `.py` 源码的
`.pyc`。不递归删除目录，不遍历环境内容，不删除数据库、模型或实验输出。
源码缺失、24 小时内更新、其他用户所有、硬链接、符号链接及未知格式均保留。

默认步骤是生成只读计划，列出每个候选文件的路径、设备、inode、大小、占用块数、
修改及变更时间。确认后 `--apply` 只处理这个计划；先验证全清单，再逐文件复核，
不跟随路径中的符号链接。新文件不自动纳入，清理收据逐项保存在本地。
清理失败可能已经删除前面的缓存；保留收据，不覆盖或假报全部完成。

进程检查仅是准入快照，不是文件系统锁。不得与安装、训练或另一清理进程并行执行。
检查当前用户的 cwd、打开文件、映射与环境；不能检查的进程默认阻止清理。
确认为无关服务时，允许显式记录 PID、启动 tick 和命令行摘要的人工豁免，
执行时再次绑定。这个豁免不表示已经读到了受保护进程的打开文件状态。

使用既有环境，无需安装依赖。每次使用新的计划和收据路径，例如：

```sh
/data1/Kane/miniconda3/envs/act-py312/bin/python -I -S scripts/test_cache_cleanup.py
/data1/Kane/miniconda3/envs/act-py312/bin/python -I -S scripts/clean_regenerable_caches.py --plan /data1/Kane/MOE/baseline_runs/storage_cleanup_20260930_r1/next_plan.json
```

查看计划并核对进程后，才用 `--apply 计划路径 --receipt 新收据路径`。
不复用旧进程豁免，不覆盖旧计划，不设置后台自动删除任务。每个完成阶段交接时检查
磁盘增长；缓存维护与科研实验分别记账。如果大头来自新证据/权重，应调整后续保留
或迁移方案，不自动删旧实验来腾空间。

## 恢复与可信范围

缓存删除不是移入回收站，不能保证恢复原缓存字节。Python 会从源码重建字节码；
pip 后续安装可能重新下载，因此恢复下载缓存依赖网络与原文件仍可获取。
已安装环境不变；保留 wheels/origin 与安装记录不能替代公共下载源的长期可用性。

控制覆盖只读计划、实际删除范围、近期文件、修改污染、越界与路径穿越、符号链接、
硬链接、活动根、重复项和无源码字节码。工程维护审计不是网络 SAFE 证明。
