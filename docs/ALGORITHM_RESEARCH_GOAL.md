### 研究目的与六项验收

改进 ACT/HybridZ 的 MoE 专用关系表示、条件传播与支持求解算法，使路由可能变化的
同一扰动域上仍能证明完整 MoE 输出鲁棒性，并以公平实验检验净验证收益。
不能仅凭包装现成 HybridZ、缓存、调度、监督层或换硬件宣布核心算法目标完成。
具有新证明规则、适用边界与增量证据的机制仍可构成方法贡献，不按代码类别先验排除。
可修改 HybridZ 本体以实现 MoE 专用关系机制；是否为方法增量仍由下述
数学合同、直接消融与完整请求证据判断，不以改动位置或代码量判断。
研究重点转到门、专家性质与路由条件之间可利用的结构；先检验具体机制，
不把初等组合公式、搜索策略或新的模块名称直接称为算法创新。

**G1 算法。** 至少一项保留同一输入/router/guard、共享与专家私有因子的
MoE 专用关系、条件传播或支持机制贯通 HybridZ 完整请求。
已有多目标支持、共享/私有块、系数引用/尺度分离、精确残差消费和生命周期复用
不重新命名为创新。每项候选明确相对已有实现的差异、数学合同、失效条件、
合理原生强基线和可证伪假设，用直接消融与完整请求结果验收。
门加权事实是第一项计算优化候选；它仍使用门区间，不恢复门与输入的完整耦合，
单独通过控制或节省调用数不能关闭 G1。
H2 端点与范围型 McCormick 单独作表示比较；相等性只在同域、同目标、
同门区间且实际 McCormick 差值区间不跨零等条件下讨论精确最优值，
不推导有限预算的结果支配。搜索变化不冒充新抽象域。

**G2 GPU。** 实现并实际检验可选 GPU 批量候选；CPU 对原始绑定系数独立精确检查
来源、符号、残差补偿与下界。原算法 CPU、新算法 CPU、同一新算法 GPU 分开归因；
先过冻结覆盖保持门，再检验完整请求配对成本的实用收益。
同候选精确接受一致，不要求候选轨迹逐位相同。当前路径 CPU-only，
模拟接口、GPU 浮点正界、kernel 加速或提额不能代替证书与算法收益。
实机运行独立冻结、新鲜准入，不循环重试旧拒绝；保留强 CPU 与合理外部 GPU 机会。
本轮不启动 GPU 工作，也不将 GPU 取消为长期目标。

**G3 同源证明。** 同一真实声明对象绑定训练制品、物化输入、预处理和 BN/eval，
闭合输入包含、专家/router 转换、误差补偿、ReLU/因子映射、gate/guard、
全部 tie-legal 路由、全部输出义务与聚合。新矩阵生成新证据；
搬迁检查不读取 checkpoint、训练数据、历史运行目录或求解器。
未闭合转换列明可信假设，保持条件化；声明实数网络与原生 PyTorch/CUDA
浮点执行证明分开。路由变化需经检查的同域见证，保守 pair 清单不等于实际可达或 flip。
门加权和的有理数重算不补上输入、专家事实或门范围的来源缺口；
即使使用有理数 sigmoid 包络，全部前提也须达到所声称的保证等级。
OS、时钟和测量工具作为有限、显式可信基础，不无限追溯其启动历史；
这不自动修改任何冻结计时边界。

**G4 外部竞争。** 保留 MetaMoE 原始类别分离 hard top-1 作者兼容路径、
ACT 路由前端加 plain CROWN 全盒可变权重静态 pair 两条线；
增加完整 αβ-CROWN/GenBaB 作为需先核对语义兼容性的强对照。
GenBaB 的全盒静态 pair、可表达时的 guarded pair、完整路由覆盖聚合分别标注，
不将其中一项冒充作者现成的完整 MoE 工具，也不预设通用工具不能做门细化。
按同对象/输入/性质/300 秒、合理强配置、硬件机会公平和保证等级分栏，
独立冻结每条比较的 gained-lost>0、最小实用效应、输入级配对不确定性和成本判据；
未通过保持未证实。正过滤不冒充严格证书，对手缺独立证明不计为同等级失败。
类别分离零填充对象不追语义不可能的跨类别 route-changing 正 margin，
但不声称路由稳定请求不可能有 ACT 独有结果。
G3/G5 的路由变化正证使用兼容的共享输出对象。保留 matched 同等性质事实、
旧强对照和全部 gain/loss/终态；不把 MetaMoE 层调优继续作为当前创新主线。
外部工具安装、适配和执行仍各需明确范围，本次不部署或运行。

**G5 外部效度。** 在预先固定的高准确率及不同模型家族上取得同源、完整、
可检查的路由变化正证和见证；模型、训练、checkpoint 不按可证性选择。
准确率、编译通过、更多同家族 seed 或合成正例不能替代，不自动重训。

**G6 相关工作与投稿。** 完成 Dual RS 的平滑/确定性、L2/Linf、
统计置信度与成本合同，以及 MetaMoE、RoME、Robust Experts、J-TLAT、
Feature Noise 的制品、语义、适用性和评估记录。
不偷改 RoME 连续混合为 top-k，不将攻击鲁棒率与 SAFE 率横比，
不伪造六篇工作的同任务胜负。新颖性依赖具体机制及其增量证据，
不以一次检索声称“首次”“唯一”或通用工具不可模拟。
形成与实际证据一致、以 ISSTA/OOPSLA 等软工 A 会为目标的材料；
论文标题、定理、主表与可信边界一致。独立人类技术审阅、干净环境实证复现、

### 当前优先级与退出条件

**M0 已作出的研究决定。** 停止推进端点中点假设及为其继续扩展的执行修复链；
不再把旧七位置/22 项 CPU 批次作为当前待运行任务。
保留实现、R3/R4 失败和已完成清理控制；停止是研究优先级判断，
不是已经测得中点算法无效。该算法尚无正常配对效果数据。
旧批次 2100 秒、单次最多 60 秒准入等条件只约束其历史协议，
不自动成为新机制的执行授权或总配额。

**M1 门加权有效下界事实的单因素合同。** 默认关闭，先独立区分
“有效下界事实”与“正下界安全事实”；有效下界允许负值，本身不能建立 SAFE。
绑定请求、模型、物化输入域、专家 membership guard、性质完整系数 `(q,c)`、
专家身份、因子框架、数值政策和原始来源。门事实绑定同域 conditioned router、
规范 pair `(a,b)`、专家 a 的权重方向及范围来源。
若专家性质下界为 `L_a,L_b`，合法门区间为 `[l,h]`，则组合规则为
`L_gate = min(l*L_a+(1-l)*L_b, h*L_a+(1-h)*L_b)`。
依据是 pair 域包含于两个 membership 域、非负归一化权重和仿射性质；
常数项通过权重和为 1 只计一次。交换专家方向同时将区间改为 `[1-h,1-l]`。
仅 `L_gate` 严格通过原安全门时消去该 pair/property；缺证据或未通过原样回退。

首版保留旧正事实快路径，在原有门范围返回后、F0 构造前应用新规则；
不前移传播、不额外调用门支持、不新增逐行支持、热启动、顺序/预算调度或 GPU。
只有源区间已有而缺少 signed fact 时，增加来源绑定的提取与独立算术检查。
浮点 sigmoid 加 nextafter 的门区间仍是原数值政策等级；
margin 符号给出的半区间也需来源/符号经检查，不能仅凭 clean route 升级。
未来控制覆盖负下界、方向、非零常数、tie、固定门、`[0,1]` 退化、
缺失/错误绑定、非有限值与倒置范围、截止/迟到、来源重算、旧快路径及原生回退。
该有限实现与合成控制已按本节顶部的后来授权完成；控制范围为标准库与函数
stub，不含原生模型/求解器集成。下一 M1b 已获本次常设授权，冻结后直接执行，
不重复本批控制。

**M1b 原生集成。** 修正三处必要接线：默认 Work 截止/资源异常的明确终态；

| 工作线 | 应改变的算法或交付 | 验收时必须回答的问题 |
|---|---|---|
| A1 共享与私有块支持 | 在 HybridZ 内保留唯一共享输入／router 坐标、独立专家激活因子和条件 guard；共同计算多目标支持，先合并共享残差再取盒下界 | 与原生合理配置相比，关系、义务和数值合同是否保持，重复工作及完整请求成本是否实际减少？ |
| A2 性质导向加权支持 | 在同一 guarded 域上比较端点支持与范围型 McCormick；只对实际性质生成必要目标 | 是否增加完整输出正结论，而不只是某个局部界更好？是否保留共享关系和全部端点？ |

A1、A2 和 D 是分开的实验因素。最小归因链为原算法 CPU、新算法 CPU、
同一新算法 GPU；原生强配置及有同等事实的 matched 对照不能因新版本出现而消失。
关系消融另外比较共享输入与已证明包含原关系的独立外包络，不把调度差异当作关系证据。
稀疏行解析、容量修复、缓存和监督属于必要支撑，不能单独关闭 MoE 专用算法门 G1。

最终整合必须绑定同一兼容的代码版本、来源身份和证据 schema。当前
[块提议器](../act/back_end/moe/block_support.py)只接受 CPU；
[平坦矩阵设备接口](../act/back_end/moe/batched_support_device.py)的控制不能替代块路径的 GPU 控制。
新的[请求内块存储设备接口](hz_store_device_20261013.md)已完成四个小源的 CPU 等价与
模拟故障控制；41 条端点证据相同。[完整设备监督](hz_store_device_supervision_20261013.md)
随后完成十次 CPU／模拟调用和 V2 审计；[六槽物理协议](hz_store_physical_20261013.md)
已冻结并执行唯一准入，因其他计算进程而拒绝，六槽全部未启动。不能把“可选 CUDA
代码已实现”或准入终态审计通过写成 GPU 已加速或目标 G2 已完成。
[公共专家模板](hz_expert_templates_20261001.md)的等价合同不包含 pair 条件下的传播收紧；
若增加这种收紧，必须重新证明事实作用域与复用有效性，不能将只在一个 guard 下
成立的范围推广为公共域事实。

G3 除声明内部的转换检查外，还必须绑定实际训练制品、物化输入、预处理、BN/eval
语义与声明之间的对应。当前[源检查器](../scoped_source/check_hz_block_source.py)
仍保留 `declaration_corresponds_to_intended_program`；未核验这一对应时，
结论必须保留条件化限定。也不把声明实数网络证明升级成原生浮点执行证明。

## 本体改进与最近交付

必须改进的是 HybridZ 中处理 MoE 关系的算法，而不是以修改文件数量衡量创新。
沿用 HZ 的基础定义和既有正确算子没有问题；新贡献要说明改变了哪一种关系表示、
支持查询或条件传播，给出正确性依据，并检验它增加了什么完整结果或减少了什么成本。
只加缓存、监督、结果审计或换 GPU，不能单独完成 G1。

| 算法因素 | 当前实际状态 | 尚需检验的交付 |
|---|---|---|
| guard 条件下的多目标支持参与 ReLU 传播 | 已通过显式 `CheckedGuardedHybridzTF` 接入真实 analyzer，有限控制能减少不稳定二元因子 | 与合理配置的原生支持比较完整成本和结果，不能把关闭原生支持的控制当竞争胜出 |
| 保留共享因子的加权端点支持 | 已在实际 SparseHZono 及有限声明来源上生成新端点证据，有同域范围型 MC 分离控制 | 真实模型完整义务、容量及净收益；不能自动迁移到 MetaMoE hard top-1 |
| 共享输入与专家私有块 | 专家模板及直接块支持均通过有限控制，同候选精确差分一致 | 真实容量和完整成本；小控制中三项总耗时更差，不能称加速 |
| GPU 多目标候选生成 | 平坦接口与请求内块接口均有 CPU／模拟控制；块路径完整监督已接入，单次六槽物理准入拒绝、全部未运行 | 真正 CUDA 执行、独立接受及同算法端到端 CPU/GPU 比较，当前没有实机加速证据；不自动重试 |

这些显式启用的传播钩子、来源路径和设备接口目前不是一套已经贯通的生产系统，
不能将各自控制通过相加，宣称真实模型与 GPU 的完整证明流程已经完成。
具体地，[guarded 传播钩子](../act/back_end/moe/checked_propagation.py)的精确支持
入口仍限于 128 因子／输出、256 约束，超出后走原生回退；

专家模板，再附 pair guard，没有将该传播钩子接入模板生成。它还要求整份声明不超
4 MiB、每层非零参数不超 262144。下一步需核对同一登记训练来源的张量与完整行结构，
设计受限内存的读取／转换，而不是仅提高这些上限或声称两条接口已经贯通。

### A1 路由条件 HybridZ 的块结构支持算法

以现有 SparseHZono、guarded 入口及 ReLU 支持查询为基础，研究：
共享输入／router 块只保持一份逻辑身份，各专家保持私有激活因子，
pair guard 显式绑定共享域。对相同分支基础约束上的多条性质与上下界目标，
采用多目标支持接口，避免把每条性质都当作全新的独立分析。

直接块支持已保留专家局部约束和共享输入／guard，并在同一全局残差上组合下界。
它没有把专家优化成可独立选择输入的子问题。若进一步按共享接口分解优化、用接口
乘子协调独立子问题，那仍是需另行证明和比较的后续假设，不是本轮已有结果。
不能将不同专家的内部因子强行合并，也不能取消输入一致性后仍称关系保留。
若采用放松，必须证明外包络包含性，不能宣称与原 HZ 精确等价。

验收要求是实际接入 HybridZ 的支持／传播路径，提供原路径对照、来源及因子映射
控制与独立消融。只在独立 LP 脚本上成功，不算本项完成。
已有增量 HiGHS、共同矩阵存储和 scoped reuse 是基线，不作为本次新发明。

### A2 性质导向的加权 HybridZ 支持

研究将 H2 的 gate 端点支持接到同一 guarded HZ 或其明确声明的 LP 外松弛上。
前提是每个真实 guarded 执行均能嵌入共同域 P，且真实归一化权重有已检查的
外包区间 0≤l≤h≤1。对专家性质 A(z)、B(z) 和独立 gate 区间 [l,h]：

    inf over z in P and t in [l,h] of B(z) + t(A(z)-B(z))
      = min(inf_P B+l(A-B), inf_P B+h(A-B)).

这可避免独立区间 gate 的额外乘积松弛，但仍放松实际 softmax 对输入的依赖；
两个不同端点目标均须处理并计费；若 l=h，可以一次相同目标的证据覆盖两个
端点标签，但须检查这一相等与覆盖关系。
[已有证明](../act/back_end/moe/proofs/gate_interval_endpoint_support.md)
不支持“新的通用凸性理论”，也不支持省略不同的另一端。

对照必须固定同一 P、gate、性质和保证合同；范围仅为 [0,1] 时，
端点退化为逐专家充分条件，不应声称加权增益。若 MC 保留额外 gate 输入耦合，
不能直接套用范围型 MC 的支配结论。
新 HZ／新矩阵必须生成新证据，不借旧直接节点 LP 的正界。

A1 的块分解、A2 的表示精度与 GPU 的设备收益分别消融，不在同一批同时改变三者。

## GPU 路线与接受边界

### 优先候选是批量对偶提议而不是搬走整个验证器

首个拟议实现针对同一 pair 基础矩阵上的多性质／端点：
以稀疏矩阵和多列目标批量生成 LP 支持的候选对偶乘子，
可研究投影对偶优化及受控初值复用。新目标仍逐条检查，不因基础矩阵相同而免除义务。

对于 A z≤b、E z=h、有限且已证明的 l≤z≤u，目标 cᵀz+d，
候选 y≤0、t 任意，检查器重算

    r = c - Aᵀy - Eᵀt
    L = d + bᵀy + hᵀt + sum_j min(r_j*l_j, r_j*u_j).

GPU 只提出有限乘子、候选范围或优先级。CPU 以原始绑定系数精确检查符号、
残差补偿、变量界、来源和目标后才接受 L；不依赖 GPU 声称收敛或最优。
这是已有弱对偶规则，创新目标在 MoE 的块关系和多目标求解组织。

二元因子若连续松弛，必须标明 LP 外包络；GPU 提议器不冒充完整 MILP 求解器。
LP 下界足够正可形成该义务证据；非正、超时或没有候选都不能推出 UNSAFE。
原生产 optimal-status 门不直接取消：新模式需独立版本、明确接受合同和完整控制。
给定 HZ 上的检查通过，也不自动修复网络到 HZ 的来源缺口。

优先接入位置为 [HybridZ 支持调用](../act/back_end/hybridz_tf/tf_mlp.py)、
[增量支持接口](../act/back_end/moe/incremental_hz_solver.py)及
[加权性质](../act/back_end/moe/weighted_top2.py)，保持原生回退且计入同一预算。
同一批不再同时迁移仿射／ReLU 传播。后续若将传播上 GPU，必须另行证明或检查
输入外包络、仿射误差、ReLU 范围与 factor 映射，不能用 CPU/GPU 近似相等代替。

### GPU 控制与停止条件

先冻结 CPU 同算法参考与 GPU 候选版本，覆盖：多 pair、tie、多类别、部分复用、
共享／私有因子、零宽及非零 gate 范围、目标换序、跨请求污染、错误符号、
缺端点、NaN/Inf、溢出、OOM、截止、晚到候选和部分证据。
在解析可核验的小问题上检查数学结论，在相同候选上要求精确 checker 结果一致；
不要求 CPU/GPU 浮点轨迹逐 bit 一致。

现有环境为 torch 2.9.1+cu128；登记只读取版本，未初始化 CUDA。
PyTorch 官方说明 CPU/GPU 与批量／逐项运算可能不逐 bit 一致，
稀疏算子的覆盖也有局限。因此必须先测当前版本的实际算子和 dtype，
不预设稀疏 GPU 一定更快。
[数值说明](https://docs.pytorch.org/docs/2.9/notes/numerical_accuracy.html)，
[稀疏算子说明](https://docs.pytorch.org/docs/2.9/sparse.html)。

初版按冻结配置使用 float64 候选；不偷偷启用 AMP／TF32 或 dtype 回退。
更低精度只能另作候选生成消融，接受端仍用相同独立检查。
优化迭代、初值、批大小、内存上限及停止策略在有限控制后冻结，不按 holdout 调整。

若候选界持续弱、精确残差修正吞没收益，或传输／检查使完整成本更差，
按预注册规则停止该因素并保留失败。不能以 GPU 利用率高、kernel 更快、
多条局部正界或更多控制通过代替完整请求收益；也不转回无限自研精确消元。

## 六个独立验收门

| 门 | 交付及通过依据 | 当前状态 |
|---|---|---|
| G1 HybridZ 算法 | 至少一项 MoE 专用关系／支持／传播机制实际接入 HybridZ；数学合同、完整控制、原算法与关系消融能检验增量 | OPEN，实际传播接入及有限 CPU 完整监督已过；native 对比与实际净收益未完成 |
| G2 GPU 全流程收益 | 同算法 CPU/GPU、相同义务和 checker；先通过冻结的覆盖保持标准，再通过完整请求配对成本的实用效应标准 | OPEN，没有实机 GPU 成绩 |
| G3 同源完整证明 | 同一真实声明对象上，输入、网络转换、因子、guard、gate、全部合法路由、全部输出和聚合检查闭合；搬迁后无 checkpoint／求解器检查 | OPEN，合成正例不能代替真实闭合 |
| G4 外部净收益 | MetaMoE top-1 与 weighted CROWN 两条线分别独立确认；各报告正结果 gained/lost、完整终态、成本及保证等级 | OPEN，当前比较不领先 |
| G5 外部效度 | 在预先固定的高准确率及不同模型家族上取得同源完整、路由变化正证据；模型按非可证性标准选择，报告准确率与全部失败 | OPEN，不以同家族 seed 或仅模型准确率达标代替 |
| G6 投稿证据 | 六项相关工作合同、可复现制品、论文本体主张对齐，独立人类技术审阅与干净环境实证复现 | OPEN，外部协作不能由 AI 自检代替 |

G1 不是必须发明新的通用 HZ 域；G2 不是局部加速；G3 是声明实数语义，

## 公平实验与完整计费

方法改进和硬件改进必须分开：原 HybridZ CPU、新算法 CPU、新算法 GPU
构成基本归因链；同样可用的廉价 scoped facts 给匹配 monolithic 对照，保留旧强配置。
新实验不是把历史 CPU 计时与新 GPU 计时直接相减。

每个请求沿用 300 秒硬预算，含创建／加载、输入物化、转换、GPU 初始化／编译、
主机设备传输、同步完成的 GPU 运算、回退求解、序列化、独立检查、接收、清理及终态。
批量义务只在同一请求内共享前处理；跨请求常驻模式和摊销若研究，另设协议。
准入等待单独披露且有界；从请求执行计时起的一切等待计入该请求，不隐藏等待总成本。

固定并公布 CPU 核／线程、RAM、GPU 型号／数量／显存、dtype、软件版本、
并发、冷／热启动和顺序。外部工具能用 GPU 时给其同等硬件机会；
CPU 专用工具保持其合理配置并披露差异，不假称硬件完全相同。
报告 CPU core-seconds、GPU 占用秒数及峰值 RAM/VRAM，不将二者直接相加冒充成本等价。

优先分析完整 positive gained/lost、共同正结果的成本及全请求封顶成本；
另列 UNSAFE、UNKNOWN、TIMEOUT、ERROR/RESOURCE_LIMIT，缺包仍在分母中。
不把提前 UNKNOWN 当成成功加速。若比较不同证据等级，正过滤与检查证书分栏，
不能用较弱合同产生的更多正结果声称严格证书优势。

G2 的覆盖保持使用事先冻结的零丢失规则或有明确容许幅度的非劣标准，二者不得在
看结果后切换。通过后才判断同保证层的共同完整正结果的配对时间收益，并同时展示所有终态的
总成本。若更快来自更早 UNKNOWN、超过冻结容许幅度的覆盖丢失或省略必需检查，
就不能宣布 GPU 加速目标达成。
CPU/GPU 候选轨迹不必逐位一致，但同一候选在同一源／性质上的精确检查结果必须一致。

先控制，再冻结有限 development 的样本数／来源／预算和停止规则；
只有完整请求信号支持继续时才另行冻结独立确认。
确认前固定主指标、最小实用效应、输入级配对区间／重采样、多比较及重复计时规则；
目前不按旧结果倒填某个百分比，也不自动指定新 100 张。
保留跨模型输入相关性，不将所有调用视作独立样本，不扩样追成功。
