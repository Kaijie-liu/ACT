## 本体改进与最近交付

必须改进的是 HybridZ 中处理 MoE 关系的算法，而不是以修改文件数量衡量创新。
沿用 HZ 的基础定义和既有正确算子没有问题；新贡献要说明改变了哪一种关系表示、
支持查询或条件传播，给出正确性依据，并检验它增加了什么完整结果或减少了什么成本。
只加缓存、监督、结果审计或换 GPU，不能单独完成 G1。

| 算法因素 | 当前实际状态 | 尚需检验的交付 |
|---|---|---|
| guard 条件下的多目标支持参与 ReLU 传播 | 已通过显式 `CheckedGuardedHybridzTF` 接入真实 analyzer，有限控制能减少不稳定二元因子 | 与合理配置的原生支持比较完整成本和结果，不能把关闭原生支持的控制当竞争胜出 |

不以“必须改很多核心文件”衡量创新，而以保留了什么关系、改变了哪些证明义务、
为何正确、在公平成本下新增了什么完整结果衡量。

### A1 路由条件 HybridZ 的块结构支持算法

以现有 SparseHZono、guarded 入口及 ReLU 支持查询为基础，研究：
共享输入／router 块只保持一份逻辑身份，各专家保持私有激活因子，
pair guard 显式绑定共享域。对相同分支基础约束上的多条性质与上下界目标，
采用多目标支持接口，避免把每条性质都当作全新的独立分析。

直接块支持已保留专家局部约束和共享输入／guard，并在同一全局残差上组合下界。
它没有把专家优化成可独立选择输入的子问题。若进一步按共享接口分解优化、用接口
乘子协调独立子问题，那仍是需另行证明和比较的后续假设，不是本轮已有结果。
不能将不同专家的内部因子强行合并，也不能取消输入一致性后仍称关系保留。
若采用放松，必须证明外包络包含性，不能宣称与原 HZ 精确等价。

验收要求是实际接入 HybridZ 的支持／传播路径，提供原路径对照、来源及因子映射
控制与独立消融。只在独立 LP 脚本上成功，不算本项完成。
已有增量 HiGHS、共同矩阵存储和 scoped reuse 是基线，不作为本次新发明。

### A2 性质导向的加权 HybridZ 支持

研究将 H2 的 gate 端点支持接到同一 guarded HZ 或其明确声明的 LP 外松弛上。
前提是每个真实 guarded 执行均能嵌入共同域 P，且真实归一化权重有已检查的
外包区间 0≤l≤h≤1。对专家性质 A(z)、B(z) 和独立 gate 区间 [l,h]：

    inf over z in P and t in [l,h] of B(z) + t(A(z)-B(z))
      = min(inf_P B+l(A-B), inf_P B+h(A-B)).

这可避免独立区间 gate 的额外乘积松弛，但仍放松实际 softmax 对输入的依赖；
两个不同端点目标均须处理并计费；若 l=h，可以一次相同目标的证据覆盖两个
端点标签，但须检查这一相等与覆盖关系。
[已有证明](../act/back_end/moe/proofs/gate_interval_endpoint_support.md)
不支持“新的通用凸性理论”，也不支持省略不同的另一端。

对照必须固定同一 P、gate、性质和保证合同；范围仅为 [0,1] 时，
端点退化为逐专家充分条件，不应声称加权增益。若 MC 保留额外 gate 输入耦合，
不能直接套用范围型 MC 的支配结论。
新 HZ／新矩阵必须生成新证据，不借旧直接节点 LP 的正界。

A1 的块分解、A2 的表示精度与 GPU 的设备收益分别消融，不在同一批同时改变三者。

## GPU 路线与接受边界

### 优先候选是批量对偶提议而不是搬走整个验证器

首个拟议实现针对同一 pair 基础矩阵上的多性质／端点：
以稀疏矩阵和多列目标批量生成 LP 支持的候选对偶乘子，
可研究投影对偶优化及受控初值复用。新目标仍逐条检查，不因基础矩阵相同而免除义务。

对于 A z≤b、E z=h、有限且已证明的 l≤z≤u，目标 cᵀz+d，
候选 y≤0、t 任意，检查器重算

    r = c - Aᵀy - Eᵀt
    L = d + bᵀy + hᵀt + sum_j min(r_j*l_j, r_j*u_j).

GPU 只提出有限乘子、候选范围或优先级。CPU 以原始绑定系数精确检查符号、
残差补偿、变量界、来源和目标后才接受 L；不依赖 GPU 声称收敛或最优。
这是已有弱对偶规则，创新目标在 MoE 的块关系和多目标求解组织。

二元因子若连续松弛，必须标明 LP 外包络；GPU 提议器不冒充完整 MILP 求解器。
LP 下界足够正可形成该义务证据；非正、超时或没有候选都不能推出 UNSAFE。
原生产 optimal-status 门不直接取消：新模式需独立版本、明确接受合同和完整控制。
给定 HZ 上的检查通过，也不自动修复网络到 HZ 的来源缺口。

优先接入位置为 [HybridZ 支持调用](../act/back_end/hybridz_tf/tf_mlp.py)、
[增量支持接口](../act/back_end/moe/incremental_hz_solver.py)及
[加权性质](../act/back_end/moe/weighted_top2.py)，保持原生回退且计入同一预算。
同一批不再同时迁移仿射／ReLU 传播。后续若将传播上 GPU，必须另行证明或检查
输入外包络、仿射误差、ReLU 范围与 factor 映射，不能用 CPU/GPU 近似相等代替。

### GPU 控制与停止条件

先冻结 CPU 同算法参考与 GPU 候选版本，覆盖：多 pair、tie、多类别、部分复用、
共享／私有因子、零宽及非零 gate 范围、目标换序、跨请求污染、错误符号、
缺端点、NaN/Inf、溢出、OOM、截止、晚到候选和部分证据。
在解析可核验的小问题上检查数学结论，在相同候选上要求精确 checker 结果一致；
不要求 CPU/GPU 浮点轨迹逐 bit 一致。

现有环境为 torch 2.9.1+cu128；登记只读取版本，未初始化 CUDA。
PyTorch 官方说明 CPU/GPU 与批量／逐项运算可能不逐 bit 一致，
稀疏算子的覆盖也有局限。因此必须先测当前版本的实际算子和 dtype，
不预设稀疏 GPU 一定更快。
[数值说明](https://docs.pytorch.org/docs/2.9/notes/numerical_accuracy.html)，
[稀疏算子说明](https://docs.pytorch.org/docs/2.9/sparse.html)。

初版按冻结配置使用 float64 候选；不偷偷启用 AMP／TF32 或 dtype 回退。
更低精度只能另作候选生成消融，接受端仍用相同独立检查。
优化迭代、初值、批大小、内存上限及停止策略在有限控制后冻结，不按 holdout 调整。

若候选界持续弱、精确残差修正吞没收益，或传输／检查使完整成本更差，
按预注册规则停止该因素并保留失败。不能以 GPU 利用率高、kernel 更快、
多条局部正界或更多控制通过代替完整请求收益；也不转回无限自研精确消元。

## 六个独立验收门

| 门 | 交付及通过依据 | 当前状态 |
|---|---|---|
| G1 HybridZ 算法 | 至少一项 MoE 专用关系／支持／传播机制实际接入 HybridZ；数学合同、完整控制、原算法与关系消融能检验增量 | OPEN，实际传播接入及有限 CPU 完整监督已过；native 对比与实际净收益未完成 |
| G2 GPU 全流程收益 | 同算法 CPU/GPU、相同义务和 checker；先通过冻结的覆盖保持标准，再通过完整请求配对成本的实用效应标准 | OPEN，没有实机 GPU 成绩 |
| G3 同源完整证明 | 同一真实声明对象上，输入、网络转换、因子、guard、gate、全部合法路由、全部输出和聚合检查闭合；搬迁后无 checkpoint／求解器检查 | OPEN，合成正例不能代替真实闭合 |
| G4 外部净收益 | MetaMoE top-1 与 weighted CROWN 两条线分别独立确认；各报告正结果 gained/lost、完整终态、成本及保证等级 | OPEN，当前比较不领先 |
| G5 外部效度 | 在预先固定的高准确率及不同模型家族上取得同源完整、路由变化正证据；模型按非可证性标准选择，报告准确率与全部失败 | OPEN，不以同家族 seed 或仅模型准确率达标代替 |
| G6 投稿证据 | 六项相关工作合同、可复现制品、论文本体主张对齐，独立人类技术审阅与干净环境实证复现 | OPEN，外部协作不能由 AI 自检代替 |

G1 不是必须发明新的通用 HZ 域；G2 不是局部加速；G3 是声明实数语义，
不是原生 PyTorch/CUDA 浮点栈机器证明。仍受信任的转换必须列明，未闭合则标条件化。
多个可行 tie-legal pair 与两个输入上真实选择不同是不同命题；
主张路由变化时需相应的经检查同域见证，潜在 pair 清单不能替代。

G4 只有在 MetaMoE 与 weighted CROWN 两条线上，分别在独立冻结的确认集合上通过
预注册的净完整正结果增益（gained−lost>0）、最小实用效应、配对不确定性判据及成本
标准后才通过；仅观察到一个净增量不够。具体阈值在执行前固定，不按旧结果倒填；
任一未通过则保持 OPEN／未证实。
比较必须有语义可比的完整端点，保证等级分栏；数值过滤数量不能冒充严格证书排名。
计数单位为同一任务／保证层中的完整模型—输入—性质集合请求，不是局部正界数；
top-1 与 weighted top-2 分开，不能混合凑净收益。对只提供数值过滤的外部路径，
保留其操作效果比较，但不能把缺少严格证据填成严格认证比赛中的失败。
若只补充少量独有例、但总体覆盖／成本更差，就报告互补性或折中，不称稳定优越。
高级目标未达到时保持 OPEN 或如实报告未证实，不因论文写完或算力耗尽标完成。

## 公平实验与完整计费

方法改进和硬件改进必须分开：原 HybridZ CPU、新算法 CPU、新算法 GPU
构成基本归因链；同样可用的廉价 scoped facts 给匹配 monolithic 对照，保留旧强配置。
新实验不是把历史 CPU 计时与新 GPU 计时直接相减。

每个请求沿用 300 秒硬预算，含创建／加载、输入物化、转换、GPU 初始化／编译、
主机设备传输、同步完成的 GPU 运算、回退求解、序列化、独立检查、接收、清理及终态。
批量义务只在同一请求内共享前处理；跨请求常驻模式和摊销若研究，另设协议。
准入等待单独披露且有界；从请求执行计时起的一切等待计入该请求，不隐藏等待总成本。

固定并公布 CPU 核／线程、RAM、GPU 型号／数量／显存、dtype、软件版本、
并发、冷／热启动和顺序。外部工具能用 GPU 时给其同等硬件机会；
CPU 专用工具保持其合理配置并披露差异，不假称硬件完全相同。
报告 CPU core-seconds、GPU 占用秒数及峰值 RAM/VRAM，不将二者直接相加冒充成本等价。

优先分析完整 positive gained/lost、共同正结果的成本及全请求封顶成本；
另列 UNSAFE、UNKNOWN、TIMEOUT、ERROR/RESOURCE_LIMIT，缺包仍在分母中。
不把提前 UNKNOWN 当成成功加速。若比较不同证据等级，正过滤与检查证书分栏，
不能用较弱合同产生的更多正结果声称严格证书优势。

G2 的覆盖保持使用事先冻结的零丢失规则或有明确容许幅度的非劣标准，二者不得在
看结果后切换。通过后才判断同保证层的共同完整正结果的配对时间收益，并同时展示所有终态的
总成本。若更快来自更早 UNKNOWN、超过冻结容许幅度的覆盖丢失或省略必需检查，
就不能宣布 GPU 加速目标达成。
CPU/GPU 候选轨迹不必逐位一致，但同一候选在同一源／性质上的精确检查结果必须一致。

先控制，再冻结有限 development 的样本数／来源／预算和停止规则；
只有完整请求信号支持继续时才另行冻结独立确认。
确认前固定主指标、最小实用效应、输入级配对区间／重采样、多比较及重复计时规则；
目前不按旧结果倒填某个百分比，也不自动指定新 100 张。
保留跨模型输入相关性，不将所有调用视作独立样本，不扩样追成功。

每个执行阶段还须冻结总请求数、配置候选数、最大尝试次数、累计资源／时间上限及
资源准入次数，并写出继续、修复或停止该机制的条件。不能用“持续观察”无限延长
同一局部搜索。否定结果和停止判断也可以完成该阶段交付，但不能据此关闭科学目标。
每次进度报告至少区分：实际算法改动及位置、保留关系／正确性依据、真实 CUDA 或
模拟执行、完整义务与新增／丢失结果、全流程成本、当前可信边界和下一门；
控制数量及文档数量不是主要进度指标。
