# 同性质端点对偶搜索的静态研究决定

2026-10-19；源码基线 `5637cd7e8fa825874532daf5b53e210ebcde06ea`，
`feat/moe-route-verification`，起始工作区干净。

**结束生命周期故障控制分支；保留一个未实施的支持搜索假设，不启动新的控制或实模。**
[两个 factor 故障](hz_pair_factor_faults_results_20261019.md)已经单独完成，旧 R1 仍为 FAIL。
下一算法候选是同 pair、同性质的两个 gate 端点之间交换对偶信息，而不是再增加缓存或监督层。
它改变有限预算的候选搜索，不改变 HZ 外包络、检查器或资源准入。

## 已有能力与实际差异

[当前候选器](../act/back_end/moe/source_row_endpoints.py)的 `Proposer.propose` 对一组至多
8 条目标共同应用算子，但每列的初值、次梯度更新、`best` 和对偶选择互相独立。
`native_coo_reference` 与 `native_source_row_blocks` 共用这段搜索；两种表示不是两种
不同优化算法。共享输入残差先合并再取范数、多目标支持、共享／私有块和尺度分离已存在。

[方法身份](../scoped_source/native_method.py)固定 128 个更新位置及 129 次评价。
[端点规划](../scoped_source/scaled_endpoints.py)按 pair、性质、gate 端点生成任务；
[Plan.tiles](../scoped_source/forest_endpoints.py)按 pair 切成宽 8 的 tile。
同 pair 的 gate 区间对所有性质相同，因此两个端点相邻且不会被宽 8 拆开；
退化 gate 只有一个端点。未来实现仍须验证实际 mate 身份，不能仅凭数组邻接交换数据。

待检验的差异仅为：在原 `step=127` 完成评价并更新各列 best 后，同步读取同一性质两端点
各自的 best 对偶，用固定中点替换最后一个次梯度更新。`step=128` 仍是原有的最后评价，
各端点独立保留本臂观察到的最佳数值候选。单端点沿用原最后更新。

这意味着双端点采用 **127 次梯度更新及 1 次中点更新**，不是 128 次梯度更新再追加评价。
固定 129 次评价、最多 504 端点、每端点 proposed 与显式 zero 两角色（最多 1008 份）、
候选宽 8、检查块宽 2；不创建混合比例网格、跨 tile 缓存或额外候选角色。

## 为什么可以检查这种候选

固定同一个已绑定 pair 的约束与因子域，写成

\[
Ax\le b,\quad Ex=h,\quad -s\le x\le s,\qquad s\ge0.
\]

第 j 个端点的性质为 \(c_j^\top x+d_j\)。任意 \(y\le0\)、自由 \(z\) 给出

\[
L_j(y,z)=d_j+b^\top y+h^\top z
-\sum_f s_f\left|c_{j,f}-(A^\top y+E^\top z)_f\right|.
\]

这是原独立检查器使用的弱对偶下界，不是新归约。若两份对偶属于同一约束行序和因子框架，
它们的中点仍满足符号约束，可以分别作为两个端点的候选。目标、偏置、全部补偿项和因子尺度
仍从各自原始绑定系数重算；不混合两条已报告下界，也不把两目标的性质系数当作相同。

同一目标的 \(L_j\) 对对偶变量是凹函数，但这**不保证**中点优于该目标原有 best。
尤其不能用另一端点的下界代替本目标对另一份对偶的评价。强制所有端点始终共用一个对偶
反而限制搜索空间，此处只试一个最后候选。

一个手算例子说明残差抵消的可能性，而不是实际优化轨迹或实验结果：
取 \(x\in[-1,1]\)、\(-x\le0\)，两个目标为 \(1/2+x\) 和 \(1/2+2x\)。
对偶下界为 \(L_c(y)=1/2-|c+y|\)。若原候选分别为 \(-1/4,-2\)，其下界为
\(-1/4,1/2\)；中点 \(-9/8\) 给出 \(3/8,-3/8\)，逐目标保留较好值后两者均正。
若原候选已经为 \(-1,-2\)，它们各得 \(1/2\)，中点却只得 0。
这些等式既不证明当前 128 步会产生所需候选，也不证明完整 MoE 或路由变化实例安全。

原生浮点评价只选择候选；最终仍对原系数执行完整精确检查。浮点中点可能舍入、溢出或
下溢，必须保留有限性、符号、位数、残差补偿及接受门。本臂的浮点 best 不等于精确 best，
更不保证支配原算法被替换的最后一次梯度更新。全部 gain、loss 和非正／不完整结果须保留。

## 绑定和成本边界

两端点必须属于同一请求、source／forest、pair、竞争类别、因子框架、约束行序、方法配置
和 live tile。先读取并复制两份 best，再写入两列，避免更新第一列污染第二列。
错误 mate、重复 slot、跨 pair／性质／请求交换、失效 roots 或 alias 污染均不能降级为接受。
不改原完整计划、全部合法路由义务、zero 角色及独立检查／搬迁／接收合同。

中点混合增加行访问、临时列和绑定检查；相应成本全部计费。若替代最后更新时省去一次
不再需要的 forward，也要与强参考如实分列，不能称评价次数相同就成本相同。
新增临时量需要进入现有对象寿命账本，不创建新监督器，也不默认扩大任何槽或额度。

实施与运行前必须另行冻结方法身份、具体来源／故障清单、两臂次数和总成本上界。
当前没有实施授权或执行冻结；旧三来源 CPU 批次与本次两 factor 批次的批准不能挪用。
300 秒、8M Work、128 MiB 制品及全部原门保持不变，不运行真实模型或 GPU。

## 完整八专家对象仍不能准入

这个搜索假设发生在来源检查之后，不能消除已有准入拒绝。按当前入口重新区分原因：

| 入口 | 当前源码能确定的拒绝 | 不能混用的解释 |
| --- | --- | --- |
| Shared 及当前 native 两臂 | 首个 Snapshot 已需至少 13,926,024 Work；展开 membership 也超限 | 不是把离线检查误加进在线预算 |
| Direct | 展开 membership 超限；完整在线构造与来源检查仍至少需 2P Work，含权重访问和逐输出必需算术 | 不经过 Shared Snapshot，不能引用其双扫描过程 |
| Wire 搬迁表示 | 展开 `rc` 门仍为 65,536 | 不是当前 native 两臂的可运行替代，也不能套 Snapshot 原因 |

[注册形状](hz_model_scaled_resources_20261013.md)有
\(P=6,684,672+273,408+3,288=6,961,368\) 个仿射权重与偏置、\(A=3,288\) 行。
[Snapshot](../scoped_source/shared_source.py)逐行收取一次 row visit、每个值一次 packing visit，
随后 `PackedRow` 对同一批值完整有限性扫描，因此**仅首个 Snapshot** 的条件完整遍历下界为

\[
2P+A=13,926,024>8,000,000.
\]

[Shared build](../scoped_source/shared_build.py)先执行此 Snapshot，尚未进入来源独立重算
就不能完成。它是从源码得到的必需访问下界，不是运行后计数或完整成本上界；旧的
\(2P=13,922,736\) 仍是有效较弱下界，旧结果不修改。

[Shared 编解码](../scoped_source/shared_format.py)在序列去重前后都按展开 membership
检查上限。注册形状至少 126,632 条 membership，不是 126,632 个唯一节点；
[Direct](../scoped_source/direct_source_format.py) 与 [Wire](../scoped_source/wire_forest.py)
也保留对应门。零权重、相同尺度和候选稀疏度不能消除这些无条件形状项。
local nnz、引用边、active factors 和候选字节的超限上界则仍不证明实际对象必超限。

[在线协议](../scoped_source/native_protocol.py)的 `restore` 与 `validate_receipt`
继承并核对累计 Work；[V2 supervisor](../scoped_source/native_resource_supervised.py)同样如此。
另行调用的[搬迁 CLI](../scoped_source/native_portable.py)可有自己的检查预算并明确
`online_acceptance=False`，不能用它补成在线成功，也不能误算成另一个在线请求的耗费。
[V2 profile](../scoped_source/native_resource_protocol.py)还限定固定合成声明，未开放真实来源。

完整形状若继续，需来源／guard 表示与独立资源政策的明确决策；不能清零计数、把必要检查
挪为免费离线工作或把展开 membership 改名为唯一 root 绕过门。
[已采纳的原生硬限额合同](hz_resource_contract_adoption_20261017.md)不豁免项目自有 Work。
本次不提出新额度，不重试已经静态拒绝的对象。

## 继续或停止

当前只保留上述一个算法假设，停止继续生命周期控制及容量包装。它尚不能支持 G1、完整
输出新增证书、GPU 收益或外部优势。通用对偶凸组合本身也不是原创理论；研究价值须由
同一 MoE 义务上的实际增量与直接消融证明。

若单独批准后续实施，先默认关闭实现并形成有限控制协议；未冻结前不执行。
只有固定评价次数下出现经精确检查的下界或完整义务增量，且完整成本与丢失结果可接受，
才值得提出下一阶段。若仅浮点 surrogate 改善、精确结果无增益，或损失最后梯度更新的
收益而无净收益，就停止这个机制，不追加比例、迭代、候选或样本搜索。
小源通过仍不能替代完整来源准入及完整请求证据；两条门分别保持 OPEN。

本阶段只核对源码、算术和文档；没有加载模型、生成来源、运行原生候选或测试。
只读 AI 复核不替代独立人类技术审阅。下一实施、控制或资源调整均需相应明确批准。

静态校验已核对方法循环、手算等式、19 个本地链接及 169 份原冻结文件，文件 hash 全部
未变。两项只读复核分别检查数学与资源／授权；Direct 的下界计量已明确为 Work 而不是
全为参数访问。这里只新增三份文档的内容，不修改生产代码或既有结果。
