## 具体兼容性原因

绑定解释器为既有 `act-py312` 的 conda-forge Python 3.12.12。
`os.pidfd_open` 与 `signal.pidfd_send_signal` 均未暴露，相关 sysconfig 字段均为 `null`。
核对只读取属性与系统信息，没有发送信号或测试其他用户进程。
内核版本 6.14.0-1020-oem、glibc 2.39 不单独证明当前进程有可用接口或系统调用权限。

此前静态检查核对了 pidfd 清理逻辑，却未在运行前核对该解释器实际暴露的两个 API。
这是执行兼容性检查缺口，不是原生候选、松弛精度、Work 额度或算法创新失败。
源码中的能力拒绝发生在 `admission()`、`root.mkdir()` 与 `owned_session()` 之前；
[独立只读审计](../scripts/audit_endpoint_v4_early_rejection.py)按冻结源码顺序和原始 hash 核对此事实。
没有启动受管 session，自然也没有替其他任务发送清理信号。
另一只读审阅代理独立复算了 stdout/envelope/caller hash、重跑保存记录审计并核对环境属性；
除本次审计自身耗时外，归档字段一致。这是 AI 记录复核，不替代独立人类技术审阅。

## 停止和下一项最小决策

依本次“运行失败即停”的授权，停止整个批次，不重新启动宿主，不换解释器/安装依赖，
不退化到按裸 PID/PGID 清理。endpoint 批次批准表已清空以消费这一次授权；native 的
历史 32 项身份、V4 冻结及旧失败保持。新冻结工具是历史准备步骤，不得自动重新激活表。

若继续，需要单独批准一个范围最小的 pidfd 兼容性实现与控制：优先检查既有环境能否
通过本地封闭适配调用同一 pidfd 机制，保持打开句柄后核对归属、无裸 PID 回退、所有
资源/截止/接受门不变；不新增监督层、不全局 monkeypatch、不换模型或 GPU。
可用性、归属/句柄生命周期与截止控制通过后，才重新冻结尚未执行的有限批次。
本轮不实施该适配，也不把旧授权自动恢复为另一轮尝试。

已有研究假设与数学合同不变。本阶段只闭合执行失败的可追溯记录，G1–G6仍 OPEN；
不能称为 HybridZ 算法收益、完整证书、外部领先或 GPU 成功。
