# Direct source and portable consumer control results

The default-off direct-source connection passes **108 controls and regressions**.
It constructs a new source identity without old forest JSON, independently
checks the source enclosure, consumes typed candidate frames through the
pair-scoped Driver, then independently replays the complete package using the
same online Work and deadline. No real model, native optimizer or GPU ran.

The [protocol](hz_direct_join_protocol_20261015.md) was committed and pushed as
`485307a934a3cc40690c85662d39ab63f692485e` before implementation. The
[machine record](hz_direct_join_controls_20261015.json) binds the code and test
files and retains phase costs, cumulative counts, exact-result hashes and the
separate relocation audit. This is a finite interface control, not full-topology
admission or an algorithm speedup result.

## Connected interfaces

- [Direct builder](../scoped_source/direct_source_build.py): the existing V3
  source equations now dispatch to a new terminal encoder. The historical JSON
  serializer remains the default. No old forest document is produced or decoded
  by the new path.
- [Direct format](../scoped_source/direct_source_format.py): unique whole roots,
  ordered membership indices, explicit binary64 coefficients and scales. An
  immutable root bank is checked once and charged; memberships retain all their
  checks and the original 65,536-use ceiling.
- [Independent checker](../scoped_source/check_direct_source.py): new bounded
  intake plus the existing independent input/affine/ReLU/guard equations. It
  never calls the producer. Checked types and cumulative Work remain closed;
  terminal source reseal rejects mutated manifests/chunks.
- [Execution connection](../scoped_source/direct_execution.py): fixed-candidate
  callbacks publish before exact acceptance; candidate width eight and checking
  block width two. Fresh portable replay uses the **same Work object**, not a
  new eight-million-visit allowance.
- [Portable entry](../scoped_source/direct_package.py): complete source,
  contract, code inventory and ordered typed frames. It calls Driver.receive
  directly, without expanding candidate JSON or trusting stored online bounds.

Entry points require `enabled=True`; the portable CLI requires
`--enable-direct`. Old defaults and all numerical/resource gates are unchanged.

## Differential and fault results

Four frozen synthetic sources, two candidate profiles and **164 proposed/zero
bound checks** agree exactly with the legacy Session, dense Driver and expanded
scalar oracle. New source identities imply new query/slot IDs; old frames are
explicitly rejected rather than reused under their old identity. Complete
outcomes agree, including UNKNOWN cases.

The 108 tests comprise 20 direct-join tests and 88 existing consumer, wire,
archive, navigation and historical-binding regressions. New controls include
rehashed semantic mutations; immutable sources and memberships; source pollution
at terminal; missing/duplicate/reordered/foreign obligations; later-block
exceptions; publication failures; inherited Work exhaustion; deadlines in source,
candidate, replay and reception phases; cleanup errors; and altered/symlink
packages. Cleanup errors retain the original failure and cost record.

The [first control result](hz_direct_join_first_control_20261015.json) remains
visible: one test incorrectly required Work to increase after portable replay.
Subsequent hashing/reception can consume wall time without adding logical Work
visits. The repaired test requires nondecreasing cumulative Work, positive replay
phase work and exact phase reconciliation, including pre-existing consumption.
No production check or acceptance threshold was loosened.

Code review also removed repeated full-root-bank validation from every view
and marked durable terminal proposals `PENDING_RECEPTION`. A written proposal
is never itself a received success. Late reception or cleanup causes the
execution return to remain TIMEOUT/ERROR with `terminal_received=False`.

Source/control preparation before the online request is not presented as live

The copied-package audit uses `python -I -S -B` with an audit hook denying the
original source and repository. It imports neither the source producer nor
Torch, NumPy or SciPy. Its complete result matches. Copying, child startup,
checking, logs and reception are separately recorded offline; they cannot
rescue an online failure. Trusted launcher/checker code remains a trust root;
packaged code self-hashes are not an independent proof of checker correctness.

## Remaining boundaries and next gate

This synchronous connection enforces a **cooperative** deadline around the
trusted fixed stub and internal checks. It does not interrupt an arbitrarily
blocking callback. Existing process-group controls remain tested separately;
the new path is **not yet integrated with a complete outer hard supervisor**.
Its received return is authoritative for these controls; a standalone pending
terminal file cannot establish online success.

The builder still retains its graph before encoding. It does not implement
first-affine tensor aliases, bounded streaming construction or a restricted
live-checkpoint parser. The source format requires exactly binary64-encodable
reference coefficients; a V3 aggregate reference outside that domain is
conservatively refused, never rounded. General-rational *candidates* remain
supported under the existing bit limits. Thus the source format is not claimed
to losslessly admit every valid V3 forest or inherit the earlier 96.8 MB design.

Next reconcile **this implementation** with the source/consumer/replay cost and
lifetime ledger, including refusal domains and unchanged membership limits.
Do not rerun full topology or infer a new quota from these small timings. A
hard-supervisor connection, native proposals, full-capacity admission and any
real/GPU experiment need their own scoped gates. G1–G6 and historical scientific
claims remain unchanged.
