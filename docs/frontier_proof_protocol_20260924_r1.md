# Real checked-frontier proof integration / bounded freeze R1

## Decision and frozen boundary

Integrate the already controlled `checked_route_frontier` mechanism into a
separately versioned real-intake supervisor. This stage tests synthetic controls
and **freezes only**, without loading a real model/tensor or executing real
requests. No production gate, output relaxation, native proposer, cache or 25%
scheduler change. Old inputs 98, 4088, 4096, failed attempts and historical 23
source-gap gains remain sealed. No statement of external superiority follows.

Supported declared graph: eval, CPU/float64 source capture, Linear/ReLU/Flatten,
selected-softmax top-2, all tie-legal unordered pairs. This is the existing MLP
family, not a newly supported convolution/BN model or high-accuracy experiment.

## Full-budget pipeline and independent reception

Both arms reuse the original checkpoint/input intake and native LP dual
proposer. A single monotonic deadline starts before request publication. Imports,
file hashing, loading, capture, route evidence, propagation, construction,
source checks, LPs, rational aggregation, serialization, receipts and owned
process cleanup are charged. Each request has 300 seconds, 2 CPU threads and a
sampled 8 GiB process-group-plus-supervisor RSS ceiling; these are unchanged.
The 2-second publication reserve is INSIDE 300. The final ledger write is
measured immediately afterward; overrun invalidates acceptance. Later saved-only
audit is separately timed and not advertised as free online checking. Every
online source/router/output check is charged.

Exhaustive: intake -> original construction -> original source check ->
original LP proposals -> original exact aggregation.

Checked frontier: intake -> fixed final-affine router dual proposals -> fresh
independent route check -> lazy retained construction -> fresh source check ->
original LP proposals on retained duties -> fresh exact full-roster aggregation.

Route candidates are atomic, source/prefix/request/invocation/direction-bound
files. All E(E-1) fixed candidates and their completion receipt are required
before continuing. A route-proposal/check timeout or exception stops the request;
saved partial candidates remain inspectable, never justify an execution plan.
Only an independently checked strictly positive whole-domain outsider-minus-
insider bound discharges a pair. Zero, missing and nonpositive bounds retain it.
The constructor rechecks received route evidence before omitting any expert.
The final independent checker rechecks source, all route exclusions, retained
construction and all output bounds. No checker parsing cache is enabled.

Original global pair/property indices are retained, including gaps. For each
of the original duties, the ledger must contain a checked route exclusion or
a strictly positive exact residual-corrected output LP bound. A manifest alone,
infeasible solver status, negative bound, missing candidate, late positive or
partial invocation never establishes a complete proof. Failed output proposal
phases may be followed by partial evidence inspection; they cannot be promoted.
Checkers run with `python -S`, without model/solver/producer imports.

The proposal phase receives half the actual remaining work time, leaving time
for exact aggregation. One lexicographic native LP attempt per retained output
duty receives an equal share of that phase's actual remaining time. No added
query, retry, iterative router search, reordering or deadline renewal.

Important baseline limitation: the unchanged exhaustive proposer can return
NO_CANDIDATE for an infeasible guarded LP; it has no independently checked
Farkas/infeasibility path. The new checked router exclusions can therefore
increase logical completion as well as reduce construction work. This is the
registered mechanism, NOT a pure caching/speed ablation. Report this distinction.
Retained source/join/guard/output matrices must equal the exhaustive originals.

## Controls before freeze

Synthetic real-checkpoint intake and native LPs test prunable and all-tied
models, exact retained-matrix/source differential, original-index gaps,
nonpositive outputs, wrong source/property/run bindings, dropped/extra/partial
route and output files, inherited exact arithmetic controls, owned-child
deadline cleanup, exceptions, RSS refusal, late positives, publication overrun,
batch denominator and complete cost accounting. No real asset decode/inference.
Control logs and source hashes are archived before a clean implementation
commit. Freeze and independent stdlib review then precede any real execution.

## Guarantee contract

Positive means `CHECKED_DECLARED_REAL_GRAPH_REQUEST`: all relevant source
enclosures, inherited factor/guard relations, McCormick construction, strict
router exclusions and residual-corrected bounds have been checked for the
declared real graph and rational input region. Trusted: intended program equals
the declared graph, stored center is the intended preprocessing, checker/runtime.
Not proved: native deployed floating-point execution, literal route flip, all
architectures or stable advantage over external tools. Production numerical
acceptance and historical result labels remain unchanged.
