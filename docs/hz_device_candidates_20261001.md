# HybridZ 设备候选内核：CPU 参考与故障控制

2026-10-01；本阶段完成设备可选实现及 CPU 控制，**没有执行 CUDA**，没有新增真实
请求或完整 MoE 证书。算法／GPU 六门仍为 OPEN。本阶段不能支持任何 GPU 加速结论。

## 冻结与实现

[先行协议](hz_device_candidates_design_20261001.md)于提交 `875c801bc` 冻结；
[配置](../configs/hz_device_candidates_20261001.json)的 SHA-256 为
`90ff1dc2ce9c20cf6b3bae19c04c7743ce1783fdc1b5b628603362681fbaa386`。

[新内核](../act/back_end/moe/batched_support_device.py)保留 V1 的 128 次投影更新、
步长、零初值、逐目标最佳候选与精确零乘子兜底，只参数化设备。多个目标共享给定
guarded SparseHZono 的稀疏矩阵；专家私有因子不合并，二元列明确连续松弛。
GPU 仅提出乘子；CPU 用原始绑定系数重算精确残差和界，原独立检查器与接受规则不改。
这是给定 HZ 的支持算法接口，不是已完成生产传播集成或新通用抽象域。

CUDA 入口只接受新进程中的显式 cuda:0、外部锚定的 batch／截止／UUID 上下文，
并要求可见设备身份一致。初始化、传输、计算、回传后同步；缺列、非有限值、
OOM、同步错误或晚到候选拒绝，不静默切换 CPU／dtype，不以旧 best 伪装完整成功。
1 GiB allocator 限额不是设备或上下文的 OS 硬配额；身份上下文也不是资源预约。

## 已执行的控制

[独立归档复核](hz_device_candidates_20261001_r3.json)为 PASS：

| 组 | 结果 | 范围 |
|---|---|---|

| 原 CPU 支持回归 | 16/16，独立复核通过 | 原矩阵／精确检查合同不变 |
| 逐行精确核回归 | 15/15 | 75 个旧 LP、72 个旧对偶与 3 个盒事实；没有新增求解 |
| 工程导航／交接回归 | 9/9、4/4 | 619 个冻结来源和 4,632 行历史保持不变 |

六个固定 HZ 批次共 18 个目标，V1/V2 的候选和精确界一致；审计分别检查两个版本
的全部目标，共 36 次界核验。六个来源由固定 fixture 独立重建身份，不能仅以文件
自报 hash 或标签充数。负控制仍非正，独立二元差仍为 [-2,2]；常数为 1/4。
零宽控制来自约束，不是偷偷缩窄导出的因子盒。这些不是 18 个 MoE SAFE。

测试覆盖上下界、offset、空约束、换序、单列、多列、默认设备污染、错误上下文、
来源／目标污染、符号与 claim 篡改、缺列、NaN/Inf、溢出、超时、3/4 部分证据。
初始化异常、OOM、同步异常和回传后截止均为明确标记的 **stub**；不能据此声称
真实 CUDA 稀疏算子、空矩阵、显存限制或 GPU 故障处理已经验证。

审计还核对故障记录的种类与数量、固定来源、完整测试清单、零跳过、执行设备和
成本字段。数学检查器本身只检查系数与界；硬件和执行元数据另由归档审计核查。
未发现本阶段阻断性代码问题；逐轮 Python 布尔判断可能触发 GPU 同步，实际成本待测。
另一路只读审阅确认先前归档清单与来源绑定问题已关闭；它不是独立人类审阅。
