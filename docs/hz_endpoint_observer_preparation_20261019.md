## 可信调用者与计时边界

[外层接口](../scoped_source/endpoint_batch_observer.py)由已运行的可信调用者使用。
`execute()` 在函数入口取得起点，随后验权、检查代码、单次资源观察、创建目录、
启动新解释器及全部受管工作。它不把自身解释器启动算成已计费；若采用新启动的 CLI，
必须另有更早的可信起点，不能使用旧脚本内导入后的计时替代。

| 边界 | 相对整批入口 | 含义 |
| --- | ---: | --- |
| 批次 worker 截止 | 2098 秒 | 启动、加载、七位置及批次摘要写读 |
| session 清理截止 | 2098.5 秒 | 仅清理本批进程并回收直接子 leader |
| 接收截止 | 2100 秒 | 外层摘要接收、终态写读及可信调用者的实际返回观察 |

各位置仍为 run 298、cleanup 298.5、native receive 299、完整接收 300 秒。
剩余不足完整位置时不启动；原 2 秒预留现在属于整批外层收尾，不是额外给 worker
另一份 2 秒。worker 末次摘要若写不完则拒绝，不能延长预算。单次准入最多 60 秒，
包含在 2100 秒内，同时保留分项时长；无等待队列、重试或升限。

`execute()` 返回的是 **proposal，不是实际返回已被接收的证据**。可信调用者必须在
函数真正返回之后调用 `observe_return(proposal)`，用相同单调时钟观察接收。实际调用顺序为：

```python
proposal = execute(root, freeze_path, expected, enabled=True)
caller_anchor = observe_return(proposal)
```

这只是待冻结的调用约定，不是本轮执行记录。接收者保留该值并提供其预期 hash；不能从
批次文件事后制造缺失锚。接收锚是在线内存接收事件，后续外部归档的成本需另列，不能
把晚到或没有在线接收的批次改为成功。若执行协议要求在线持久化接收者日志，其写读也
必须在同一预算内，不能将本接口当作那项持久化已完成。

离线审计只有磁盘文件时最多返回 `CONSISTENT_PENDING_CALLER_OBSERVATION`；有可信
接收锚时才可能为 `PASS_TRUSTED_CALLER_OBSERVATION`。hash 仅绑定数据完整性，不认证
任意第三方自写的时间。时钟、OS、冻结调用者及执行代码仍属于可信基础。

## 会话与失败处理

[session owner](../scoped_proof/owned_session.py)创建整批 session。每个请求仍有独立
进程组，但不离开该 session；native/component invocation、组回执、位置与批次摘要
绑定同一个 SID。旧 `owned_bounded` 默认模式和返回结构不增加字段。

外层在清理结束前保持直接子 leader 未回收。发现的后代先打开 pidfd、再核对 SID，
仅经 pidfd 发信号；直接子 leader 的 pidfd 也能处理其尚未完成 setsid 的启动竞争。
没有裸 PID 扫描后杀进程、没有其他用户任务操作；pidfd 不支持、观察失败或清理未完成
均拒绝接受。受信任子进程不得逃离 session；不声称回收所有孤儿 zombie 或 GPU 驱动资源。

worker 正常失败返回非零时，外层仍可在原截止内读取已落盘的失败前缀和未执行后缀，
但不接受成功。缺失摘要、部分文件、清理未完成或超时记录为不完整；不补写成功、不重试。
负向调用者锚也能被审计并报告实际观测耗时，不因结果失败而丢弃接收记录。

## 成本与存储

四个批次文件仍为 `freeze.json`、`admission.json`、`batch.json`、`batch-received.json`。
前两个由外层写，第三个由 worker 写，第四个仅在外层观察退出及清理后写。
逐名上限为 128 KiB、1 MiB、1 MiB、64 KiB，合计 **2,293,760 字节**，
小于已有 4 MiB、四成员预留。没有新增磁盘日志；最多 16 KiB pipe 输出嵌入终态。
输出超限明确失败，区分观察字节与已保留日志，不伪装成完整日志。

每请求仍在原 128 MiB、4096 文件内；原生位置元数据为 7,798,784 字节／14 文件，
组件为 6,619,136 字节／10 文件，均在已有 8 MiB／16 文件预留内。Work 仍为 8M。
预期故障没有完整剩余 Work，接收锚明确 `all_work_complete=False`；
“接收到了批次摘要”不能被写成“全部 Work 都已观测”。

共同驻留对象增加了外层 freeze/launch/摘要、最多 16 KiB pipe 缓冲及最多 512 项
session 清单；完整终态受 64 KiB 拒绝门约束。所有受管进程仍为 8 GiB AS，调用者也
收紧至该上限，若已有更低限制则拒绝而不是抬高。执行时采样整个 SID 加外层 caller
的 RSS，超过 2 GiB 即停止，不叠加各内层峰值。接收阶段只有调用者 AS 和原截止门，
不是持续 RSS 采样或总 heap 证明。OS 延迟导致实际超时会拒绝并保留，不承诺物理强实时。
