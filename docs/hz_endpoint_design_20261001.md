# 加权端点接入共享 HybridZ 的控制合同

本阶段将 H2 的端点恒等式接到实际 `SparseHZono` 的共享专家 pair 与多目标支持接口。
它改变加权输出义务的表示，不同时改变候选优化、预算、guard 或 gate 精度。
[协议](../configs/hz_endpoint_controls_20261001.json)先于实现和执行冻结。
只允许有限 CPU 合成控制，不加载模型、数据，不使用原生求解器或 CUDA。

## 数学对象与独立接收

对同一 guarded pair 域 P，沿用
[端点恒等式](../act/back_end/moe/proofs/gate_interval_endpoint_support.md)。
将 `qᵀB+c+t qᵀ(A-B)` 构造成联合输出上的有理数目标：A 的行系数为 t q，
B 的行系数为 (1-t)q，常数只加一次。再交原批量支持器对存储 HZ 精确投影。
不先用浮点 `sparse_hz_linear` 合成标量目标；不借旧矩阵的正界。

使用原 `shared_input_pair_hz` 合并专家。共享连续／二元前缀各保留一份，
两个专家新增的因子放入不同私有块；保留全部共有和新增等式、不等式。
新检查器不调用该合并器或端点 builder，按原始三个 HZ 的序列化系数逐项重建
列映射、共享前缀和输出行，再检查每个端点投影与精确下界。
frame id 相同本身不是因子来源证明；前缀相等仍不证明网络传播正确。

调用方绑定专家数、类别维度、性质列表、上下文及每个 pair 的 entry/专家 HZ/gate。
本版保留全部无序二元组合，包括不可行 pair，不接受未证实的路由排除。
每条性质的两个端点均为义务；仅当两个权重精确相同才共用一条查询，仍记录两端
覆盖。性质缺失、pair 缺失、方向或源替换不能接收。非正界和部分证据保持 UNKNOWN。

结果仅为 `CHECKED_POSITIVE_GIVEN_GUARDED_HZ_AND_GATE`：仍信任网络到给定 HZ、
guard lowering、专家语义及 gate 区间覆盖。它不是来源完整的 MoE SAFE，亦不证明
原生浮点执行。每次调用共享至多 300 秒合作式 deadline，硬监督仍需单独接入。

## 固定对照与诊断

三专家控制沿用既有解析结构但使用精确二进制常数 3/32，构造新的 HZ 和新证据。
两个专家的 ReLU 三角变量保持私有，不将它们合并成同一激活。三组 pair 全部保留；
x=-1、-1/2、1 分别检查路由及 tie 覆盖。注册 gate 范围来自解析分数顺序，
通用接口仍以 supplied gate 为前提。

第一条对照固定同一 P/gate/性质：端点目标对比 range-only McCormick。
独立精确检查同一基域上的负可行 MC 点；它不是原网络反例，也不代表 LP 最优值。
解析对偶证据与固定 128 步候选分别报告；后者弱时不调参，不把数学表示收益
冒充候选器已完成正证明。

第二条对照固定 A=x+1/4、B=-x+1/4、gate=1/2，比较共享输入与原有独立乘积
外包络。两臂各自产生新证据，不把独立路径误标为保留关系。
其余控制覆盖不同输出维度、非二进制有理性质、固定 gate、[0,1] 退化、
专家方向交换、私有连续与二元列、错误绑定、遗漏、非法候选、截止和异常。

## 停止与下一门

完整保留第一次失败和来源快照；不换例、不增迭代、不放宽阈值追正。
控制通过才考虑单独的完整预算监督，不直接启动真实或全尺寸比较。
本阶段不会关闭 G1 至 G6，也不改变既有生产默认入口或数值接受策略。
