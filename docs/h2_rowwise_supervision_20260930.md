## 新版本只改变检查核与执行身份

[协议](../configs/h2_rowwise_supervision_20260930.json)保留原来的四个声明来源
和同一固定合成模型对象、endpoint／McCormick 两臂、64 字节控制分块、全部 pair
及性质、复用规则和 `1/10000000` 接受阈值。普通控制 30 秒，延迟控制 6 秒，
最终发布控制 5 秒，另有启动前截止；接口上限仍为 300 秒。不得把控制预算误写成
已经验证全尺寸模型能在 300 秒完成。

[新 worker](../scoped_source/rowwise_worker.py)复用旧 `factored_build.build()`，
只通过固定 proposer 入口调用 `rowwise_native.propose(lp, deadline=phase_deadline)`。
旧构造器给出的相对时间提示不能延长截止；额外 solver 参数被拒绝。保留两处隔离
副本，不同时研究别名共享。新候选提议仍要求原生成功，并经过精确检查才返回。

[独立来源检查器](../scoped_source/rowwise_check.py)保留旧函数的全部来源、仿射、
ReLU、私有因子、guard、gate、性质、复用与覆盖重建。除两个下界调用传入同一
deadline 外，函数体的 AST 与旧版相同；新核导入是固定代码，不是配置可注入函数。
运行控制还逐条记录检查调用收到的截止，并将同一证据交给旧检查器核对完整结果。

[可搬迁入口](../scoped_source/rowwise_verify.py)只增加精确检查核，不携带原生
proposer 或 SciPy；旧间接依赖仍打包。[发布器](../scoped_source/rowwise_portable.py)
和[监督器](../scoped_source/rowwise_supervised.py)采用新的 `HR_*` 外层 schema、
代码清单和协议身份。内层来源／证明 schema 不变，因为数学义务没有变化。
没有修改任何旧冻结模块，未用全局 monkeypatch 替换生产检查器。

## 完整预算与接收规则

计时从监督 API 入口开始，包含模型创建与捕获或声明来源创建、分块、来源重建、
候选生成和保存、bundle 发布、独立检查、接收、进程清理与最终发布。每个阶段沿用
同一个请求派生的绝对截止。事件日志中的嵌套操作用于解释阶段，不与阶段耗时再相加。

父进程预先绑定 producer/checker 源码，在独立检查进程退出后锚定实际 stdout 的
原始字节哈希。接收器不能用自己改写的摘要冒充正结论。最终发布超时覆盖先前的
positive；单有完整文件不证明调用完成，还须外部观察到完整 API 返回。
进程组清理仅限本次所属进程，不影响其他用户或控制中的独立 sentinel。

搬迁控制把 bundle 复制到新路径并暂时隐藏原 bundle，在 `python -I -S` 下检查。
读策略拒绝原仓库、模型、求解器、外部执行和写入；它是受审计的读取约束，不是
抵御任意恶意 Python 代码的操作系统沙箱。

## 容量门仍未通过

当前只证明新核能在固定小型请求的完整监督中工作。MC 重建、共同证书构造、pair
组装、隔离副本、完整 JSON 身份序列化和原生工作区仍可能产生大对象；逐行核不能
消除这些成本。不得从两行临时对象或本轮控制耗时推断全尺寸 RAM／时间可行性。

下一项单独固定与登记架构形状一致的合成容量控制：覆盖创建、捕获、分块、构造、
提议、独立检查及终态；记录实际停点、大小与资源，而不按正界选择对象。先完成该
协议及准入控制，再判断是否有依据另提真实实验。已存在的默认分块策略与旧 64 字节
控制协议须分开，不通过调大限制掩盖失败，也不继续无限扩展静态表。

封存的真实输入、旧 holdout、H1 稠密剪枝和后端搜索不动；没有新增外部比较成绩。
本阶段不解决 MetaMoE top-1、高准确率跨家族或人类独立审阅目标。
