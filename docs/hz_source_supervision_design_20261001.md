## One execution budget

Reuse `scoped_proof.device_lifecycle` and its bounded owned-process executor
without changing them. The phases remain admit, produce, release, check, receive.
Normal calls have a 30-second control budget, fault calls the registered 8/10/30
seconds, with maximum API admission 300 seconds. No stage receives a new budget.
The unchanged inherited producer cutoff reserves min(5 seconds, budget/4)
after production; the short fault budgets therefore reserve 2 or 2.5 seconds.
This clarification was committed before any execution; it changes no formula.
Source construction, imports, input enclosure, router and expert propagation,
entry/guard construction, endpoint preparation, proposals, serialization,
independent checking, reception and cleanup all occur inside this clock.

The producer runs source creation and every numerical operation in an owned
process. Parent-side receipt checks remain bounded hash/schema/inventory work;
they must not rerun propagation, create a source fixture or call the complete
mathematical checker outside an owned checker process. Admit/release/receive
workers use `python -S`, so numerical imports must be deferred to produce/check.
Parent work, startup, publication and observed API return are charged as well.
Filesystem/OS stalls and escaped processes are not claimed machine-verified.

## Two distinct kinds of partial evidence

Publish the source declaration first, then append-only lowering snapshots after
input, router and each completed pair. These are diagnostic prefixes: a checked
input/router prefix is not an output proof. Prefixes must retain immutable
earlier components, exact source identity and canonical pair order. An interrupted
expert operation retains its open cost event, not an invented complete trace.

Once all source traces and the endpoint request exist, publish a complete-source
package with every pair present and null candidate records. Append a new package
after each completed candidate batch. Prior candidates may not change, and
unproved pairs remain explicit. A completed execution with missing/nonpositive
evidence is UNKNOWN, not failure-free SAFE. An offline recheck of a timeout prefix
never becomes online budget acceptance.

The mathematical checker reconstructs the full source/guard/gate/endpoint chain;
the receiver verifies the caller/source/package binding, every duty and count,
positive threshold and declared guarantee. Keep `declared_source_positive`
separate from execution completion, real-model completion and native-float SAFE.
Program/declaration correspondence and checker implementation remain assumptions.
The previous numerical pipeline is not retrospectively re-certified.
