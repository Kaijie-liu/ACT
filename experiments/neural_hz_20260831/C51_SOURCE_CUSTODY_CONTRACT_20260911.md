absolute star-import dependencies. Selected sources retain C50's equivalent

Hash-check source and run the fixed compiler BEFORE its module executes.
Retain immutable code plus an immutable receipt of source hash, compiler policy
and every recursive code image (including flags/constants/line/exception data).
The expected images are never taken from the loaded test module. Compile-source
custody replaces a second deterministic compilation of the same source/config;
it does not replace independent source/code authority by a previous test result.
Module bodies and all candidate/test calls still execute normally. Old pyc files
cannot mint this receipt. Reimporting a source under top-level/package names
reuses only its hash-checked immutable code, not its module state or outcomes.

At collection, check complete actual selected modules/helpers/fixtures against
that source-first receipt. Bind each selected item to its collected attribute,
actual definition source, declared import edge, module object and executing
globals. Fixture unwrapping uses the ordinary installed pytest fixture object
and its actual executing function. Imported library wrappers are not falsely
classified as test-source functions. Private frame-reflecting test sources
remain outside the cleanup scope and fail closed.

Multiple ordinary comprehensions/lambdas can share a line and qualname: retain
the full code image as part of the key instead of dropping images or rejecting
that source. A source may have distinct ordinary module namespaces; each actual
namespace is checked, not conflated by path. For repeated parametrized items,
retain the already verified immutable code object and check its current binding
and namespace rather than hash the same body again. A later code reassignment
is rejected. This is not an adversarial Python sandbox or a universal theorem
about arbitrary runtime reflection; it preserves the existing scoped test gate.
