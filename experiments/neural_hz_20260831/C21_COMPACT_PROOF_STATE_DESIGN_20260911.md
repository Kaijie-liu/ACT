# Next compact proof-state hypothesis after C21

Design only; no C22 source or target yet. C21 is CLOSED under its frozen full
entry gate, despite actual complete generation, mathematical and ownership
success. Never rerun it, swap to bytes-only accounting, release an external
oracle after the fact or retroactively increase its reference witness.

## Candidate direction: seal proof dependencies and compact consumed metadata

Audit actual readers of node support/needed/slots/exponents after complete
affine proof, and actual readers of both ownership vectors. Identify exactly
which data are runtime relations/witness lineage, which are needed to resolve
stable UIDs during future real ReLU append events, and which are construction-
only proof witnesses. Retiring a field requires replacing every later consumer
or proving it has finished, not renaming the data as metadata or hiding a copy.

One possible closed representation is the SAME HZ plus existing tagged alias
lineage, one ownership vector, and a compact stable-UID-to-physical-row index,
bound to a completed original-DAG proof receipt. Original input prefix,
all binary predicates, global IDs and exact alias extension remain unchanged.
The receipt must be produced by the actual independent checker, retain its
source/HZ/content binding, and reject mutation even if an outer object is
resealed. A boolean flag or self-generated unkeyed hash is not an independent
mathematical proof. Test that the full original check really happened before
any witness retirement. Preserve all original native caches and external
oracles; only NEW private generation/proof temporaries may have shorter lives.

Do not assume a UID index is free: a post-phase row table146637 entries would
consume most of the prospective gain, and merely copying the pre-phase table
already exceeds140566 work headroom. Inspect whether existing row-emission
labels can be emitted in compact retained form or their stable-UID runs can
be encoded exactly without an additional whole-array scan. This requires new
implementation/equivalence/resource evidence, not a lower price for C21 code.

A separate possible proof-state lifetime optimization is to verify appended
phase ownership through a reversible known-event transaction on ONE private
owner vector, then restore it exactly, instead of retaining a full copied
vector. Any such transaction needs pre-reserved apply/rollback work, precise
failure recovery, proof that no query sees an inconsistent state, and source/
HZ/ownership identity before and after. It must not use a completed archived
post-HZ as an algorithmic shortcut to a new native phase. Full independent
post-incidence proof is still required, with its diagnostic work charged.

For scale only, removing four node fields and ONE redundant owner copy while
adding a146637-entry UID table would make the old ledger's arithmetic52375683,
53117 below the fixed52428800 reference. This is NOT an implemented memory
result: certificates, additional owners, sharing, workspace and actual work
may invalidate it. The tiny margin requires complete ledger measurement and
content/proof preservation before launching another original-expression run.

## Boundary of any next experiment

First read-only consumer/ownership/source inspection and mathematical design,
then focused tests (including re-sealed corruption, reconstruction, mixed/native
phase events, rollback/caps and zero-copy alias ownership). Freeze a NEW version
before a fresh original-expression target. Keep every current physical and
logical cap, both complete oracles, original native snapshot and fixed two-leaf
reference gate. Failure closes that version. If a different comparison proof
or boundary is proposed instead, make that explicit before any run; it cannot
be smuggled in as C21 success or called a representation reduction.

No unit-splice/native-ReLU/live/terminal/wider replay is authorized merely by
this design. The eventual single-path full2413 and full400 retention/new-gain
requirements remain unchanged. Formal1870/2413, separate E061/400, gain0.
