# 相位关系在完整惰性读出中的谓词运输

本候选把D256证明的接入规则落实到生产使用的SparseHZAffineExpr类型：保留全部原读出与谓词，以严格零读出的HZ项携带D255增强关系，并在物化开始之前折叠这个零项的纯线性链。目标是让已证明的相位关系能被真正的联合读出及普通终端消费，而不是只在断开的局部HZ中成立。

这是定义研究的接入支撑，不是新集合类、已经完成的Neural-HZ定义创新或真实模型提分。默认关闭，仅在新的隔离实验目录实现。生产文件、冻结实验和历史结果不改动。

## 非凸语义及等价范围

原共同状态保留全部连续因子xi、signed binary beta、EQ/LE和完整decoder。登记的读出为Phi_j=bias_j+sum_t L_jt h_s。共同谓词P_live包含这些source的全部谓词，而不是任选最长source的谓词。

D255的Result来源于原局部S。其增强谓词P_S(v) AND C_S(v,u)对每个满足P_S的原整数相位赋值都有canonical辅助延拓，且保留所有原谓词和变量。只要P_live implies P_S，就有

~~~text
project_v { (v,u) : P_live(v) AND P_S(v) AND C_S(v,u) }
    = { v : P_live(v) }.
~~~

本次采用严格而可核验的充分条件：S是所登记views中实际可达的source对象，且其完整内容与Result的原snapshot一致，所有views处于同一已知共享frame。若capture曾把原S补到全frame高水位，认证时对原S作同样的零列补齐并支付复制/核查费用；原terms仍保留原S，不替换成临时副本。其他source可以有S没有的额外谓词，也可以仍是较早的较窄列宽；不要求反向蕴含或先把全部旧支路重新物化。仅有frame整数相同不证明来自同一个实际模型；本次使用受控的内存共享状态，完整在线来源认证尚未授予。

anchor读出为一维零、生成元为空，但保留Result.hz的全部谓词、原因子、原二元列以及新连续辅助。每个登记view都追加相应形状的零映射，原terms与bias不变。其精确对象是登记的完整联合状态，不声称每个原独立branch的更大局部集合都逐一相等。不同source的零读出不能成为删除或合并谓词的理由。

新辅助列必须从完整旧高水位开始。传入宽度与snapshot旧宽度不一致、其他source越过旧高水位或来源内容不一致均拒绝。本次返回完整的离线批次和新宽度，不修改HybridzTF分配器或部分发布cache。真实接入还须原子预约全frame列并更新全部必要live、skip、precomputed和decoder消费者；这个离线返回值不能冒充已完成在线事务。

## 物化前的结构规则

仅当source实际c逐项严格等于零、Gc和Gb结构为空时，才把整个已验证的纯线性链换为直接零CSR。原source对象、全部谓词、全部原相位和表达式bias都保留。非零存储读出即使在某些谓词下等于零，也不适用本规则；不使用近零阈值、LP状态、margin或模型身份。

支持类型是实际CSR及生产ImplicitConv2DOp，不接受任意ducktype算子。类型、有限数、形状、frame及源内容检查在零值判断前完成。未知算子、NaN/Inf、坏形状或资源失败不能借零乘法绕过。新函数不调用求解器，也不枚举或删除二元相位。

私有适配器复制tf_cnn模块内函数的代码对象及其模块全局查找环境，保留原表达式类和导入对象，在私有环境中以normalize后调用原物化函数的wrapper替换_lazy_materialize。当前checkpoint、selective、deferred及apply内部的相关调用均通过该私有全局名字查找，故经此适配器进入时会先规范化。原模块及HybridzTF的调用绑定不变；未通过该适配器进入的生产调用不在这项覆盖声明内。

适配器不进行失败后的原路径重试。它使用同一Budget，支出不退款，资源失败sticky。原代码可能捕获ValueError等异常，适配器返回前仍须检查Budget失败，不能把被内部捕获的资源失败当成功。

## 成本和所有权

设S为所访问source的完整存储项数，O为所访问CSR数据及索引和隐式kernel、mask、几何描述的大小，C为term与链引用数。组件必须支付完整来源检查、摘要、必要复制及元数据，不只支付最终零nnz。生成一个m维直接零CSR仍需m+1个row pointer。隐式几何重新验证若遍历空间位置及kernel或mask，必须支付这些实际遍历，不能仅按kernel驻留大小计费。

完整端到端成本仍为

~~~text
原模型读取及可靠bounds
+ 原传播与bias matvec
+ 相位出生及D255关系构造
+ 本次来源检查与anchor运输
+ 非零消费者的原组合、物化、谓词合并
+ 终端转换和查询
+ decoder、具体见证验证、证据与完整物理存储。
~~~

本次共享逻辑Budget覆盖新组件自己的检查、运输和规范化，及已计费的D255组件；不会因为复用生产函数就宣称其整个内部循环和allocator已经纳入该计数。所有原函数调用都包含在本次完整pytest墙钟内，但这不替代未来真实worker的完整work及物理账。规范化只省去零值链的不必要组合；共享prefix缓存已经省掉的工作不能重复记成收益，原bias传播仍付费。

输入是同步、单owner的受信内存对象，不是防恶意反序列化证书。source保持原对象身份并作内容复核；新anchor拥有独立只读数据。冻结dataclass本身不能冻结其数组或防止外部私有篡改。在线并发/GC/分配器完整生命周期不由本组件测试认证。

保持256M总work、200M单操作、64M累计entries和512-bit；真实三来源的一次40M evidence预付及全部原门不变。本次数学组件计数与真实worker账严格分开，不对原费用退款、不提高门。

## 尚未覆盖的目标

此规则不会自动让sparse_hz_fast_bounds读取新增谓词，也不会自动解决HybridzTF中lazy ASSERT drop或新增lazy Concat。测试使用真正物化后的HZ调用普通终端，而不是拿Result原局部终端冒充完整view已消费。数学上等价的零运输不证明实际网络能力、GPU加速或新定义的独立新颖性。

后续仍需固定三来源完整前缀、同结构shadow、逐家族及全2413回放、独立400回放和四并发不回退。正式1870/2413、独立CIFAR10025+TinyImageNet36=61/400均不变，不相加。GPU、smooth activation、Transformer及新家族目标继续保留。
