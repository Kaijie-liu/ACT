# 跨层幅值关系的全边冗余审查

本组件实现 D036 已证明的区间系数四条下界，并只检查充分冗余条件。输出的 UNRESOLVED 意味着这些条件未能证明冗余，不意味着严格增强、完整非冗余或真实验证收益。它不是新抽象域，也不改变原 HZ。

## 共同赋值和下界

每条真实原边的源为 q=ReLU(g)，原相位为 alpha；接收端 h=a*q+v，r=ReLU(h)。保留全部原连续源、原 bits、接收门、EQ/LE、frame 和 decoder。系数 a 属于认证区间 [alo,ahi]，残差 v 属于 [L,H]，q 属于 [0,Q]，且用于比较的松弛必须实际含有 q<=Q*alpha、r>=0、r>=h 和相应源界。整数语义中的 alpha 仍是原二元因子，分析松弛不授权替换它。

令 ell=max(0,L)、m=max(0,-H)，四条有效行是：

```text
R1  r     >= ell*(1-alpha)
R2  r     >= alo*q + L*alpha + ell*(1-alpha)
R3  r-h   >= m*(1-alpha)
R4  r-h   >= -ahi*q - H*alpha + m*(1-alpha)
```

在原整数 alpha=0 时 q=0，前两行由 r=ReLU(v) 推出；alpha=1 时前两行由 a>=alo、q>=0、v>=L 推出。后两行将同一论证应用于 r-h=ReLU(-h)。四行线性，因而对原带标签集合的凸包有效。g=0 时两种合法原 alpha 都保留；这里不通过挑选零点相位增强规则。

原网络仍使用实际 a，不改成 alo、ahi 或中点。区间端点只参与有效行的构造。相位和源身份在本次存档中可以核对到原端口及空间坐标，但尚未核对为生产查询中的具体相位列，因此实际 native 绑定资格始终为 false。

## 充分冗余条件

以下任一相应条件成立时，删除该候选行不会改变由上述比较前提定义的松弛：

```text
R1: L<=0，或 L+min(alo*Q,0)>=0。
R2: L>=0，或 alo*Q+L<=0。
R3: H>=0，或 H+max(ahi*Q,0)<=0。
R4: H<=0，或 -ahi*Q-H<=0。
```

R1 的 L<=0 情形直接是 r>=0；否则由 h>=alo*q+L 及 q<=Q*alpha 得 r>=L*(1-alpha)，条件中的剩余项非负。R2 在 L>=0 时退化为 r>=alo*q+L；L<0 且 alo<=0 时右侧非正；alo>0 时由 q<=Q*alpha 和 alo*Q+L<=0 得右侧非正。R3、R4 是对 -h 使用同一证明，系数区间成为 [-ahi,-alo]、残差界成为 [-H,-L]。

未被证明冗余的 R1 必有 L>0，R2 必有 L<0；R3 必有 H<0，R4 必有 H>0。同一边不能同时留下 R1/R2 或 R3/R4。留下 R2 需要 alo>0，留下 R4 需要 ahi<0，二者也不共存。结合 L<=H，每边最多两行，最多六个物理坐标非零项。单行计数依次为 2、3、3、4；这是假定 q、h、r、alpha 已是可用坐标的计数，不是原 latent 展开后的 nnz。

若 Q=0，所有四行被上述条件覆盖。稳定正源的原相位还可能提供其他冗余证明；本组件没有使用它们，因此未决计数只是保守上限。

## 残差界必须来自同一次拆项

对源前激活界 [li,ui]，先取 ReLU 区间 [max(0,li),max(0,ui)]。每个系数区间与该非负区间的乘积下界 ci_lo、上界 ci_hi 按四端点乘积的等价符号规则计算。总界为 bias_lo+sum(ci_lo)、bias_hi+sum(ci_hi)。第 i 边残差界只能取同一次总和减去同一 ci_lo、ci_hi，不能从另一个相关求界结果直接减去独立贡献。

所有 canonical 槽位都保留，包括 padding、零系数及稳定源。padding 的源区间是 [0,0]，不产生原 phase bit，其 mask 固定为零。对真实边仍逐一计算 Q、残差和四个冗余条件。

## 正控和本研究能回答的问题

[D036 原证明](../d036_descendant_amplitude_20260930/THEORY.md)给出普通两层 ReLU 正控：完整父凸包和以它为源的完整子门局部凸包仍允许物理输出 63/100，跨层幅值关系给出可达上界 3/5。该结果是已知 perspective 机制的结构实例，不是本次新发现或具体数据集 ADV。

同一证明也给出宽 fan-in 的充分全冗余条件。这次要测量的是在一个已完整保存的真实卷积块上，廉价独立残差界下还有多少行逃出上述冗余证明。若为零，停止将这个廉价版本作为该存档块的能力路线；若非零，只获得进一步研究的候选人口，不能据此判定实际生产查询更强。

## 成本与 GPU 边界

对 n 个 canonical 槽位，参考 kernel 的已预付保守界为 180*n+160 个标量及容器工作单位，不是 bit complexity 或墙钟时间。保留完整 Fraction 端点，最高 512 位；所有 source parsing、认证、证据及内存另计。接收行之间独立，内部为贡献归约及 all-but-one 计算，形式适合 GPU 批量归约，但目前只是 CPU 精确参考，没有设备实现或速度资格。

未来 native 编译还须支付原相位绑定、观察坐标定义、latent 展开、谓词转换、终端查询、设备与主机传输及见证重构。若每条边都保留，最多 2E 行、6E 个坐标非零项；若 q/h/r 没有现成坐标，这个上界不代表最终矩阵成本。不能将省掉候选行当作完整 GPU 验证加速。
