# 跨领域机制与 GPU 求解对 Neural-HZ 的启发

结论是应当跨出 HZ 文献圈，而且把域定义与 GPU 约束计算一起研究。但“借鉴”要落实为能证明、能比较、能付清成本的机制，不能把现成混合整数模型或 GPU 求解器换名为新抽象域。本轮最具体的收获是共同源投影的组合边界，以及终端 GPU 求解和证明验收之间的清晰接口。

这是面向项目作者的机制综述补充，不是穷尽式新颖性调查。较早的[跨领域综述](../../literature_cross_domain_20260929/REVIEW.md)及其[补充](../../literature_cross_domain_20260930_followup/REVIEW.md)已经覆盖 ImageStar、DeepPoly、控制理论、混合符号域、静态分析和消元。这里不把那些阅读重新记成新发现，而是解释它们怎样约束下一项定义研究。

## 文献已经改变了我们的数学问题

原先很自然的候选是：将共同源 `x` 投影成少量坐标 `t=R x`，只在 `t` 中表达多个激活，从而减少源复制。配套[推导](D019_PROJECTION_AND_FIBERS.md)给出四项明确结果。

第一，保留原 HZ 源、所有二元因子和守卫后，投影上的逐相位精确关系可以保持整个整数图精确。第二，即使投影上的凸包完全精确，接回原输入和残差仍不一定精确：普通二维盒的一个 ReLU 已经足以给出严格反例。第三，源在投影方向和剩余方向形成特定的乘积纤维时，凸包可以安全组合。第四，在所有非源约束只能通过 `R x` 观察输入的模型中，一个普通盒上单 ReLU 的完整保留输入凸包就可能要求 `R` 满列秩。

这些结果分别回答整数语义、松弛强度和组合条件，不能混在一起。特别是“仅在逐预激活独立区间上取精确包络”恰好回到原 big-M，没有产生新能力。满输入凸包不是我们的硬目标；研究仍可以追求严格而有用的精度成本提升，不必为全局 ideality 支付不可承受的代价。

这使下一项研究问题更具体：能否定义一个保留原相位、共享源和下游消费者关系的局部非凸元素，使前向组合后仍有可证明、可负担的优势？必须与“普通 HZ 加完全相同的关系”比较，而不是只与最弱的独立区间比较。目前这是待验证的假设，不是已经完成的 Neural-HZ 定义。

## 不把投影代价隐藏在终端

若一个既有共同源提升需要 `k` 份、每份 `d` 维的源，换成 `r` 维投影在表面上把该部分变成 `k*r`。但只有 `Q` 真正在 `r` 维中被描述时，才可能省掉这一部分。原源必须保留，`t=R x` 的行、系数、全部位、`Q` 的谓词、每份提升、消费者连接与见证还原仍要计入；若每份 `Q` 又用一套 `d` 维存在变量表示，所谓节省就可能消失。

小维度也不等于描述便宜。即使某个二维线性盒投影只有线性数量的边，逐个方向对全部生成元计算支撑值的直接算法仍有二次工作量。GPU 可并行这些工作，但不把二次工作变成线性，也不能令丢弃 HZ 谓词的辅助外包络变成精确源。此处没有提出用 zonotope 代替核心非凸域。

## 用户新增的 GPU 目标如何进入设计

2026-09-30 本轮用户进一步要求：趁提出 Neural-HZ 的机会，将此前主要在 CPU 上完成的约束处理和求解也纳入全面 GPU 加速。此补充扩展研究对象，不修改其他限制或历史档案。

设计评价因此覆盖域传播、关系构造、谓词乘法、终端求解、证据检查和具体见证验证，逐项报告在哪个设备上执行。目标是大规模计算尽量在 GPU 常驻并减少来回传输；尚未迁移的 CPU 步骤必须明示，不能把 GPU LP 称作完整非凸求解已全部上 GPU。最终设备划分和加速幅度都尚未测得。

PDLP 的原始论文与扩展论文表明，主要迭代可以避免直接矩阵分解，以 `A z`、`A^T lambda`、投影和归约组织。扩展论文为 2026-03-18 的 v2，增加了可行性 polishing 等机制；其通用 LP 实验和数值停止准则不是本项目的认证实验或精度门。[2021 版本](https://arxiv.org/pdf/2106.04756)，[扩展版本](https://arxiv.org/pdf/2501.07018)

cuOpt 26.08 文档显示，GPU PDLP、GPU barrier 和 CPU dual simplex 可以并发竞争；其 MIP 则结合 GPU primal heuristics 与 CPU 分支定界。所以直接启用默认求解配置不等于单一路径全部上 GPU，也不授权本项目新增 BaB、启发式菜单或救援路径。[官方介绍](https://docs.nvidia.com/cuopt/user-guide/latest/introduction.html)

实现前必须冻结依赖和方法版本。当前文档已将 `BatchSolve` 标为弃用，不能根据旧搜索结果预注册它。mixed precision 的迭代矩阵使用 FP32，但收敛检查还使用完整 FP64 矩阵；不能只统计前者显存。文档中的求解时间上限也不含所有外部传输与检查，项目须保持端到端计时。[cuOpt 26.08 特性](https://docs.nvidia.com/cuopt/user-guide/latest/convex-features.html)

## GPU 求解结果和严格证明之间的接口

OR-Tools 官方文档区分报告的对偶目标值和 corrected dual objective：前者不保证是有效下界，后者在数学上给出下界但可能为负无穷。它同时规定不可行证书的代数条件。因此“Optimal 状态、小 residual、正的浮点 margin”不能单独升级为 CERT。[PDLP 数学文档](https://developers.google.com/optimization/lp/pdlp_math)

以下是已有弱对偶原理的直接形式，用来说明可检查接口，不是新的域定理。对固定终端 LP

```text
min c^T z
A z >= b,     E z = d,     l <= z <= u,
```

若每一项所需的变量界有限，取任意满足符号条件的 `lambda>=0` 和任意 `nu`，令

```text
r = c - A^T lambda - E^T nu,
B = b^T lambda + d^T nu + sum_j min(r_j*l_j, r_j*u_j).
```

则每个可行点满足 `c^T z>=B`。证明只需展开目标，用行约束处理前两项，并对剩余线性项在盒界上求最小值。这种证据验算适合研究 GPU 的稀疏乘法和归约，但实现仍必须对原始系数、原始尺度、符号与全部舍入误差提供严格控制；直接以浮点结果代入并比较零不是证明。无穷界、无法验证的符号或资源失败都不能被静默忽略。

固定终端 LP 内部的 primal-dual 迭代属于普通求解算法，不等于网络的 backward/dual rescue。若对偶量被用于翻相位、修域、改谓词或选择另一条查询路径，就越过当前边界。这里的下界检查不做这些事，也不删去 HZ 中的任何二元因子。实际 CERT 仍须对应原性质和既有证明验收规则；GPU 给出的可行点仍只产生 ADV 候选，必须通过原始具体网络验证。

这条设计边界既不要求保留大规模 CPU 求解瓶颈，也不允许为了声称全面 GPU 而降低验算标准。哪些证据计算能用有保证的 GPU 算术完成、最终可信检查的代价如何，是需要显式证明和实测的实现问题。

## 下一步与当前证据等级

下一项定义候选应同时交付具体化、全相位精确对应、前向组合定理，以及可在 GPU 上执行的谓词算子和证据接口。先用普通共享源和残差结构验证它相对相同关系的 HZ 对照确有优势，再进入显式 opt-in 实现与逐级 replay。不能用一个更快的通用 LP 后端替代定义创新；也不能只给出漂亮的定义而把全部昂贵约束工作留给 CPU。

本轮没有安装求解器、修改生产源码或默认配置，也没有运行网络、shadow、全量 replay 或 GPU 实验。新结果是数学边界、足够条件及文献比较；不是已验证的速度或能力提升。正式基线仍为 1870/2413；外部 CIFAR100 25、TinyImageNet 36，共 61/400，独立计账，新增正式收益为 0。
