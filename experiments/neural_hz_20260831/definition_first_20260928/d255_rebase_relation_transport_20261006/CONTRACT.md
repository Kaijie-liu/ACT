# 重基底后同源读出的精确关系运输

本候选解决D254 NEXT_INTEGRATION中的具体覆盖缺口：生产image重基底后，child改读新连续列，而原提取器仍只查看parent旧幅值列，可能把tau误读为零并拒绝。唯一新规则是对完整登记的读出沿已认证link做精确同H归一化，然后执行原D254定量守卫公式。默认关闭，不按模型、标签、margin或求解状态选择路径。

这是定义研究走向实际前向的一项支撑性正确性改进，不是新集合类、独立域创新、实际网络提分或GPU结果。不会把一般等式代换重新命名为PLDI贡献。

## 完整非凸语义和代换证明

原H保留所有连续因子xi∈[-1,1]、signed binary beta∈{-1,1}、原EQ/LE、完整输出和decoder。追加image列kappa也是原当前H中的连续列；本候选不删除它，不重写原谓词或输出。

经逐行内容认证，某次rebase的每个新增image列对应实际存储等式a*kappa+ell=R，a≠0，ell只使用该次之前的连续列及原二元列。所有epoch的连续列区间按追加顺序、不重叠，允许中间出生其他因子。当前行位置可以因合并重排，但实际系数和RHS必须匹配内容凭据。

定义归一化N_H对读出中的c*kappa统一替换为c*(R-ell)/a，并按已认证DAG反向展开。单步有

~~~text
new_readout - old_readout = -(c/a)*(a*kappa+ell-R).
~~~

右边在H上为零。沿DAG归纳得每个H可行赋值上N_H(f)=f，包括全部合法零标签与所有原二元相位。因此原门y=ReLU(f)在H内也等于ReLU(N_H(f))；对归一化的完整父/child来源使用原关系定理仍健全。它不将相位连续化，不证明廉价最佳抽象、任意循环EQ消元或所有坐标变换不变性。

四个原门的private列不能成为代换目标；原来源先通过D254依赖检查，再归一化，再检查被link隐藏的private依赖。全部a/b/tau、r/e、相位条件尾项和六产品从同一归一化读出计算，不在拒绝之后调用另一种提取器。不支持的门误差、秩、非正tau或非法依赖继续fail closed。

原坐标输出和输入decoder不变；原整数点的canonical六产品延拓和原普通terminal仍走已有路径。向外舍入后的任意辅助解不能被解释为精确相位乘积。

## 实际存储凭据而非调用者标签

record_rebase读取完整before和after SparseHZono，检查相同frame、全部旧列/二元宽度、完整旧EQ/LE前缀、实际追加对角image输出及每个link。生产有无image列的常量link也须完整保存，不能只数有pivot的行。它核对实际binary64的center减旧center得到的stored RHS，不将该减法当成精确实数减法。

RebaseReceipt由本入口产生，保存两端完整内容摘要、列区间、变量link内容、所有输出偏差和新增EQ总数。RebaseBinding在最终H中以实际EQ内容重新定位这些变量link，不靠旧行号、frame整数或形状猜同源。Receipt与capture必须共用同一Budget，避免把前序记录费用移出当前账。

凭据只认证给定对象的存储内容符合rebase格式，不证明函数确实在某个生产执行中被调用，也不证明调用者提供的image界可靠、before/after整数集合相等或对象对应原ONNX。最终capture匹配的是当前H的变量link；完整历史来源、非变量link的生产生命周期、bounds、BN、全消费者及decoder到原输入的证据仍需真实worker认证。不能把owned Python对象当成防恶意反序列化的安全证书；直接构造/篡改私有记录不是支持入口。

若原输出为c+G*xi、新输出为m+r*kappa、实际link为G*xi-r*kappa=R，则

~~~text
m+r*kappa = (c+G*xi) + (m-c-R).
~~~

完整存储偏差必须保留，非零本身不是拒绝条件。例如普通c=float64(0.1)、m=1/2、R=float64(0.4)给精确偏差−2^-55。由当前H证明的同值性不升级成原raw模型精确性。最小tau反例及其范围见只读D254 NEXT_INTEGRATION。
