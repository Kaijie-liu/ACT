## Changes Made

### 1. PyTorch Converter Fixes

#### [act/pipeline/verification/act2torch.py](act/pipeline/verification/act2torch.py)

**Problem**: RNN modules return `(output, hidden_state)` tuples, but ACT networks expect tensor outputs.

**Solution**: Added `RNNOutputWrapper` class (Lines 71-82):

```python
class RNNOutputWrapper(nn.Module):
    """
    Wrapper for PyTorch RNN/LSTM/GRU modules to extract only the output tensor.

    PyTorch RNN modules return (output, hidden_state) tuples, but ACT networks
    expect only the output tensor when followed by SLICE/FLATTEN layers.
    """
    def __init__(self, rnn_module):
        super().__init__()
        self.rnn = rnn_module

    def forward(self, x):
        output, _ = self.rnn(x)  # Discard hidden state
        return output
```

**Updated RNN/LSTM/GRU creation** (Lines 480-526):
- Wrapped all RNN modules with `RNNOutputWrapper`
- Added LSTM `proj_size` support
- Ensured tuple unpacking in forward pass

**Problem**: SLICE layer not supported in PyTorch converter.

**Solution**: Added SLICE support (Lines 442-469):

```python
elif kind == "SLICE":
    # Extract slice parameters from metadata
    starts = meta.get("starts")
    ends = meta.get("ends")
    axes = meta.get("axes")
    steps = meta.get("steps", [1] * len(axes) if axes else None)

    if starts is None or ends is None or axes is None:
        logger.warning(f"SLICE layer missing required metadata, skipping")
        return None

    # Create a lambda that performs the slicing
    def slice_fn(x):
        # Build slice objects for each axis
        slices = [slice(None)] * x.dim()  # Start with full slices
        for axis, start, end, step in zip(axes, starts, ends, steps):
            slices[axis] = slice(start, end, step)
        return x[tuple(slices)]

    # Wrap in nn.Module
    class SliceModule(nn.Module):
        def __init__(self, slice_fn):
            super().__init__()
            self.slice_fn = slice_fn

        def forward(self, x):
            return self.slice_fn(x)

    return SliceModule(slice_fn)
```

**Key Features**:
- Handles arbitrary N-dimensional slicing
- Supports starts, ends, axes, steps parameters
- Compatible with batch_first RNN outputs

## Verification Pipeline Flow

```
1. Config Sampling
   ↓
   config_gen_act_net.yaml
   └─ family_selection: rnn (20% weight)
   └─ rnn config: cell_kind, hidden_size, num_layers, etc.

2. Network Generation
   ↓
   NetFactory.generate()
   └─ build_rnn_layers() (Phase 2)
       └─ INPUT → INPUT_SPEC → LSTM → SLICE → FLATTEN → DENSE → ASSERT
   └─ generate_rnn_params() (Phase 3)
       └─ weight_ih_l*, weight_hh_l*, bias_ih_l*, bias_hh_l*
   └─ save to JSON

3. PyTorch Conversion
   ↓
   ACTToTorch.run()
   └─ RNNOutputWrapper(nn.LSTM(...))  # Extract output tensor
   └─ SliceModule(...)                 # Sequence reduction
   └─ nn.Flatten(...)
   └─ nn.Linear(...)

4. Interval Verification
   ↓
   validate_bounds()
   └─ Generate 10 random input samples
   └─ For each sample:
       ├─ Concrete forward: model(x)
       └─ Abstract forward: interval TF
           ├─ tf_lstm() (Phase 7.2)
           │   └─ _process_lstm_direction()
           │       └─ _lstm_cell_bounds() for each timestep
           │           ├─ Sigmoid bounds (gates i, f, o)
           │           ├─ Tanh bounds (cell input g, cell output)
           │           └─ Multiplication bounds (element-wise)
           └─ Validate: concrete_output ∈ [lb, ub]

5. Result
   ↓
   ✅ PASSED: 0 violations
```

## Known Limitations

### Level 1 (Counterexample) Validation
**Status**: ❌ ERROR (expected)

**Error**:
```
Unsupported op tag 'lstm' (tag='lstm:2').
Add it to SUPPORTED_EXPORT_OPS in layer_schema.py
```

**Reason**: The torchlp solver (used for counterexample search) does not support LSTM as an exportable constraint. This is expected - LSTM is a complex recurrent operation that cannot be easily represented as linear constraints.

**Impact**: None for interval verification. Level 1 (counterexample) validation is for testing concrete solvers, not abstract transfer functions.

**Future Work**: Add LSTM support to HybridZ (Phase 6) for symbolic constraint solving.
