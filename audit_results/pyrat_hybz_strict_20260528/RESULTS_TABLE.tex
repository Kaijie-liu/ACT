\vspace{0.2em}
\centering\scriptsize
\textbf{Protocol.}\;
\texttt{STRICT HYB\_Z} reuses the runtime monkey-patch (\texttt{scripts/run\_pure.py})
and forced CLI flags from \texttt{pyrat\_strict\_20260527}. The only differing knob
is \texttt{domains = [hyb\_z]} in \texttt{patches/hybz\_ini/}. PyRAT's internal
\texttt{\_domains\_clean} unconditionally appends \texttt{con\_z} as carrier when
\texttt{hyb\_z} is selected, so the runtime line reads \texttt{['con\_z', 'hyb\_z']}.
This is intrinsic to PyRAT's hyb\_z implementation (the Hybrid Zonotope is
constructed \emph{on top of} a constrained-zonotope carrier and cannot stand
alone); both abstractions are computed and the tighter per-element bound is kept.
The headline finding is therefore: \emph{adding the hyb\_z layer to PyRAT's
\texttt{con\_z} abstraction yields a categorical improvement only on
\texttt{sat\_relu} ($+$8\,V) and a small marginal A bump on \texttt{acasxu}
($+$6\,A), while incurring a 22.1\,pp drop in overall resolve rate from increased
VRAM footprint and per-instance compute cost on every other architecture.}
