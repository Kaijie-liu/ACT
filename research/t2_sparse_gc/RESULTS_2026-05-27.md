# T2 sparse-Gc HZ representation — results (2026-05-27)

## Status: prototype + production patch validated; pilot pending

## Direction (from INSIGHTS_AND_NEXT_STEPS.md §T2)

> RSS-cap is the true ceiling for convolutional benchmarks, NOT precision.
>
> First theoretical experiment: re-implement HZ with CSR-sparse `Gc` storage,
> threshold-prune generators with `|Gc_col|` below ε, measure RSS on cifar100
> iid 0 with bound 24 GiB. If sparse drops RSS below cap → high-payoff direction.

## What changed (all default OFF)

### New file
- `act/back_end/hybridz_tf/sparse_gc_t2.py` (210 LoC) — two sound
  operators with row-slack compensation:
  - `act_hz_prune_gc_dense(hz, eps)` — drop Gc columns with
    `||col||_inf <= eps`, compensate with a single per-row slack
    generator (sound: triangle inequality on dropped contributions).
  - `act_hz_dense_to_sparse(hz, density_threshold)` — convert dense
    HZono to SparseGcZ when density < threshold and sparse storage
    is strictly smaller than dense.
  - `act_maybe_compact_hz(hz)` — convenience wrapper honoring env knobs.

### Edits (HZono dense path only)
- `act/back_end/hybridz_tf/hz_routing.py`:
  - `hz_conv2d` HZono exit (after dense conv): call
    `act_maybe_compact_hz(out)`.
  - `hz_dense` HZono exit (after matmul + add bias): same.

Both call sites are NO-OPS when env knobs are unset.

### Env knobs

| Name | Default | Effect |
|---|---|---|
| `ACT_HZ_PRUNE_GC` | `0` | Enable threshold-prune of dense Gc cols |
| `ACT_HZ_PRUNE_GC_THRESH` | `1e-9` | Drop cols with `||col||_∞ ≤ threshold` |
| `ACT_HZ_DENSE_TO_SPARSE` | `0` | Convert low-density HZono → SparseGcZ |
| `ACT_HZ_SPARSE_GC_DENSITY` | `0.05` | Density threshold for conversion |
| `ACT_HZ_PRUNE_GC_INSTRUMENT` | `0` | Print per-conv ng/density/RSS |

## E3 Fix #8: OnnxResize roi-vs-scales discriminator

cgan_2023 iids 18/19/20 were 100 % ERROR on GPU r93 with
`ValueError: OnnxResize at resize: cannot resolve scales or sizes`.
Root cause: the converter at `_convert_OnnxResize` (utils.py:1142)
iterated positional args `(input, roi, scales, sizes)` and matched the
FIRST floating-point tensor as `scales`. ONNX `roi` is also floating-
point and appears *before* `scales`, so the matcher locked onto `roi`
(8 entries for 2D spatial) and then failed the numel-check.

One-line fix: filter by `numel == len(self.shape)` BEFORE the
float/int discriminator. `roi` has `2 × spatial_rank` entries, so it
is naturally skipped.

### Effect (cgan_2023, 24 GiB cap, 30 s wall)
| iid | model | pre-fix | post-fix |
|---|---|---|---|
| 18 | upsample | ERROR_ValueError | **UNKNOWN_TIMEOUT** ✓ |
| 19 | small_transformer | ERROR_ValueError | ERROR_AssertionError (Fix #9) |
| 20 | small_transformer | ERROR_ValueError | ERROR_AssertionError (Fix #9) |

iid 18 (Upsample model) is fully fixed end-to-end. iids 19/20
(small_transformer) progress past Resize but hit a downstream Flatten
shape-tracking bug — a new Fix #9 candidate in the attention block,
not addressed here.

## Design-principle compliance

- **No CROWN** — operators are pure HZ arithmetic, no bound engine
- **No backward** — forward-only, applied at HZono exit of each linear op
- **No Gurobi** — no LP / MIP involvement
- **No fallback** — same method throughout; SparseGcZ is a representation
  flavor, not a different verifier
- **No B&B with backtracking** — no neuron splitting, no search tree

The sparse-Gc representation was already an existing flavor inside the
codebase (`act/back_end/hybridz_tf/representations.py: SparseGcZ`); T2
adds the bridge from the dense HZono path to this flavor when density
is low, plus a row-slack pruning operator. Both stay strictly within
the "single forward method" principle.
